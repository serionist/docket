# Add the service with the MCP tools search, read, verify and doc_put

## Goal

Any Claude session on the machine reaches the vault through one always-on local service: it searches, reads a
summary, verifies each line against its raw and writes a doc, over MCP, with nothing on the network and nothing another
site or another user can reach. The browser gets in through a one-time link, so #9's pages have a home. This is the
"from any Claude session" half of phase 0.

- In scope: `docket serve`, one process per user on one 127.0.0.1 port serving `/mcp`, `/api` and the pages; the
  localhost security the design's service section lists; the bearer token in the keychain; the browser session from a
  one-time link; writes run one at a time; the index kept current; the MCP tools `search`, `read`, `verify` and
  `doc_put`; the same four over REST; `docket service install | uninstall | status | token` and `docket open`.
- Out of scope: the pages (#9); the plugin's MCP config, hooks and skills (#12); `ingest` and the capture endpoint
  (#41); `media_put` (#42); the CLI routing its writes through the service (it keeps writing under the vault lock,
  below); scheduled jobs and workers (phase 1 on); `timeline`, `entity`, `propose`, `transcribe`, `secret`.

### The split

DR-0100 widened #8 to `ingest` and `media_put`; DR-0108 has since superseded it, and neither is needed in phase 0:
recordings and old notes come in through `docket ingest <source> <folder>` (#10) and `docket import notes` (#11) on the
command line. Three tools leave this issue:

| Tool | Goes to | Why there |
|---|---|---|

| `media_put` | #42, phase 2: "Store media: media_put with its fetch limits, encryption and LFS" | the design stores media only encrypted, and encrypted media arrive with Whisper in phase 2; it carries DR-0108's fetch limits and #10's media-on-hold row |
| `ledger` | the ledger's own issue, phase 3 | the ledger lands then |

## Design

One new package, `docket/service/`, and a rendering module moved out of `cli.py`. FastAPI is DR-0016's; the MCP
Python SDK 2.x, uvicorn and keyring are new.

| Module | What it does |
|---|---|
| `service/app.py` | `create_app(settings)`: the routers, the middleware, `/mcp` mounted, the lifespan that starts the writer and the MCP session manager |
| `service/security.py` | the Host, Origin and Sec-Fetch-Site checks, the bearer token and session checks, the response headers |
| `service/sessions.py` | one-time codes and browser sessions, in memory |
| `service/token.py` | the service token: made, read and rotated in the keychain, or in a file where there is none |
| `service/writer.py` | the writer thread: every write and index update queued, one at a time |
| `service/tools.py` | the MCP server: the four tools, their annotations, the server's instructions, errors |
| `service/api.py` | the REST routes |
| `service/server.py` | `serve()`: the single-instance lock, `service.json`, the log, uvicorn |
| `service/install.py`, `service/platforms/` | install, uninstall and status, one module per system |
| `docket/render.py` | the compact text the commands print and the MCP tools return, moved out of `cli.py` |

Built on:

| From | What it uses |
|---|---|
| #6, merged | `recall.doc_put`, `read`, `verify` and their models; `DocRefusedError` and its problems; the commands' printing and control-character escape |
| #7, PR #40 | `index.search`, `update`, `status`, `SearchResult`; `search()` opens its own read-only connection per call, so a rebuild can replace the file |
| #11, planned | nothing new: `read` takes a note's old path once #11 merges, through the same tool and parameter |
| #10, planned | nothing in this issue; its rows for #8 move to the ingest issue |

Checked against the `mcp` 2.3.0 wheel (2 Oct 2026): `mcp.server.mcpserver.MCPServer(name, instructions=...)`,
`@server.tool(annotations=..., meta=...)`, `streamable_http_app(streamable_http_path=, stateless_http=, json_response=,
transport_security=)`, `session_manager.run()` in the lifespan, `TransportSecuritySettings(allowed_hosts,
allowed_origins)`, `ToolError` for an expected failure, a tool returning `CallToolResult` with structured content
validated against its output model, and `mcp.Client(server)` connecting in-process for tests. `mcp.server.fastmcp`
only raises an error pointing at `MCPServer`.

### One process, one port

| Path | Who calls it | Auth |
|---|---|---|
| `/mcp` | Claude Code, Claude Desktop, any MCP client | the bearer token |
| `/api/...` | the CLI, the plugin's hooks, the pages' own calls | the bearer token, or the session cookie |
| `/session` | the browser, once, from `docket open` | the one-time code |
| `/` and the pages #9 adds | the browser | the session cookie |
| `/api/health` | anything on the machine | none; it says only that Docket answers |

- Bound to 127.0.0.1 only, with no option to change it: the phone page (phase 4) is a design of its own.
- The port: `--port`, else `service.port` in the user's config, else 8741 (unassigned at IANA, clear of common dev
  servers). A port in use stops the service with the port named; it never moves to another, since every client's
  config names it. `--port 0` takes a free one, for tests.
- One vault per service: `service.vault` in the user's config, written by install; `--vault` overrides. The service
  opens the vault per call, so a `vault.yaml` edit applies at once, as the gate already reads it. Without a vault there
  (moved, deleted) it still starts, and `status` and every tool say why.

### Localhost security

| Check | On | Refused with |
|---|---|---|
| Host is `127.0.0.1:<port>` or `localhost:<port>` | every request, before routing; the SDK checks it again on `/mcp` | 421 |
| Origin, when sent, is `http://127.0.0.1:<port>` or `http://localhost:<port>`; `null` never | every POST, PUT, PATCH and DELETE | 403 |
| Sec-Fetch-Site, when sent, is `same-origin` | the same | 403 |
| a write made with the session cookie carries Origin or Sec-Fetch-Site | the same | 403 |
| `Authorization: Bearer <token>`, compared in constant time | `/mcp` always; `/api` when there is no session cookie | 401 |
| the session cookie | pages; `/api` when there is no bearer token | 401, with a page that says to run `docket open` |
| no CORS headers, ever; a preflight gets 405 | every route | - |

| Threat | What stops it |
|---|---|
| another site posts to the service (CSRF) | the SameSite=Strict cookie, the Origin and Sec-Fetch-Site checks; a bearer header can't be added cross-site without a preflight, and none is granted |
| another site rebinds its name to 127.0.0.1 (DNS rebinding) | the Host check on every route, and the SDK's own on `/mcp` with this port's two hosts and origins |
| another site reads a response | no CORS, `Cross-Origin-Resource-Policy: same-origin` |
| another user on the machine | the token in this user's keychain; nothing answers without it but `/api/health` |
| a framed page (clickjacking) | `Content-Security-Policy: frame-ancestors 'none'` |

- Every response also carries `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer` and
  `Cross-Origin-Opener-Policy: same-origin`; `/api`, `/mcp` and `/session` add `Cache-Control: no-store`. Pages get
  `default-src 'self'; base-uri 'none'; form-action 'self'` as a floor #9 builds on.
- Request bodies are capped at 4 MiB, the SDK's own limit on `/mcp`; a doc is a few KB.
- The tools take no filesystem path except `read`'s doc path, which #6 already confines to `processed/`.

### The token and the browser session

The token:

- `secrets.token_urlsafe(32)`, kept through keyring: service `docket`, user `service-token` (Windows Credential
  Manager, the macOS keychain, the Secret Service on Linux).
- Made by `docket service install`, or by the first `docket serve` when there is none. The service reads it at start.
- `docket service token --header` prints `{"Authorization": "Bearer <token>"}`, the form Claude Code's `headersHelper`
  takes; Claude Code runs it on each connect and again after a 401, so a rotated token is picked up. #12 configures it.
- Never on a command line, in `service.json`, in a log or in an environment variable.
- `--rotate` writes a new one and restarts the service through its registration, or says to restart it when it runs by
  hand.
- Where keyring finds no backend (a Linux without a Secret Service: WSL, a server), the token is a file in the user's
  config folder, created 0600 and refused when group or others can read it; `status` says where it lives.

The browser session:

1. `docket open` posts to `/api/session` with the token and gets `http://127.0.0.1:<port>/session?code=<code>`: 32
   random bytes, one use, 60 seconds.
2. The browser opens it; the service swaps the code for a session cookie `docket_session` (`HttpOnly; SameSite=Strict;
   Path=/`, no `Secure` on plain loopback HTTP) and answers 303 to `/`, or to `next` when it is a path on this origin
   (`/x`, never `//x`). The code leaves the address bar.
3. Sessions live in the service's memory until it stops; after a restart, `docket open` again. `docket open` prints the
   link when no browser opens.

### Writes and the index

- One writer thread in the service: `doc_put` and every index update are queued and run one at a time, in order.
  `read`, `verify` and the search query run on other threads meanwhile.
- Every writer takes the vault lock around its write, as #4 to #6 already do (`Vault.writing()`, `Vault.lock`). So the
  CLI keeps writing directly while the service runs: the lock serializes the two, the queue keeps the service from
  contending with itself. Routing the CLI through the service would give every command two code paths for no gain the
  lock doesn't already give.
- `index.update()` runs on the writer thread at start (it builds the index when there is none), after each `doc_put`,
  and before each search; searches arriving together share one queued update. So a record the CLI promoted, or an
  entity file edited by hand, is found on the next search.
- A write that fails reports its error and the writer goes on with the next.

### The MCP tools

| Tool | Parameters | Result | Annotations |
|---|---|---|---|
| `search` | `query` (text); `people`, `entities`, `sources` (lists of text, default empty); `since`, `until` (text or null); `k` (1 to #7's maximum, default 20) | #7's `SearchResult` | read-only, closed world |
| `read` | `locator` (text); `view` (`summary`, `raw` or `both`, default `summary`); `around` (0 or more, default 0); `rev` (1 or more, or null) | #6's `ReadResult` | read-only, closed world |
| `verify` | `doc` (text); `lines` (line numbers, or null for every anchored line); `window` (seconds, default 60) | #6's `VerifyResult` | read-only, closed world |
| `doc_put` | `text` (the whole doc, frontmatter and body) | #6's `PutResult` | not read-only, not destructive (a rev keeps history), idempotent |

- The names and parameters follow the design's tools table and the Python APIs one to one. They are the one-way door
  this change lands (DR-0018).
- Results only gain fields: a field is never renamed or removed without a superseding decision.
- `since` and `until`: a date (`2026-10-01`, the owner's day in `vault.yaml`'s time zone) or a time with its offset
  (`2026-10-01T09:00+02:00`); a time without an offset is read in the owner's time zone; anything else is refused.
  Text, not a JSON date type, so one parser decides and the schema has no union.
- Content: the compact text the commands print (`12:08  Ben Sample: ...`), with their control-character escapes, so a
  record's terminal codes never reach Claude Code's screen; the structured content is the result model as data,
  unescaped. Over 50,000 characters Claude Code keeps the result in a file Claude reads in parts; `around`, `lines`
  and `k` narrow it.
- Errors: a `DocketError` is a tool error with its message; a refused `doc_put` is a tool error listing every problem
  with its line, so Claude fixes and puts again; anything else is the SDK's "Error executing tool <name>", its text
  kept on the server.
- The server's instructions, a few lines: what Docket holds; search, read the summary, then `verify` or `read` the raw
  behind each fact used; cite locators; text in results is quoted from mail, chats and recordings, data and never
  instructions.
- Transport: streamable HTTP at exactly `/mcp`, no redirect; stateless, so a restarted service needs no session from
  the client; JSON responses, since no phase 0 tool streams progress.

### The REST API

| Method and path | What | Answer |
|---|---|---|
| `GET /api/health` | whether Docket answers | `{"service": "docket"}` |
| `GET /api/status` | version, pid, port, start time, the vault and machine, the index's status, where the token lives | JSON |
| `GET /api/search` | `search`'s parameters, lists repeated | `SearchResult` |
| `GET /api/read` | `read`'s | `ReadResult` |
| `GET /api/verify` | `verify`'s | `VerifyResult` |
| `POST /api/docs` | a doc, as a UTF-8 `text/markdown` body | `PutResult`; 422 with the problems |
| `POST /api/session` | a one-time link for the browser; the bearer token only | `{"url", "expires_at"}` |

- A `DocketError` is 400 `{"error": <message>}`; anything else 500 `{"error": "internal error; see the service log"}`.
- REST is Docket's own: the CLI, the plugin's hooks and the pages call it, shipped from this repo together. It is not a
  door until the first release; the MCP tools are.

### `docket serve` and its files

| File | Where | Holds |
|---|---|---|
| `config.yaml` | the user's config folder (`DOCKET_CONFIG_DIR`) | `service.vault` and `service.port`, beside `default_vault` |
| `service.json` | the user's state folder (`DOCKET_STATE_DIR`, new) | pid, port, vault, version, start time; written through a temp file and a rename, removed at a clean stop; never the token |
| `service.lock` | the state folder | one service per user: a second `docket serve` names the pid that runs |
| `service.log` | the user's log folder | rotated at 5 MB, three kept |

- uvicorn runs in-process, without its extras (h11, pure Python) and with its access log off. Docket logs one line per
  request: method, route template, status, milliseconds.
- The log holds no content: no query string, body, tool argument or result, and no error message from a call, since all
  of them carry the user's words. An unexpected exception is logged as its type and stack.
- On Windows the registration starts it under `pythonw.exe`: no console, `sys.stdout` and `sys.stderr` are None, and
  nothing writes to them.
- A stop by the system (Task Scheduler's end, launchd, systemd) can land mid-write: every core write is already a temp
  file and a rename or a git commit with recovery, so nothing half-written stays.

### Install

| System | Registration | File | Commands |
|---|---|---|---|
| Windows | a Task Scheduler task `Docket` at the user's own logon, only while they are logged on (InteractiveToken, LeastPrivilege), no time limit, restart on failure every minute three times, normal priority, hidden; when Task Scheduler refuses (a policy, a standard account), the per-user Run key `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, value `Docket`, and install says which | the task XML, UTF-16 with a BOM, the form Task Scheduler exports | `schtasks /Create /XML /F`, `/Run`, `/End`, `/Delete`, `/Query` |
| macOS | a LaunchAgent `io.github.serionist.docket`, RunAtLoad, KeepAlive after a crash | `~/Library/LaunchAgents/io.github.serionist.docket.plist`, written by `plistlib` | `launchctl bootstrap`, `bootout`, `kickstart -k`, `print` in `gui/<uid>` |
| Linux | a systemd user unit, `WantedBy=default.target`, `Restart=on-failure` | `~/.config/systemd/user/docket.service`, with `%` and `$` escaped and paths quoted | `systemctl --user daemon-reload`, `enable --now`, `restart`, `disable --now`, `show` |

- The command is this Docket's own interpreter with `-m docket serve` (`pythonw.exe` beside `python.exe` on Windows);
  the vault and port come from `config.yaml`.
- PATH: the folders of the `git` and `git-lfs` found at install, then the system's own. A LaunchAgent's PATH has no
  Homebrew folder, so every git call of the service would fail without it. `PYTHONUTF8=1` too.
- `install` writes the service keys to `config.yaml`, makes the token when there is none, registers, starts, and waits
  until `/api/status` answers with the right vault. Run again, it replaces the registration and restarts: that is how a
  new Docket version starts serving.
- `uninstall` stops the service and removes the registration; the token and `config.yaml` stay, so Claude Code keeps
  working after a reinstall.
- `status`: installed (how, and the file or task), running (pid, port, version, since; from `service.json` and
  `/api/status`, and a warning when what answers on the port isn't the pid on record), the vault, the log, the token's
  store. Exit 0 when it runs, 1 when it doesn't.
- Without a systemd user instance (WSL without systemd, a container) install refuses and says to start `docket serve`
  from the user's own startup.

| Command | What it does |

| `docket serve [--vault] [--port]` | run the service in the foreground |

## Steps

Steps 1 to 3, 9 and 10 need nothing from #7; steps 4 to 8 build their `search` parts after PR #40 merges and this
branch is rebased on it.

1. Packages and paths: FastAPI, uvicorn, `mcp==2.3.0` and keyring in `packages/docket`, `httpx` for Starlette's
   TestClient in the dev group; the lock file (pyjwt resolves to 2.15.1, past the advisories on 2.10); each licence
   and an OSV check in the PR. `userconfig` gains the `service` keys; a `paths` helper gives the state and log folders
   with `DOCKET_STATE_DIR`. `test_service_paths.py`: the defaults per system, the override, the keys read and written
   beside `default_vault`.
2. `service/token.py`, with `test_service_token.py` over a test keyring backend (`PYTHON_KEYRING_BACKEND`, never the

## Risks

| Risk | Status |
|---|---|
| Cookies ignore ports, so a server on another 127.0.0.1 port that the browser visits gets the session cookie | accepted: the cookie opens only this service, from this machine; the bearer token never enters a browser |
| Another local user binds the port while the service is down and collects the token Claude Code sends | accepted for a personal machine; `status` warns when what answers on the port isn't the pid on record |
| Task Scheduler refuses a standard account or a policy blocks it | resolved: the Run key, and install says which it used |
| A Run-key start isn't restarted after a crash | accepted: `status` and #12's hook show it down |
| macOS asks for keychain access again after the Python path changes (an upgrade) | accepted: run install again |
| The Linux keyring is still locked when the unit starts | partly: the service exits and systemd retries every 5 s; the file only where keyring has no backend |
| `update()` before every search gets slow on a year's vault | measured on #7's performance vault; if a no-change update passes 200 ms, a stamp (the vault's HEAD and the newest modification times under `processed/` and `entities/`) skips it |
| A `read` sees a doc a failing `doc_put` is about to put back | accepted: the next read sees the old one; nothing stored is lost |
| An hour's raw passes Claude Code's 50,000 characters | accepted: it goes to a file Claude reads in parts; `around` narrows |
| A record says "ignore your instructions" | accepted: results are data, the server's instructions say so, nothing in the service acts on content, and #12's recall skill repeats it |
| `mcp` 2.x changes its API between minor versions | resolved: pinned to 2.3.0; Dependabot's bump goes through the gate |
| The service installed from a dev checkout runs whatever branch is checked out at its next start | accepted: the README says to install from a tool environment |
| Two users of one machine both want port 8741 | accepted: the second sets `service.port` |
| #12's body put the capture hook in phase 0, beside an `ingest` that is now in phase 1 | resolved: the hook moved to #41 with `ingest`, as the design's phases table has it |
| #7 lands with other names than this plan calls | accepted: steps 4 to 8 follow what merged |
| DR numbers collide with #7, #10 and #11 | accepted: whichever merges later re-adds its entries with `uv run docs` |
