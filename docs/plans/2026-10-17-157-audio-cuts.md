# Cut a released or hand-cut recording's audio before it is stored

## Goal

A recording cut by a release or by hand gets its audio, with every cut stretch silent and every other moment where it
was. Today such audio is refused (DR-0547), and every release has a cut (DR-0200), so no released recording has audio.

| The issue's part | This plan | PR |
|---|---|---|
| Decode | PyAV's bundled FFmpeg in a child process: forced demuxer, file protocol only, no shell, a memory cap, 15 minutes, 12 hours of audio at most | 1 |
| Cut | each range replaced by digital silence, widened 250 ms each side; the audio's onset and end checked against the transcript first | 1 |
| Encode | WebM Opus, mono, 48 kHz, 32 kbit/s: about 14 MB an hour, seekable, played by every current browser | 1 |
| Order | at the put, after the fetch and before encryption; uncut bytes only in a per-process temp folder in Docket's private folder, removed on every path and by the next sweep after a crash | 1 |
| Later releases | `run_open` lists the source's cut recordings with no audio; the media step puts them, cut | 1 |
| #42's revisit | a hand cut by time is cut like a release; a hold, a character cut or a private decision still refuses; `_decided.jsonl` now says which a decision was; staged audio whose cuts change is deleted and put again | 1 |
| Stored audio that gains a cut later | each stored file's ranges committed with it (PR 1); a file whose recording outgrows them is not played, is put again, cut, and its old key deleted (PR 2) | 1, 2 |
| Tests | a tone in a cut range comes back silent, unchanged elsewhere; a decoder stopped at its limit, or a parent killed mid-cut, leaves nothing | 1, 2 |

Out of scope: audio for recordings stored before media existed (a backfill, its own issue), the player (#159), and
Whisper (#158), which reuses this decoder.

## Design

### The pipeline

| Step | Where | What |
|---|---|---|
| 1. ranges | `check`, under the lock | the cut ranges the rid's media needs now (below), or a refusal |
| 2. fetch | outside the lock | the path or URL, through #42's `Capped` reader, into a plain temp file in this process's temp folder (no ranges: encrypted while read, as today) |
| 3. cut | outside the lock | a child decodes the temp file, silences the ranges, writes WebM Opus to a second temp file there, and reports the duration, the onset and the input's codec, rate and bitrate |
| 4. encrypt | outside the lock | the second file through `crypto.encrypt` into #42's encrypted temp; both plain temps deleted in a `finally` |
| 5. finish | under the lock | the checks again; the ranges again, which must be covered by the ones applied, else "its cuts changed while it was fetched; put it again"; then the key, the sidecar and the rename |

A put with no ranges takes #42's path unchanged: nothing is decoded and the original is stored. The put's line names
the input's format, so the first real Plaud recording shows what Plaud sends.

Plain temps live in `<private tmp>/media-cut-<pid>/`, one folder per process. Every sweep (each gate call) removes
the folders of processes no longer running, whatever their age, beside #42's hour-old encrypted temps. Whether a pid
runs is asked with `os.kill(pid, 0)` on Linux and macOS, and with `OpenProcess` and `GetExitCodeProcess` on Windows,
where `os.kill` would end the process.

### The decoder

`python -I -X utf8 -m docket.media.child --memory <bytes>`, started fresh for each put with the mapper runner's
stripped environment, as #69's extraction child is (DR-0485). It caps its own memory before saying `ready` (Linux
`RLIMIT_AS`, a job object on Windows, none on macOS), then takes one JSON line and answers one.

| Limit | Value |
|---|---|
| memory | 512 MiB where the system enforces it |
| time | 15 minutes, then the child is killed |
| audio | 12 hours decoded, then `not_read` |
| input | `media.max_bytes`, as the fetch |
| demuxer | forced from the sniffed type: mp3, mov (m4a), aac, ogg and opus, wav, flac, matroska (webm); `bin` refused |
| network | FFmpeg's `protocol_whitelist=file` and the forced demuxer: no playlist, reference or URL opens anything but the one file |
| Python | no numpy in the child; an audit hook refusing `socket.connect` covers Python's own sockets only |

It decodes frame by frame through `av.AudioResampler` to 48 kHz mono s16, zeroes the samples inside each range,
and encodes as it goes, so memory stays flat for a three-hour call. FFmpeg trims an MP3's encoder delay from its
LAME header, so sample 0 is the recording's start.

| Option | Why not |
|---|---|
| soundfile (libsndfile) | no M4A or AAC; brings numpy, which DR-0485 keeps out of children; Opus bitrate only by a compression level |
| ffmpeg on PATH | absent on stock Windows and macOS; versions and codecs vary |
| miniaudio | decodes only; no Windows-on-Arm or Linux aarch64 wheels |

`av==18.1.0` (12 August 2026), pinned like pyrage, with pyrage's platform markers: media is off where either has no
wheel. Its wheels are 18 to 35 MB, with libopus, libmp3lame and the AAC, MP3, Opus and FLAC decoders. PyAV itself is
BSD-3-Clause, but its wheels are not LGPL-only. Their FFmpeg reports "LGPL version 3 or later" and is configured with
`--enable-version3` and without `--enable-gpl`, yet with `--enable-libx264 --enable-libx265`. The wheel bundles both
libraries (GPL-2.0-or-later) and registers their encoders, so it carries GPL code whatever FFmpeg's string says. This
was checked on the Windows wheel; the others come from the same pyav-ffmpeg scripts. Docket only depends on it through
PyPI and uses no video encoder. Phase 5's bundled installers would redistribute it, so they need an FFmpeg built
LGPL-only or must meet the GPL's terms. #158's Whisper decodes through the same child.

### The cut and the format

- Silence: each range widened 250 ms each side, merged, clamped to the audio, and its samples set to zero. Nothing is
  removed, so every transcript time points at the same moment.
- Timeline checks, when the media's family has a transcript, each failing closed with a reason that names the offset:
  - end: the transcript's last segment must end before the audio does, give or take 1 s;
  - onset: the audio's first sound (the first 50 ms window above -45 dBFS) must fall within 1.5 s of the first
    segment's start. Both numbers are constants, tuned on the maintainer's recording.
- Format: WebM Opus, libopus, `application=voip`, VBR at 32 kbit/s, 20 ms frames, Cues written (the temp file is
  seekable). Speech at 32 kbit/s is close to transparent, and silence costs almost nothing.

| Format | Why not |
|---|---|
| FLAC | 40 to 60 MB an hour at 16 kHz, three or four times Plaud's MP3, in LFS forever |
| Ogg Opus | Safari plays it only since 18.4, with a wrong duration on long files (WebKit bug 293310) |
| MP3 again | worse than Opus at the same size, and MP3's own delay to account for |

### Which ranges

The ranges a rid's media needs are the union of:

| From | Ranges |
|---|---|
| the release covering the rid (DR-0200) | its cuts, already widened over the transcript's utterances |
| each version in raw of a transcript in the family | its `[cut]` segments, which span what each cut removed (DR-0028) |
| each staged version of a transcript in the family | its `[cut]` segments after a dry run of its own cuts and the release's, as promotion will make them |

The family is #42's: the rid and every rid nested under `<rid>/`. The screen's checks change only where cuts are
concerned:

| Case | #42 | Now |
|---|---|---|
| a release with cuts covers it | refused | cut by the ranges |
| a transcript cut by time, staged or in raw | refused | cut by the ranges |
| a record without segments cut by characters | refused | refused: there is no time to cut the audio at |
| `decided` holds a `cut` entry for a rid of the family | refused | passes: its ranges are in raw |
| `decided` holds a `private` entry, or one without a kind, for a rid of the family | refused | refused |
| withheld, never-store, held, left out by a release | refused | refused |

### What a decision was

`_decided.jsonl` can't say a private classification from a promotion with cuts, and a release's cuts leave no line at
all, so no count of lines against cut versions in raw tells them apart. From now on each line carries
`"kind": "cut"` (a promotion with hand cuts) or `"kind": "private"` (a private classification). The field is additive:
an older Docket reads only `rid` and `key`. A line without a kind was written before this change, and counts as
private for media, as every decision counted under #42. So a recording hand-cut before this change keeps no audio
until its owner says so.

`docket media confirm-cuts <rid>`, at the owner's console only (refused in Claude Code's shell or a pipe, DR-0518),
shows the evidence for each of the family's rids with kind-less decisions:

| Shown | From |
|---|---|
| how many kind-less decisions it has | `_decided.jsonl` |
| the versions in raw each could be, with their runs and cut times | its `[cut]` segments; only a version this clone promoted cut by hand counts, less one for each `cut` decision the rid has; a version whose every `[cut]` span lies inside the release's cuts was cut by the release, and is left out |

It refuses when a rid's kind-less decisions outnumber the versions left: at least one was a private classification. Otherwise the owner types back a code to say each was a cut, and it appends a `cut` line for each of
those keys; the last kind for a key counts. Without it, that recording's audio waits.

### Staged audio, and refused audio's return

A staged file's sidecar, now schema 2, keeps the ranges it was cut with (schema 1 reads as none). At every sweep and
promotion the needed ranges must be inside the applied ones, or the file is deleted with its key and counted, as any
failing check is. A pending record cut later, or a second release line, so costs one more download, never an uncut
file. A cut the owner takes back leaves extra silence: accepted.

#42 asked whether held or hand-cut audio could be kept and cut instead of deleted. Partly:

- A hold still refuses and still deletes: a held recording keeps no text either, and the release decides what goes.
- A hand cut by time no longer refuses. Audio staged before the cut is deleted, since cutting it in place would hold
  the vault's lock for minutes, and it is put again, cut.
- Both come back through `run_open`: its text gains `media    <n>: <ids>`, the source's recordings, staged or in raw,
  with no audio, a release with cuts or a cut transcript, and every check passing. At most 20, newest first. The run's
  media step puts those too. This is how a recording released after its audio was refused gets it at the next run,
  cut, and how the recordings released so far get theirs.

### What stored audio was cut with

PR 1: each media commit also appends to `state/media-cuts/<source>.jsonl` one line per file it stores, in the same
commit: schema_version 1, the rid's hash, its ranges, when and the machine. It merges by union (the vault's
`*.jsonl merge=union`) and holds times only, as the release log does. A file stored without a line counts as uncut.

PR 2 reads it:

| Case | Then |
|---|---|
| the family's ranges outgrow the file's line (a new release line, a version cut by hand) | the reader says `recut` and plays nothing; `run_open` lists it; a put is allowed beside the stored file |
| a hold covers a stored file | the reader says `held` and plays nothing; its release then makes it `recut` if its cuts grew |
| the new file is promoted | committed with the old file's removal and a new log line; the old key is deleted on this clone, so the uncut copy in history opens nowhere here |

## Tests

All on invented data, with audio the tests make through `av` itself: a 440 Hz tone, 10 s, mono, encoded as each
input format.

| Test | Proves |
|---|---|
| a tone with a cut at 3-5 s | below -60 dBFS inside 2.75-5.25 s (30 ms in from each edge); outside, within 1.5 dB of the input's level and at 440 Hz |
| every input format | the same result from mp3, m4a, wav, flac and Ogg Opus |
| a tone starting 3 s in, against a transcript starting at 0 | refused at the onset check, naming 3.0 s |
| a transcript longer than its audio | refused at the end check |
| a child held at its time limit (a test seam stops it before it answers) | killed; no temp file, staged file or key left |
| a parent killed mid-cut (a separate process, ended by the test) | its `media-cut-<pid>` folder is removed by the next sweep; a live process's folder is kept |
| a crashed child, a memory cap refused, a file that isn't audio, an HLS playlist named `.mp3` | refused in Docket's words; nothing left |
| a release, a hand cut by time, a character cut, a hold | cut, cut, refused, refused |
| a released recording with a kind-less decision on its transcript, then `confirm-cuts` | refused, then cut |
| `confirm-cuts` with more kind-less decisions than versions cut by hand, a release-cut version among them | refused, naming the counts; nothing appended |
| a release-cut version and a `private` decision on the same rid | refused |
| a second release line while staged | the staged file deleted; `run_open` lists the rid |
| cuts changed during the fetch | refused at `finish`; temps gone |
| a media commit | its `state/media-cuts` line in the same commit |
| (PR 2) a stored file whose transcript is cut later | `recut`; put again; the swap commit; the old key gone |

CI runs them on Linux, Windows and macOS, where `av` has wheels.

## Risks

| Risk | Status |
|---|---|
| Plaud's transcript times and the MP3's may not line up (a trimmed start, a resample) | the onset and end checks fail closed and name the offset; the 250 ms padding absorbs small drift; the maintainer's listening test settles it |
| the end check alone is one-sided: it catches audio shorter than its transcript, not audio shifted later with room at the end | the onset check covers a shift; both are heuristics, tuned on a real recording |
| the onset check refuses a good recording with noise before the first words | fails closed; the reason names the offset, and the tolerance is a constant |
| a crash leaves uncut audio in the private folder until the next sweep; a reused pid keeps a dead process's folder until that pid ends | accepted: the folder is the user's alone, and the next gate call after the pid is free removes it |
| `av` adds 18 to 35 MB per install | accepted; #158 needs it too |
| `av`'s wheels carry libx264 and libx265 (GPL) | fine for a PyPI dependency; phase 5's installers need an LGPL-only build or the GPL's terms |
| MP3 to Opus is a second lossy step | 32 kbit/s Opus for speech is near transparent; the format line of a real recording shows Plaud's bitrate |
| WebM Opus on Safari is unconfirmed for long files | #159's player is tested in Chrome; Safari is checked by hand then |
| FFmpeg parses hostile files | child caps, the forced demuxer from the sniffed type and the file-only protocol |
| recordings hand-cut before `kind` existed keep no audio | until the owner runs `confirm-cuts`; resolved by design |
| no memory cap on macOS | accepted, as #69 |
| a re-put downloads hours of audio again | once per change of cuts |
