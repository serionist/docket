# Commit without hooks in a repo vault, as in a folder vault

## Goal

Docket's own commits skip the repo's hooks in both modes, through one hooks path that is a file, so a commit on
Windows takes about 65 ms instead of about 500 ms and no hook rewrites or refuses what Docket writes once. A push keeps
the hooks, so git-lfs still uploads media.

- In scope: `Git.commit` in both modes; `docket sync`'s fetch and rebase and the aborts of it; the tests; the docs.
- Out of scope: a push in `docket sync` (there is none yet; #58); convert, whose host merge is plumbing
  (`fast-import`, `commit-tree`, `update-ref`) and runs no commit hooks; the user's own commits and pushes.

## Design

### What folder mode does today

It doesn't skip git-lfs's hooks. Its `no-hooks` folder doesn't exist until git-lfs's filter runs; init's add of
`media/.gitkeep` runs it, and the filter creates the folder and writes `post-checkout`, `post-commit`, `post-merge` and
`pre-push` into it (measured: `Vault.init` of a folder vault in a host after `git lfs install --local`). Every folder
commit since has run git-lfs's `post-commit`. So the two modes can't share today's path as it is; they share a fixed one.

### One hooks path, a file

- `Home.hooks_off` is `<private>/hooks-off`: `.git/docket/hooks-off` in a repo of its own,
  `<host git dir>/docket/<vault path>/hooks-off` in a folder.
- `Git.run(..., hooks=True)` gets a flag. `hooks=False` writes the file when it is missing (a stat on every call, one
  short write the first time) and puts `-c core.hooksPath=<file, posix>` before the command, as `NO_SIGNING` is.
- git finds no hook under a file. git-lfs's filter tries to write its hooks into the hooks path, can't make a folder
  where a file is, and says nothing; media still goes to LFS through the filter. Measured here, git 2.47.0.windows.2
  and git-lfs 3.5.1: three commits each way, 59 to 73 ms with the file against 470 to 474 ms with git-lfs's hooks; the
  media blob is a pointer; nothing is written to `.git/hooks` or next to the file.
- A missing path doesn't work either: git-lfs creates it as a folder and fills it. Hence the check before every call.
- An older folder vault's `no-hooks` folder stays where it is; nothing reads it.

### Which git calls skip hooks

| Call | Hooks | Why |
|---|---|---|
| a commit's add, commit and its unstage after a failure, both modes | off | a formatter or a commit-msg rule would rewrite or refuse what Docket writes once; git-lfs's `post-commit` is most of a commit's time |
| sync's fetch, its `rebase --autostash` and `rebase --abort`, and the recovery check's abort (a repo of its own) | off | the rebase runs `pre-rebase`, `post-checkout`, `post-commit` for every commit it picks and `post-rewrite` (measured with a hook that logs its name); a refusing `pre-rebase` would stop every sync; the fetch runs only `reference-transaction`, off for one rule across sync |
| a push | on, the default | git-lfs's `pre-push` uploads the media |
| `git lfs install --local` at init, everything else | as today | install writes the hooks the user's pushes need; reads run no hooks |

- Sync rebases and never merges, so `post-merge` doesn't come up. A rebase still smudges media through the filter
  (measured: a media file from the remote arrived in the working tree with hooks off).
- Hooks are off per call, never by default: a push written later without the flag would otherwise leave media off the
  remote, and a later push of the same ref doesn't send it (measured: after a hooks-off push, a push with hooks said
  "up to date" and uploaded nothing).

### What git-lfs's hooks do, and what skipping them loses

| Hook | Does | Lost by skipping it |
|---|---|---|
| `post-commit`, `post-checkout`, `post-merge` | make files matching a `lockable` attribute read-only unless you hold their lock (`git lfs help post-commit`) | nothing: the vault's `.gitattributes` has no `lockable` line; a host's `lockable` rule on vault paths would leave Docket's media writable, and Docket writes media once |
| `pre-push` | uploads the LFS objects of the commits being pushed | never skipped |

### Windows, macOS and Linux

| System | What happens | Checked by |
|---|---|---|
| Windows | measured as above; a hook starts `sh.exe`, which is where the half second goes | the new tests in CI's Windows job |
| Linux, macOS | git's hook lookup under a file fails with "not a directory", and git-lfs is the same Go code; a hook starts faster there, so the gain is smaller | the new tests in CI's Linux and macOS jobs |
| all | the path goes as one argument in posix form, so spaces and drive letters are fine, as in today's folder mode; `core.hooksPath` needs git 2.9 | |

### Not taken

- `git commit --no-verify`: skips `pre-commit` and `commit-msg` only; `post-commit` and git-lfs's hooks still run.
- `core.hooksPath` in the repo's own config: the user's own commits would lose their hooks too.
- Hooks off by default in `Git.run`, on for a push: see above.

## Doors and data

None. No one-way door moves: the vault's layout, what Docket commits (paths, messages, identity) and where its own
files live (DR-0141, the git dir) stay; `hooks-off` is one more of Docket's files there. What changes for a user: a
hook set up in a repo vault, or a global `core.hooksPath`, no longer runs for Docket's commits or sync's rebase; it
still runs for the user's own commits and for every push. No stored data moves, and an older Docket opens the vault as
before.

The decisions are in `packages/docket/index.yaml`, proposed, by Claude (autonomy grant), from this branch's block of
ten that starts at DR-0260:

|---|---|---|

| DR-0261 | `docket sync` fetches and rebases without hooks, every push keeps them, and a call skips hooks only when it says so | medium |

## Tests

In a new `test_hooks.py`, on the kit's vaults (the copies, if #43 has merged), parametrized over a repo of its own and
a folder where both apply:

- A commit: `pre-commit` that rewrites staged files, `commit-msg` that refuses and `post-commit` that writes a marker,
  in `.git/hooks`; `write_run` commits the run unchanged, no marker; the user's own `git commit` still runs them.
- Media (needs git-lfs): after `git lfs install --local`, a file under `media/` committed by Docket is an LFS pointer in
  `HEAD`; `.git/hooks` holds only what install wrote; no folder appears at `hooks-off` or `no-hooks`.
- The file: deleted, then a commit writes it again and still runs no hook.
- Sync (a repo of its own): a refusing `pre-rebase` and a marker `post-commit`; with local and remote commits, sync
  rebases, no marker.
- A push through `vault.git.run("push", ...)`: a marker `pre-push` runs; with git-lfs, the media object lands in the
  bare origin's `lfs/objects`.
- Changed: `test_an_init_whose_real_commit_fails_leaves_nothing` fails init's commit through a patched `Git.run`
  instead of a refusing `pre-commit`, same assertions; a refusing global `pre-commit` no longer stops init, a new
  test.

Coverage stays at 100% for `docket`.

## Risks

| Risk | Status |
|---|---|
| A user's hook in a repo vault, or a global hooks path such as a company's scanner, no longer runs for Docket's commits | accepted, the issue's catch: it runs for the user's own commits and every push |
| A push written later with hooks off leaves media off the remote | resolved: hooks stay on by default, DR-0261 binds every push, and a test pushes media through `Git.run` |
| A git-lfs version fails its filter when it can't write its hooks | accepted: the add fails loudly, nothing is lost, and the media test runs on CI's three systems |
| The file is deleted and git-lfs makes a folder there | resolved: the file is written before every call that skips hooks; a test deletes it |
| A host's `lockable` rule covers vault paths, and Docket's media stays writable | accepted: Docket writes media once and never rewrites it |
