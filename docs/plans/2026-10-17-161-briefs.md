# Keep a brief per person, project and topic, and show the briefs on a page

## Goal

A brief is a processed doc about one entity: what changed, the last conversations, the decisions, every line cited
(design §3.5). Claude writes it, since that is judgement (DR-0104). Docket checks its form, says which briefs are stale
and why, and shows them on the Briefs page beside the raw their lines cite.

- In scope: the brief's form and what doc_put checks of it, staleness through `docket brief stale` and an MCP call,
  the plugin's `brief` skill, the Briefs page, and never-store rules for briefs.
- Out of scope: open items, which wait for the ledger (phase 3) and are left out rather than guessed; a brief before
  each meeting, which waits for the calendar's meetings (phase 3); the decision log (#162), which the Briefs page will
  show per entity once it exists.
- Built on #166 (refs and flags), merged as 7f050a6.
- Two PRs: the first holds the brief's form, the stale report, the `briefs` tool and the skill; the second, the Briefs
  page. The first is useful on its own, and the page reads what it adds.

## Design

### The brief (DR-0555)

```markdown
---
id: brief:ben-sample
type: brief
covers: []
by: claude-opus-5.5, brief 2026-10-17
entities: [ben-sample]
---

# Ben Sample

## What changed

- Ben now leads the Northwind site; the handover was on Monday. [d:minutes:2026-10-12-northwind-weekly@3#14]

## Last conversations

- 15 Oct, supplier call: Ben asked for ten million for the quarter. [d:recording-note:2026-10-15-supplier-call@1#12]

## Decisions

- The offer goes in writing before Friday. [r:mail:<offer-1@northwind.example>#2]
```

| Rule | What doc_put checks |
|---|---|
| Id | `brief:<entity id>`, for an entity that exists in `entities/`; any type, since ids are unique across types |
| Entities | its `entities` list names that entity |
| Sections | a `# <title>` heading, then `## What changed`, `## Last conversations`, `## Decisions`, in that order, each once, all required; a section may be empty |
| More sections | a further `##` section after the three is taken, with a warning in the put's result rather than a refusal, until the maintainer's trial week settles the format. Open items wait for the ledger |
| Lines | every content line ends with raw anchors, refs, or both (#166): a line that sums up a note line cites it with `[d:<doc>@<rev>#<n>]`, as `verify` gives it as `cite`; `covers` may be empty when no line has a raw anchor |

The form is checked only for the `brief` type, on top of every doc's rules, so other docs are unchanged.

### Staleness (DR-0556)

A brief is stale when either of these holds:

| Why | How it is worked out |
|---|---|
| New records | records that mention the entity (the index's `mentions`, authors and speakers included, DR-0471) whose run file isn't in the tree of the brief's last rev commit |
| Flagged lines | a line of the brief cites a doc line that changed since (#166's flags) |

- **The rev commit** is found as `history()` finds it, with #132's merge guard (G3): one log over `processed/brief/`
  for all briefs, unless a merge touched that folder, and then one log per brief.
- **The tree** is `git ls-tree -r --name-only <rev commit> -- raw/`, once per brief, cached by commit id, so briefs
  committed together share one call. A run file the tree lacks is one the brief couldn't have seen, whichever machine
  wrote it and whenever it was pulled. No clock is compared.
- **The mentions and run files** come from the index (`records.path`), brought up to date first, as a search does.
- **An orphaned brief** is one whose entity no longer exists. When exactly one other entity holds the gone entity's
  name (the brief's title, or the name its id spells) among its names or aliases, the brief names it as the survivor.
  Curate has no merge op today, so a merge is a file deleted and its names added to another, by hand or by a later
  op; the rule reads both the same.
- **`docket brief stale [--entity <id>]`** lists each stale or orphaned brief. With `--entity`, it gives one entity's
  state: stale, current, orphaned, or no brief yet.

The MCP call `briefs(entities=None, stale_only=True)` is read-only and answers the same for the skill. Each brief in its
result has these fields, which the MCP test pins:

| Field | What |
|---|---|
| `id` | the brief's id |
| `entity`, `name`, `type` | the entity's id, its name in the owner's first language that has one, and its type |
| `rev`, `rev_time` | the brief's last rev and that commit's time (UTC) |
| `new` | how many records are new, and the newest five rids |
| `flagged` | how many of its lines are flagged |
| `orphaned` | for an orphaned brief, the surviving entity's id, or null when none is named |
| `state` | `stale`, `current` or `orphaned` |

The result as a whole also gives `hidden`: how many briefs it left out because a never-store list holds their entity.

### The skill

The plugin's `brief` skill rebuilds one brief, or after a sync the stale ones, through doc_put:

1. `briefs` for the stale list, or the entity the user named.
2. For each, `read` the brief as it is, then `search` the entity's records since its rev, and `read` and `verify` the
   notes they are summed up in.
3. Write the brief in the fixed form: what changed since the last rev, the last conversations (newest first, at most
   ten), the decisions said in them. Each line cites the note line it sums up, with the `cite` token, or the raw.
4. For an orphaned brief with a survivor, fold its lines into the survivor's brief, then say the orphan can be deleted.
5. `doc_put` it, and say which briefs it rebuilt.

The run's closing steps (`run_open`'s rules) gain one line: after `ingest`, `briefs` names the stale ones, and the
brief skill rebuilds them when the user asks. Writing a brief is never automatic.

### The Briefs page (DR-0557), the second PR

It follows the Recording page (#164, DR-0544): GET only, a whole page per state, plain links, the URL holding the state
in one canonical form, the facts read through recall and the index.

| Part | What it shows |
|---|---|
| `/briefs` | the briefs grouped by entity type, each with its entity's name, rev, age since that rev, flagged lines and new records; orphans with their survivor |
| `/briefs?brief=<id>` | the brief's lines, with their flags, beside the raw a chosen line cites: `line=<n>` shows that line's spans, as `verify` gives them, refs followed one level |
| URL | `brief`, `line` and `type`, in that order, defaults left out; unknown parameters ignored |
| Links | a line's anchor links to the Recording page at that time, or to Search for a mail or a chat |

### Never-store (DR-0558)

doc_put's screen for a brief builds its phrases from each people-list value's forms, as matching a record's author
does (`_forms`): the name without an `<address>`, and each address. Each name goes in both word orders (`_orders`). The
screen reads the body, the title and every ref's doc id, and the brief's own id and its refs' ids through
`slug_listed`, on top of the keywords list every doc is screened with. With people `Dóra Minta` and
`Ben Sample <ben@example.invalid>`:

| Shape | Caught by |
|---|---|
| met Dora Minta today | the name as written, accents folded |
| met Minta Dóra today | the other word order |
| Minta, Dóra | the other word order, punctuation read as a word break |
| minta-dora (a slug) | `slug_listed` |
| Ben Sample asked | the name without its address |
| mail from ben@example.invalid | the address |

| Rule | Where |
|---|---|
| no brief for an entity a list holds, by its id or a name (`slug_listed`, `listed`) | doc_put refuses it |
| a brief never names a person on the people list, in any of the shapes above | doc_put refuses it, naming the line, never the value |
| a list that gains a value later | the page and `docket brief stale` leave out a brief whose entity is now listed, and count it as `hidden`. A line whose text a list now names is shown as "a line hidden: it names a never-store value", as Curate hides a snippet |
| hidden by URL too | a hidden line's `line=<n>` opens nothing, no spans and no refs, and `brief=<id>` for a brief whose entity is now listed answers "hidden" |

## Steps

The first PR:

1. Brief checks in doc_put: the id's entity, `entities`, the sections and the warning for more, and the never-store
   screen. Tested by `test_briefs.py`: each refusal, the six shapes, an unanchored line refused, an extra section
   warned, a brief citing note lines only stored with empty `covers`.
2. The rev commit per brief with the merge guard, the cached tree per commit, the mentions from the index, orphans,
   and the stale report in `briefs.py`; `docket brief stale`. Tested by `test_briefs.py`.
3. The MCP tool `briefs`. Tested by `test_service_mcp.py`, which pins its fields.
4. The `brief` skill and the run's closing line. Tested by the plugin's own checks (`test_plugin_files.py`).

The second PR:

5. The Briefs page. Tested by `test_web_briefs.py`: it renders without JavaScript, groups by type, opens a brief beside
   a line's raw, shows a flagged line and an orphan, and hides a listed entity and a listed line, by URL too.

## Tests

| Test | What it proves |
|---|---|
| a new record | a record mentioning the entity, promoted after the brief, makes it stale and is listed by rid |
| another machine's record | a record whose run file was written before the brief on another clone, and pulled after it, makes it stale: its run file isn't in the brief's tree |
| a backfill | a record with an old `ts` that arrives after the brief makes it stale too |
| a merge in history | with a merge in `processed/brief/`, the rev commit comes from the brief's own log and the result is the same |
| a flagged line | a correction to a cited note line makes the brief stale |
| current again | the brief's next rev clears both reasons |
| an orphan | an entity deleted and its name added as an alias of another: the brief is orphaned and names the survivor |
| the form | missing or reordered sections, a missing `entities` entry, an entity that doesn't exist; an extra section after the three is warned, not refused |
| unanchored | a brief line with no anchor or ref is refused |
| never-store | a listed entity gets no brief; the six shapes are refused; the stale list hides what a list gained later and counts it |
| the tool | the `briefs` result's fields and `hidden` |
| the page | renders without JavaScript; the URL's canonical form; a line opens its raw; a hidden line opens nothing; a newly listed entity's brief answers hidden |

All on the test kit's vaults, with invented people.

## Risks

| Risk | Answer |
|---|---|
| the sections aren't what the maintainer wants | accepted for now: the three are required, more are warned, and the maintainer's week of real briefs for three people and two projects settles the format before #162 builds on it |
| a record that names the entity only by an alias curate hasn't learned doesn't make the brief stale | accepted: staleness is as good as the aliases, which the weekly curate round keeps up |
| a busy entity is stale after every sync | by design: stale is a prompt, and the skill rebuilds only when the user asks |
| a never-store person's common first name blocks a brief that names someone else | fails closed, as the lists do everywhere; the refusal names the line, never the value |
| `ls-tree` of `raw/` costs a git call per distinct rev commit | cached by commit id; briefs put in one batch share it |
| an orphan's survivor guessed wrong | it is named only when exactly one entity holds the gone name; otherwise the brief is orphaned with no survivor, and the skill asks |
