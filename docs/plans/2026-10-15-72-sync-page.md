# Add the Sync page: runs, cursors, failures and what needs a session

## Goal

The user sees how syncs went without reading a log: what to ask Claude to sync now, what failed and what to do about
it, the runs open and just ended, and where each machine's cursors stand. `/sync` is read-only and shows ids, counts,
times and Docket's own messages, never anything from a capture.

- In scope:
  - the Sync page at `/sync` and its runs fragment, in the shell, linked from the navigation;
  - a small run history, so recent runs survive a restart: one line per ended run in the vault's private folder;
  - a kind for every way a run drops, for the page's advice;
  - `run_open`'s checks and its final-run rule as functions the page calls too;
  - the shell's per-page bits the second page needs: the current page, its own keys;
  - tests over HTTP on invented runs, and the browser test's Sync flow at desktop and phone width.
- Out of scope:
  - any write from the page: opening, closing or dropping a run, editing a cursor;
  - imports with `docket ingest`, which aren't runs; staging's records, which the Staging page shows (#71);
  - per-source settings such as a sync cadence, which belong to Settings (#73) and `vault.yaml`'s door;
  - telling Claude at session start what is due (the status hook's lines, DR-0163): the rule is one function it can
    call later;
  - a `docket sync status` command.

### The page

Conclusion first: what needs doing, then what failed, then the runs, then the cursors.

- The sources: each one whose `vault.yaml` entry lists tools, and any other a cursor file or the history names. A
  turned-off source shows muted and needs nothing.
- `source` narrows every part to one source.
- Each part has its empty state: no source with tools (`docket source new`, then its tools in `vault.yaml`), no run
  yet on this machine, nothing failed since each source's last whole close, no cursor file yet.
- No vault, or one that doesn't read: the `DocketError`'s message, as on Search. Anything else: the error page.

### Where each fact comes from

| Fact | From |
|---|---|
| open runs: source, final or backfill, bound, closing, captures and bytes of the budget, opened, last capture, when it drops, why it is short, its window, how many ids it was told to skip | `Runs` in the service's memory, as a snapshot; no session or agent id |
| recent runs: opened, ended, closed or dropped with its kind and reason, captures, staged counts, intake drops, skips by reason, the mark, what is owed after, expired ids | the run history (below) |
| each machine's mark, lookback, retry and waiting entries with reasons and first dates | `state/cursors-<machine>.yaml`, through `cursors.read` and `read_others` |
| the next window | `cursors.window`, as `run_open` works it out |
| a final run due | `cursors.handover(final=True)` with the inputs `run_open` gives it |
| what needs the user first | `preflight`: the checks `run_open` makes before any work |
| ages and "drops at" | the service's clock (`Runs.clock`), injected in tests |

Every value is autoescaped; ids are shown as locators (mono, copyable). Times are in the owner's zone, ages beside
them, as `<time datetime>`.

### Needs

What needs a Claude session, and what needs the user before a session can help (DR-0304).

| Need | When | The line |
|---|---|---|
| needs you | `preflight` refuses: no `SKILL.md` or one without the marker line, no mapper, this machine's cursor file unreadable, a held record waiting in staging | `run_open`'s own message, which names the fix |
| due | no machine's mark of the source is under a day old, or none has one, and no run of it is open | the newest mark, its machine and its age; the words to paste |
| final run due | `handover(final=True)` hands over any id | how many ids, the oldest's age; the words to paste |
| running | a run of it is open | no need; the run is under Runs |

- The words to paste: `Sync plaud with Docket: run_open("plaud") and follow its steps.`; for a final run alone,
  `Run Docket's final run for plaud: run_open("plaud", final=true).` A copy button beside them; without the script
  they are text to select. Several sources due get one line naming them, one at a time.
- A day, not the source's lookback: with the lookback the page says nothing for a week. A cadence per source would be
  a `vault.yaml` key (DR-0124), for Settings.
- A source due and with a final run due gets the first words only: the run's steps open the final run after its
  close.

### Failures

Current problems only, each with what to do (DR-0305). An older one stays in the runs list.

| Kind | Shown while | What to do |
|---|---|---|
| `unbound` | no whole close of its source since | turn the docket plugin on in the session that syncs, with `docket` on PATH, and sync again |
| `idle`, `too-long`, `stopped`, `replaced` | the same | nothing: the next sync covers the window (a rate limit on the listing ends as `idle`) |
| `short`: a refused capture | the same | a tool not listed: add it to `sources.<source>.tools` in `vault.yaml`, or refresh the skill from the reference; a cap: fewer items a run |
| `count` | the same | nothing; if it repeats, the capture hook misses calls: check the plugin |
| `mapper` | the same | run the mapper's tests, `.claude/skills/sources/<source>/tests` in the project |
| `refused`, `failed` | the same | `refused`: what its message says (a held record in staging names its files); `failed`: `docket service status` names the log |
| cursor not moved, not committed | no later whole close of its source moved or committed it | not moved: nothing, the next run fetches the window again; not committed: nothing, the next close commits it |
| `rate-limited`, `too-large`, `gone`, another reason | a cursor file holds the retry entry | the date it leaves (30 days from its first); `too-large`: refresh the skill from the reference, which pages smaller |
| expired | 7 days after the close that expired it | if one matters, fetch it by hand and `docket ingest` its folder |
| held but in raw | 7 days after that close | it waits for `docket forget`, as the close said |
| this machine's cursor file doesn't read | now | fix the line it names; a conflict: keep one side, the older mark is safe |
| another machine's doesn't read | now | fix it on that machine; its marks and sets are left out meanwhile |

`later` isn't a failure: an id held back for the budget shows under Cursors. One table in `sync_view.py` holds the
advice, and a test holds it to every kind.

### Runs

Open runs first, then recent ones newest first; `k` of them, 20 to start, Show more adds 20 (DR-0303).

- An open run: its id, source, badges (final, backfill, closing, not bound yet), opened and its age, captures and
  bytes of the 400 KB budget, the last capture's age, when it drops (the earliest of the bind's minute, 30 minutes
  idle and 6 hours open), why it is short when it is, its window, the ids it was told to skip, held and handed over.
- A recent run: its outcome (closed, or dropped and its kind), source, badges, opened, how long it ran, captures and
  bytes, then for a close: staged pending and ready, already staged or in raw, on hold, intake drops by reason,
  skips by reason, set aside and waiting, the mark moved or kept, what is owed after, ids expired; for a drop, its
  reason. The id lists sit in a `<details>`; `run=` opens one's card at the top.
- While a run is open, the runs part asks `/sync/runs` again after 5 seconds and swaps only itself (DR-0306). With
  none open the refresh stops, and the part says to reload for the cursors and what is due.

### The run history

`<private>/sync/runs.jsonl`, beside `folders.json` (DR-0248): one line per ended run, per machine, never committed
(DR-0301).

```json
{"v": 1, "run": "run-20261015T091200-3f9a1c2e4b5d6e7f", "source": "plaud", "final": false, "backfill": false,
 "opened": "2026-10-15T09:12:00Z", "ended": "2026-10-15T09:19:41Z", "since": "2026-10-08T09:12:00Z",
 "until": "2026-10-15T09:12:00Z", "outcome": "closed", "kind": "closed", "why": null,
 "captures": 12, "bytes": 187392, "told_to_skip": 6, "held": 2, "handed": {"retry": 0, "waiting": 1},
 "skipped": {"later": 2, "rate-limited": 1}, "staged": {"pending": 3, "ready": 0, "skipped": 6, "on_hold": 0},
 "dropped": {}, "set_aside": [], "set_aside_count": 0, "waiting": ["of_00decaf000decaf000decaf000decaf0"],
 "waiting_count": 1, "mark": {"before": "2026-10-14T07:01:00Z", "after": "2026-10-15T09:12:00Z", "moved": true},
 "cursor_problem": null, "owed": {"retry": 1, "waiting": 1}, "expired": [], "expired_count": 0, "held_in_raw": []}
```

- Ids, counts, times and Docket's own reason, at most 500 characters. Never a capture's arguments or result, a
  title, a session or an agent id. The id lists keep 20 each, with their full counts.
- Written by the service alone, as each run ends: appended whole under the history's own lock, off the writer thread
  and outside the vault lock. DR-0153 queues the vault's data; this is one machine's log of the service's own runs,
  like `runs.json`, and no other Docket writes it. Through `make_private`, so a git dir that went missing is refused.
- Read at start into memory, the newest 500; the page reads memory only. A line that doesn't read is skipped. Past
  1,000 lines the file is rewritten with the newest 500, through a temp file and a rename.
- A write that fails keeps the line in memory, logs the error's type, and the page says runs aren't kept across a
  restart, and why.
- Disposable: nothing decides from it; windows, marks and the sets read the cursor files. Deleting it loses only the
  page's list. A later format starts a new file. So no door.

Every drop names a kind (DR-0302):

| Kind | Dropped by |
|---|---|
| `unbound` | no bind within 60 seconds of the open, or a close of a run never bound |
| `idle`, `too-long` | 30 minutes with no capture; 6 hours open |
| `replaced` | a newer run of its source, or a second run bound to its session and agent |
| `stopped` | the service stopping (`close_all`); a stale `runs.json` at start, with no counts |
| `short`, `count` | a close of a run marked short; a count that doesn't match |
| `mapper` | `MapperFailedError` or `MapperRefusedError` at close |
| `refused`, `failed` | another `DocketError` at close; any other exception |

A run dropped by a limit ends when the limit passed, not when a later call's sweep saw it.

### Cursors

Per source, the next window, then one row per machine whose file names the source.

- A row: the machine (this one marked), the mark with its age, the lookback, the retry and waiting counts. Another
  machine's row says whether its sets are handed over: while its mark is under 30 days old (DR-0247).
- Its entries in a `<details>`: retry with reason, first date, age and the date it leaves (none for `later`); waiting
  with what it waits for, first date and age; "due a final run" on each that is.
- A mark ahead of this machine's clock is marked as left out of the window, as `run_open` notes it.
- A cursor file that doesn't read shows its message in place of its rows.

### The URL and the fragment

| Parameter | What | Default |
|---|---|---|
| `source` | narrow every part to one source | all |
| `run` | open this run's card at the top of Runs, open or in the history | none |
| `k` | how many recent runs: Show more adds 20, up to 500 | 20 |

- One canonical form: this order, defaults left out. A malformed value (not a source's name, not a run's id, `k` out
  of range) is the page's own error, status 400; a well-formed source or run the page doesn't know says so, status
  200; unknown parameters are ignored, and parameters only gain (DR-0303).
- `/sync` is always a whole page; `/sync/runs` always the runs part, for the refresh. Links are plain links to
  `/sync?...`: the page is light, and every part changes with `source`. The fragment names the canonical URL by
  DR-0170's rule, so the refresh never adds a history entry.
- Without JavaScript the page shows the same at load, with a reload link beside "as of".
- Only GET, as on Search: no new write route.

### Look and phone width

The Search page's look: the shell, the tokens, cards with a left border in the state's colour (ok, warn, error),
badges, locators in the mono face, notices, the empty state.

- No wide tables: lists and description lists that stack under 600 px, ids wrapping anywhere, the source chips
  wrapping, the words to paste wrapping with their copy button below.
- The Sync page answers one key, `?`; its footer and keys dialog say so. Search keeps its keys.
- Colour never alone: each outcome and kind has its word.

## Doors and data

No one-way door. The MCP tools, their results and texts, the hooks, the cursor file, `runs.json` and `vault.yaml`
stay as they are; `/api` is Docket's own (DR-0151) and its `GET /api/runs` doesn't change.

- The run history file is not a door: it is per machine, never committed, and disposable. Nothing decides from it, a
  line that doesn't read is skipped, and a later format starts a new file. It is not on AGENTS.md's list and doesn't
  join it.
- Users' data: each vault gains `<private>/sync/runs.jsonl` on the first run that ends after the upgrade. Nothing
  migrates; deleting it loses only the page's list of recent runs.

The decisions, `proposed`, `by: Claude (autonomy grant)`, added with this plan in `packages/docket/index.yaml`:

| Id | Decision | Cost |
|---|---|---|
| DR-0300 | The Sync page is read-only and shows what needs doing, what failed, the runs and the cursors | cheap |
| DR-0301 | Each ended run's summary is a line in the vault's private folder, sync/runs.jsonl, and is disposable | cheap |
| DR-0302 | A dropped run names its kind, and runs a crash left open are recorded at the next start | cheap |
| DR-0303 | The Sync page's URL holds source, run and k | cheap |
| DR-0304 | A source is due when no machine synced it in a day; a final run is due by run_open's own rule | cheap |
| DR-0305 | The Sync page shows current failures, each with what to do | cheap |
| DR-0306 | The Sync page's runs part refreshes every 5 seconds while a run is open | cheap |

## Steps

Each step builds and passes `uv run gate` on its own.

1. Run summaries and the history. `runs.py` (kinds, the summary, the stale marker's runs, the snapshot),
   `history.py`, the wiring in `state.py`, each drop in `sync.py` passing its kind. `test_service_runs.py`: each
   drop path has its kind and an end time when its limit passed; `close_all` ends every run as `stopped`; a stale
   marker's runs are recorded before it goes; no summary holds a session or agent id. `test_service_history.py`: a
   line round-trips; a torn last line and a line of another version are skipped; past 1,000 lines the file holds
   the newest 500; a private folder that can't be written keeps memory and names why; a missing git dir is refused,
   not made. In `test_service_api_runs.py`: a whole run's line has its staged counts, skips by reason, mark and
   expired ids; a mapper failure is `mapper`, a count that doesn't match `count`; neither `TITLE` nor the session
   id is in the file.
2. `preflight` and `owed`, and `run_open` on them. `test_service_api_runs.py` and the MCP golden file pass
   unchanged. New: `preflight` gives `run_open`'s message for each refusal it covers; with an id waiting 8 days
   `owed` hands it over and `run_open(final=true)` opens, with none it hands nothing and `run_open(final=true)`
   refuses.
3. The shell. Sync built in `pages.py`, `shell(current=)`, keys per page, the shared CSS moved, the push-or-replace
   rule in `templating.py`. `test_web_shell.py` counts links and slots from `pages.NAV`'s built pages rather than a
   number, so Staging's and Settings' branches don't collide on it; `test_web_a11y.py`'s keys test runs per page;
   Search's tests pass unchanged.
4. The view. `SyncState` and `sync_view.py`. `test_web_sync_view.py`, with invented facts and a fixed clock: due
   at a day and not before, running beats due, needs-you first; a final run due at 7 days; each failure's window
   (a drop until a later whole close, a retry entry while held, an expiry for 7 days); the advice table covers every
   kind; another machine handed over at 29 days and not at 30; drops-at the earliest of the three limits;
   `SyncState` written back canonical, its errors, unknown parameters ignored.
5. The routes and templates. `web/sync.py`, `templates/sync/`, `sync.css`. `test_web_sync.py` (below); `/sync`,
   `/sync?source=memo`, `/sync?run=<id>` and `/sync/runs` join the CSP, HTML and a11y lists in `test_web_shell.py`
   and `test_web_a11y.py`.
6. The browser. A Sync flow in `test_web_browser.py` (below).
7. The docs below, then `finish-work`: `uv run gate full`, a draft PR, `review-code` until it is clean.

## Risks

| Risk | Status |
|---|---|
| a Docket message stored in `why` quotes a payload | resolved: the messages are Docket's own (ids, counts, paths), the mapper's stderr is never in them (DR-0244), and a test plants a title and a phrase in a capture and finds neither in the file or the page |
| the history grows without end | resolved: trimmed to the newest 500 past 1,000 lines |
