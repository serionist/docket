# Add the source contract, mappers and Plaud as the reference source

## Goal

A source's mapper, kept in the consuming project, plugs into a contract the core owns, and Plaud is the reference
source that shows it working. The core runs a mapper in its own process, checks every rid, computes every version,
keeps held recordings out on every route and in the gate, and cuts transcripts by time. `docket ingest <source>
<folder>` imports payloads fetched earlier through the same mapper, so a user's backfill goes in from their own project
with their own mapper.

- In scope, the core: the mapper interface (a run's captures and its manifest in, records out); loading a mapper from
  the path `vault.yaml` names, which must resolve under `.claude/skills/sources/<source>/`; running it in its own
  process with a time limit and an output cap; rid checks, segment order and a transcript's text set by the core; the
  hold list in the gate; the time cutter over `segments`; `vault.yaml`'s source names checked and its new source keys
  (mapper, tools, media hosts); `docket ingest <source> <folder>`; removing `records.register_projection` and
  `cuts.register_cutter` with their tests.
- In scope, the example: `examples/sources/plaud/` with `SKILL.md`, `mapper.py` and `tests/`, run by the gate on all
  three systems. It is an example to copy, not a dependency: nothing in `packages/` imports it.
- Out of scope: fetching, the cursor, the retry set, the service's `ingest` tool and its buffering (#8); the capture
  hook, setup and `docket source new` (#12); releasing holds and staging held recordings with their cuts (#31); audio
  and its cuts (phase 2); `media_put`'s fetch (#8: this only adds the hosts key); Plaud's outline and highlights;
  classifying a recording's records together (the Staging page, phase 1); a user's own sources, which live in their
  project.

## Design

The core has no source's code. A mapper is plain Python in the consuming project that reads JSON and writes JSON; the
core starts it, checks what it returns, and owns everything a mapper could get wrong for privacy or ids.

### The mapper interface

`mapper.py` defines `map_run(run: dict) -> dict`. Both are plain JSON, so a mapper needs nothing but the standard
library.

| In | What |
|---|---|
| `contract` | `1` |
| `source` | the source's name |
| `manifest` | `run`, `source`, `captures` (the count), `final`, `window` (`since`, `until`) or null, `skipped` (`{id, reason}`), `folder` or null |
| `captures` | each `{seq, run, captured, tool, arguments, result, file}`: a tool's result as given, with the tool's name without the host's prefix; or a file from an import folder (`tool` null, `file` its name, `result` its JSON, `captured` its modification time) |
| `holds` | the source's held ids |

| Out | What |
|---|---|
| `contract` | `1` |
| `records` | raw records in the core's shape, without `v` or `run`; a transcript's utterances in `segments`, its `text` left empty |
| `set_aside` | `{id, reason, tool, key}`: what the mapper couldn't use, and why |
| `waiting` | `{id, for}`: ids waiting for more, such as a transcript or a summary |
| `held` | the held ids it saw and skipped |

- `print()` inside a mapper goes to stderr, so debugging output can't break the JSON.
- A later contract changes the number, and a mapper written for another one fails loudly instead of mapping wrong.

### Running a mapper

- `vault.yaml` names it per source: `mapper: .claude/skills/sources/<source>/mapper.py`, relative to the consuming
  repo, which is the git repo that holds the vault's folder (`--show-toplevel` from the vault's parent). That works for
  a vault folder in the repo and for a vault repo nested in it, the setup's default.
- A source's name is checked before it builds any path: `vault.yaml` refuses a `sources` key that doesn't match the
  rid's source pattern (`^[a-z0-9][a-z0-9._-]*$`) or ends in `.`, which Windows drops from a file name. So `..`,
  `a/b` and `Plaud` (one folder with `plaud` on Windows and macOS) never name a folder. The runner checks the name
  again.
- The mapper's real path, after symlinks, must sit under the real path of `<repo>/.claude/skills/sources/<name>/`,
  built from the checked name, and outside the vault. An absolute path, `..`, or a symlink that leads anywhere else (a
  downloads folder, the vault, another source's folder) is refused before anything runs.
- The core starts `python -I -m docket.sources.child <mapper>` with its own interpreter, in the mapper's folder, with
  an environment holding only what Python needs to start, so nothing in the service's environment reaches it.
- Limits: 300 seconds, 256 MiB of output. Past either the process is killed and the run fails.
- A failed run stages nothing: a timeout, a crash, output that isn't JSON or a contract mismatch. #8 then drops the
  captures and keeps the mark, so they are fetched again, as for a run that never closes.
- The mapper's stderr is never logged and never part of an error, since a traceback can quote a payload. `docket
  ingest --mapper-errors` prints it for the user who asks.

### What the core checks

Every record a mapper returns, before any reaches the gate. One failure fails the whole run, so the mark stays and a
fixed mapper sees the same captures again.

| Check | Refused when |
|---|---|
| shape | it isn't a raw record: a field of the wrong type, such as `to` as a string, or a `ts` without a zone |
| source | `source` isn't the run's source |
| rid | not `<source>:<native id>`: no whitespace or control characters, at most 512 characters, no empty part between `/` |
| container, thread | set to a rid of another source |
| version, run | the mapper set `v` or `run`: the core computes the version |
| fidelity | the mapper set `cut`: only the core's cutter marks a record cut |
| once | a rid comes twice in one run's output |
| text | a record with `segments` also sets `text` |
| report | an entry's `id` is neither a native id nor null, or `reason`, `for`, `tool` or `key` isn't a short token (`[A-Za-z0-9_.\[\]-]`, at most 64 characters) |

- Errors name a record by its position in the output and the field, never by a value from it: a rid, a reason or a
  bad field from a buggy mapper can hold a title. A shape error is built from pydantic's error location and type only;
  its message and `input_value`, which quote the input, never pass through.
- Then the core sorts each record's segments by start, end, speaker and text, drops exact duplicates, and renders its
  `text` from them, one line per segment, `<speaker>: <text>`, or the text alone without a speaker. A page boundary or
  the order captures arrived in never makes a new version, and every source's transcripts read alike. This refines
  the bind in DR-0111 that a record keeps its mapper's order: on the mapper route, the order kept is the core's.
- Versions come from the gate's `stage`, as now, with DR-0020's one projection.

### Holds

Recordings Docket must not stage yet are held by id in the vault, per source. The core enforces them on every route
in, and the gate on every way out of staging.

- `state/holds/<source>.txt`, committed: one native id a line. It sits in `state/`, so the vault's layout (DR-0019)
  doesn't change.
- Read as UTF-8 with or without a BOM, each line stripped, blank lines skipped, any order, duplicates allowed. A line
  that isn't a native id, or a `.txt` there whose name isn't a source's, refuses every ingest of that source and every
  gate call, naming the file and the line number, never the line's text: the list fails closed.
- The path is built only from a checked source name. A hold list, or `state/holds/` itself, that is a symlink is
  refused on read and on write. A list is written to a temp file in `.git/docket/tmp/` and renamed over the old one,
  never written through a link.
- A hold on `<id>` covers a record whose rid, thread or container is `<source>:<id>` or starts `<source>:<id>/`.
- Two machines can add at once: `state/holds/*.txt merge=union` in the vault's `.gitattributes`, written in the commit
  that first creates a list and carried by the init template; the next add sorts the list and drops duplicates.
- Docket only adds, committed as `Holds: <source>, <n> added on <machine>`, a message with no id. #31 releases.

| Where | What happens to a held record |
|---|---|
| `ingest_run`, before the mapper runs | any held record waiting in staging stops the ingest of its source, naming each staged file's path, until those files are deleted by hand |
| the mapper | gets the hold list and skips held captures before parsing them |
| `ingest_run`, after the mapper | records and report entries under a held id are dropped and only counted ("on hold 3") |
| raw | a held rid already in raw is named on every run; it waits for `docket forget` (phase 2) |
| `Gate.stage` | not staged; counted `on_hold`, with no id |
| `Gate.classify` | refused, work or private, naming the hold list; nothing written |
| `Gate.promote` | left waiting; counted `on_hold` |

- The gate's sweep reads the hold lists on every call, the way it reads `vault.yaml`, so a record staged before its
  hold arrived (a second clone, before a sync) can't reach raw, whether or not an ingest runs first.
- The count is `on_hold`, not `held`: the gate already calls a record it can't promote "held".

### Time cuts

The core cuts a transcript by its `segments` (DR-0028, as #33 updates it); no source registers a cutter.

| Record | `ms` cuts | `char` cuts |
|---|---|---|
| with segments | each segment overlapping a cut goes whole (an utterance has no word times); one `[cut]` segment spans each cut widened to what it removed, cuts that touch after widening made one; `text` rendered again | refused by #33's check, kept: its `text` is rendered from its segments; cut it by time |
| without segments | refused: nothing to cut by time; cut its transcript, or classify it private | `cut_text`, as now |

- A cut that starts after the last segment ends is refused; one over silence still leaves its `[cut]` segment.
- Every cut record keeps no `native`. One marked `verbatim` becomes `fidelity: cut`, so `RawRecord.fidelity` gains
  `cut`; one marked `derived` (its id built from its content) stays `derived`, and is known as cut by `[cut]` in its
  text and its empty `native`. That refines DR-0108's bind, which says every cut record is marked `cut`, so the
  derived-id mark is never lost.

### The import

`ingest_run(vault, source, manifest, captures, folder=None)` is the one way in. The CLI calls it with a folder; #8
calls it when a run's manifest closes the run, with the captures and, for a backfill run, a folder.

1. The folder's `hold.txt` and the `--hold` file are read; a bad line stops the run before anything is written. Their
   ids are added to the hold list and committed.
2. The hold list is read; a held record in staging stops the run.
3. The count is checked: captures that don't match the manifest's count, or carry another run, refuse the run.
4. The folder's `*.json` files join the captures: one shaped like a capture (`tool`, `arguments`, `result`,
   `captured`) as that capture, any other as a file. A file that isn't JSON is counted and named by its place in the
   folder's sorted listing, never by its name, since a backfill's file names can be titles.
5. The mapper runs; its output is checked and normalized; held records are dropped.
6. The rest goes through `Gate(vault).stage()`.

`docket ingest <source> <folder> [--hold <file>] [--final] [--mapper-errors]`:

- `--final` sets the manifest's `final`, which tells the mapper not to wait for anything more.
- The output is counts, set-aside ids with their reasons, waiting ids, the on-hold count, hold ids from this import
  that no capture had (so a typo in `hold.txt` shows), held rids in raw. Never a title.
- A source not in `vault.yaml`, or with no `mapper`, is refused, naming the key to add.
- Running it twice stages nothing new: the gate skips what staging or raw has.

### The Plaud example

`examples/sources/plaud/`: the skill, its mapper and their tests, a user's starting point once copied to
`.claude/skills/sources/plaud/`. Standard library only.

Three records per recording, all with the recording's rid as `thread` and `container`, so the index groups them as one
hit and a never-store `containers` entry drops a whole recording by its id:

| Record | rid | kind | Content |
|---|---|---|---|
| the recording | `plaud:<file id>` | `recording` | `title` its name, no text; `native` the six meta keys both the listing and `get_file` give |
| its transcript | `plaud:<file id>/<block>`: `transaction_polish`, or `transaction` when that is empty | `transcript`, engine `plaud/<block>` | `segments` from Plaud's `start_time`, `end_time`, `speaker`, `content`; `native` the file id, the block and Plaud's segments, every page |
| Plaud's notes | `plaud:<file id>/summary` | `vendor-summary`, engine `plaud` | `text` each tab as `## <title>`, a blank line, its content, tabs sorted by type, title and content |

- All three: `ts` the recording's `start_at`, `fidelity` verbatim, `via` `plaud-mcp` or `plaud-file`, `fetched` the
  capture time.
- Plaud's times without a zone are UTC: checked against local times written down by hand for a few recordings.
- `presigned_url`, `data_link` and `data_path` are dropped from `native` at any depth: they carry a session token or
  the account's internals.
- A file id is letters, digits, `_` and `-`; anything else is set aside as `bad-id` with a null id, never echoed.
- A tab counts when its content isn't empty; its title is `data_title`, else `data_tab_name`, else `Summary`: the rule
  the backfill script used, so a backfill file and a later capture of one recording give the same text.
- Results are read from `structuredContent`, else from the first JSON value in their text.
- A capture's file id is read before anything is parsed, from `arguments.file_id`, each listing item's `id` or a
  backfill file's `file_id`, and checked against the holds first.

Assembling a recording, once per run, from all its captures:

| Has | Gives |
|---|---|
| a transcript with segments, its page chain complete | the transcript |
| an empty transcript (both blocks empty, a list result, a backfill `block` null) | nothing; the id waits for its transcript; when final, it is stored without one |
| tabs | the summary, and the recording under the name in the newest meta |
| `final`, no tabs | the recording alone, under the name at that point |
| meta only, not final | nothing; the id waits for its summary |
| no meta | nothing; set aside as `no-meta`: without `start_at` no record has a `ts` |

- The recording waits for the summary because Plaud renames a recording when it writes the summary; staged earlier,
  every recording would get a second version.
- A transcript's pages chain from the first through each `next_cursor` to a page without one; a broken chain is set
  aside, never staged, since a partial transcript would stay in raw for good.
- With several meta captures of one recording, the newest wins, so the listing captured after the run's notes gives
  the renamed recording.
- Backfill files are always final: Plaud won't write summaries for old recordings. Their start times come from a
  listing captured with them.

`SKILL.md` is the route, for a session with the service (#8) and the hook (#12):

- `list_files` newest first, without date filters (they aren't exact), until a page's oldest `start_at` is before the
  window's start.
- Per recording: every page of `get_transcript` for `transaction_polish` (`limit` 500, following `next_cursor`), else
  for `transaction`; then `get_note`; then the listing again after the run's last `get_note`.
- Held ids and what raw or staging already has are skipped, read through the service; that saves calls, the core is the
  control.
- `429 Too Many Requests`: pause and retry with growing pauses; still limited, end the run, and the kept window
  resumes it.
- "not authenticated" means the server's `login` tool.
- A waiting id is asked for again on later runs, and after 7 days as final.
- A backfill run: the listing paged down past the oldest backfill recording, no other calls, its manifest naming the
  backfill folder.
- Changing the mapper: keep its output stable, since every record the lookback reads again gets a new version when
  the output changes; pin golden versions in the mapper's tests, as the example does; pull the project on every machine
  before its next sync, so two machines never map one recording two ways.

## Decided

Taken under the autonomy grant; each one's alternative is the option not taken.

| Decided | Not taken |
|---|---|
| JSON in and out of `map_run`, with a contract number | a Python API importing Docket: every mapper would break on Docket's internals |
| the mapper in its own process with Docket's interpreter and `-I` | in the service's process: a hung or crashing mapper takes the service down; any command or language: more to secure for no user yet |
| a bare environment, cwd the mapper's folder | the service's environment: whatever it holds reaches user code |
| 300 seconds and 256 MiB | a few seconds and a few MB: a backfill of hundreds of transcripts runs in one process |
| the consuming repo is the one holding the vault's folder | a project path in `vault.yaml`: one more setting to keep right, for the layout the setup already makes; a flag on every call: the service has no one to ask |
| any refused record fails the whole run | skip it and stage the rest: the mark moves and the refused record is lost for good |
| errors name a record's position and field, never a value | quote the rid, or pass pydantic's message on: both can hold a title |
| source names checked against the rid's pattern in `vault.yaml` | checked where each path is built: one missed place lets `..` widen the mapper folder or move a hold list out of the vault |
| hold lists written by temp file and rename, a symlinked list refused | written in place: a link planted there sends the write anywhere |
| `fidelity: cut` replaces `verbatim` only | on every cut record: a `derived` record would lose the mark that says its id is built from content |
| report entries are ids and short tokens | free-text reasons: a mapper could put a title in a terminal |
| stderr only with `--mapper-errors` | always shown: a traceback can quote a payload |
| the core sorts segments and renders a transcript's text | each mapper renders: two sources' transcripts read differently, and a mapper's rendering change re-versions everything |
| a mapper leaves `text` empty on a record with segments | the core overwrites it: a mapper's text would vanish without a word |
| a hold covers rid, thread and container, and what is under `<id>/` | the rid alone: a mapper's other rid shape for the same recording slips past |
| hold lists for every source, in `state/holds/` | Plaud's only: the next mixed source repeats the work; a top-level `holds/`: changes the layout |
| a held record in staging stops every ingest of its source | only the run that adds the hold: one "work" classification later, the left-out stretches are in git |
| the hold check in the gate as well as in the ingest | the ingest alone: a record staged before its hold arrived could be classified and promoted with no ingest between |
