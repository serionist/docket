# Add the Plaud source: its profile and the import of fetched transcripts

## Goal

Docket knows what a Plaud recording is: its ids, its versions, its segments and its cuts, and it can turn what Plaud's
MCP tools return into raw records. The transcripts already fetched go through the gate with it. Fetching new ones is
the plugin's Plaud skill (#12) with the user's own Plaud MCP, captured verbatim by the plugin's hook and posted to the
service's `ingest` tool (#8); this plan writes down what they need.

- In scope: the Plaud profile in the core (`docket/sources/plaud.py`): rids and kinds, the projection per kind, the
  segment reader (#6), the cutter (#5), the zone rule, and the mapping of `list_files`, `get_file`, `get_transcript`
  and `get_note` results to records; the hold list, which keeps recordings out of staging on every route;
  `docket ingest <source> <folder>`, which reads backfill files and captured tool results; Plaud's note names for the
  legacy import (#11).
- Out of scope: fetching, the cursor, the retry set and backoff (Handed to #8 and #12); a Python connector package
  (only if a headless or scheduled fetch needs one later); audio (phase 2); Plaud's outline and highlight blocks
  (highlights are phase 1); classifying a recording's records in one go (the Staging page, phase 1); staging held
  recordings with their cuts and releasing them from the hold list (#31: the stretches are written in words, not
  times); reading the backfill's manifest (a private format Docket doesn't learn).

## Design

One module per source in the core, registered when the vault package is imported, so no process can version a Plaud
record without Plaud's projection.

| Module | What it does |
|---|---|
| `docket/sources/__init__.py` | `register_builtin()`: registers each profile's projection, segment reader, cutter and note names once; `profile(source)` for the ingest command |
| `docket/sources/holds.py` | the hold list `state/holds/<source>.txt`: read it, check it, add ids and commit them |
| `docket/sources/plaud.py` | the payload models, the result unwrapping, the rids, `assemble()`, the projection, the segment reader, the cutter, and `ingest()`, the one entry both routes call |
| `docket/vault/__init__.py` | calls `register_builtin()` after its own imports |
| `docket/cli.py` | `docket ingest <source> <folder>` |

Built on:

| From | What it uses |
|---|---|
| #4 (merged) | `RawRecord`, `register_projection`, `version`, `Vault`, `Vault.commit` |
| #5 | `Gate(vault).stage(records)` and its counts, `Gate.list(source=)` with each entry's `.path`, `register_cutter`, `Cut`, `cut_text`, the `[cut]` marker; a source's cutter gets its records' cuts of both units and refuses with a `DocketError` that `classify` passes on |
| #6 | `Segment`, `register_segments`; a reader is pure |
| #11 | `register_note_names`; whichever of #10 and #11 merges second adds Plaud's line |

### Records

Three records per recording, all with the recording's rid as their `thread` and `container`: the index (#7) groups
hits by `thread`, so a recording's meta, transcript and summary come back as one hit, and the never-store `containers`
list (which matches `container` or `thread`) drops a whole recording by its id. The recording's rid is `plaud:<file
id>`, the form #11 expects.

| Record | rid | kind | text | native |
|---|---|---|---|---|
| the recording | `plaud:<file id>` | `recording` | empty; the name is `title` | `id`, `name`, `created_at`, `serial_number`, `start_at`, `duration`: the meta keys both the listing and `get_file` give |
| its transcript | `plaud:<file id>/<block>`: `transaction_polish`, or `transaction` when the polished block is empty | `transcript`, engine `plaud/<block>` | one line per utterance, `<speaker>: <content>`, by start | `file_id`, `block`, `segments` as Plaud gave them, every page |
| Plaud's notes | `plaud:<file id>/summary` | `vendor-summary`, engine `plaud` | each tab as `## <title>`, a blank line, its content | `file_id`, `tabs` as Plaud gave them |

- All three: `ts` is the recording's `start_at`, `author` null, `fidelity` verbatim, `via` `plaud-mcp` for a capture
  or `plaud-file` for a backfill file, `fetched` the capture time or the file's modification time.
- Plaud gives times without a zone, and they are UTC: checked against local times written down by hand for a few
  recordings. A time with a zone is taken as given.
- Signed links and storage paths (`presigned_url`, `data_link`, `data_path`) are dropped from `native` at any depth:
  they carry a session token or the account's internals, never content.
- A file id is letters, digits, `_` and `-`; anything else is refused before a rid is built from it.
- A tab counts when its content isn't empty; its title is `data_title`, else `data_tab_name`, else `Summary`. That is
  the rule the backfill script used, so a backfill file and a later capture of one recording hash alike.

### Versions

Plaud's projection hashes what a recording says, never how Plaud delivered it.

| Kind | Hashed | Never hashed |
|---|---|---|
| recording | kind, ts in whole seconds, title, duration | `created_at`, `serial_number` (null in the listing, set in `get_file`), the block and note inventories |
| transcript | kind, ts, the segments as `[start_ms, end_ms, speaker, content]`, sorted, exact duplicates once | `original_speaker`, `segment_uid`, page order and boundaries, the rendered `text` |
| vendor-summary | kind, ts, the tabs as `[type, title, content]`, sorted, empty ones left out | ids, error codes, tab order |

- Plaud adding a summary later is a new record, never a new version of the transcript. A link, a serial number filled
  in or a moved page boundary changes nothing.
- A new title, a renamed speaker or an edited tab is a new version, and the gate asks again: it is new content.
- `text` is Docket's rendering, so it stays out: rendering it differently later must not version every transcript.
- When a char cut has cleared `native` (`cut_text`), the projection hashes kind, ts and text instead.
- Golden tests pin one hash per kind. Like DR-0020, changing this needs a migration of every vault.

### Assembling a recording

`assemble(meta, transcript_pages, tabs, final)` gives the records one recording is ready for. Meta is required:
without `start_at` no record has a `ts`.

| Has | Gives |
|---|---|
| a transcript with segments, its page chain complete | the transcript |
| an empty transcript (both blocks empty, a list result, or a backfill `block` null) | nothing: the recording waits for its transcript; when final, it is stored without one |
| tabs | the summary, and the recording under the name in that meta |
| `final`, no tabs | the recording alone, under the name at that point |
| meta only, not final | nothing yet |

- The recording waits for the summary because Plaud renames a recording when it writes its summary. Staged with the
  summary, it is stored once, under the final name; staged earlier, every recording would get a second version.
- A transcript is complete when its pages chain from the first (no `cursor` argument) through each `next_cursor` to a
  page without one. A broken chain is set aside, never staged: a partial transcript would be a version in raw for good.
- An empty transcript is never staged: an empty `transaction` record would stay in raw, and the real transcript would
  arrive later under a second rid.
- With several captures of one recording's meta, the newest wins, so a listing captured after the run's notes gives
  the renamed recording.

### The hold list

Recordings Docket must not stage yet (the backfill's recordings with stretches the user left out) are held by id in
the vault, and the Plaud profile enforces it on every route.

- The list is `state/holds/plaud.txt`, committed: opaque file ids only, one a line. It sits in `state/`, so the
  vault's layout (DR-0019) doesn't change, and it reaches every machine with git.
- Read as UTF-8 with or without a BOM, each line stripped, blank lines skipped, in any order and with duplicates. A
  line that isn't a file id refuses every Plaud ingest, naming the file and the line: the list fails closed.
- Two machines can add at once: `state/holds/*.txt merge=union` in the vault folder's own `.gitattributes` keeps both
  sides' lines, and the next add sorts the list and drops duplicates. `holds.py` adds that line in the commit that
  first creates a list, and the init template carries it. The vault folder's file is one of the vault's own paths, so
  a vault in a folder of the user's repo (DR-0102) commits nothing outside it.
- `plaud.ingest()` reads it before anything else. A held id gets no record of any kind (recording, transcript, notes or
  meta) and never appears among the waiting ids it reports; it is only counted ("held 3"), with no id and no title.
- Docket only adds to it: an import's `hold.txt` and `--hold` file, committed as `Holds: plaud, <n> added on
  <machine>`, an id-free message, before anything is staged. #31 releases ids once their cuts are confirmed.
- Any held id with a record waiting in staging stops every Plaud ingest before anything is staged, naming the id and
  the path of each staged file (`staging/plaud/<key>.json`, from `Gate.list(source="plaud")`). The check runs on
  every run, not only the one that added the hold, so a second run, or a second clone that staged the recording
  before the hold reached it, stops too until the files are deleted. They are deleted by hand: a private
  classification would leave a decision #31 would have to undo. A held id already in raw is named on every run; it
  waits for `docket forget` (phase 2).

### Segments and cuts

- The segment reader maps a transcript's `start_time`, `end_time`, `speaker` and `content` to `Segment`: sorted,
  overlaps kept, exact duplicates once. A recording or a summary has none. A malformed segment is a `DocketError`
  naming the rid.
- The cutter, by kind and unit:

| Record | `ms` cuts | `char` cuts |
|---|---|---|
| transcript | each utterance overlapping a cut goes whole (an utterance has no word times); one `[cut]` segment spans the cut widened to what it removed; `text` is rendered again, `[cut]` in it | refused: cut a transcript by time, so its time anchors keep working |
| vendor-summary | refused: a summary has no times | `cut_text`, which clears `native` |
| recording | refused: cut its transcript, or classify it private | refused |

### The import

`plaud.ingest(vault, captures, folder, final)` is the one way in: the CLI calls it with a folder, and #8's `ingest`
tool calls it when a run closes, with the run's captures and, for a backfill run, the backfill folder. In order: the
folder's holds are added, the hold list is read, a held id waiting in staging stops the run, held ids are set aside,
the rest is assembled and staged through `Gate(vault).stage()`, ten recordings a batch.

`docket ingest plaud <folder> [--hold <file>] [--final]` reads:

| File | Read as |
|---|---|
| `hold.txt` | ids to add to the hold list, read the hold list's way; a bad line stops the run before anything is written |
| a backfill file: `file_id`, `block`, `segments`, `summary` as `[{title, type, content}]` | a complete transcript (empty when `block` is null) and its tabs; always `final`, since a backfill is old recordings |
| a capture: `tool`, `arguments`, `result`, `captured` | `list_files` and `get_file` give meta, `get_transcript` a page, `get_note` tabs |
| anything else | named and skipped |

- A result is read from `structuredContent` when there is one, else from the first JSON value in its text; a
  preamble or trailing note around it is ignored.
- A capture's file id is read before validation, from `arguments.file_id`, from each listing item's `id`, or from a
  backfill file's top-level `file_id`, and checked against the hold list first, so a held payload is never parsed. A
  reason names the tool, the id and the key, never the validator's message, which quotes the input and can carry a
  title. An id that isn't a valid file id is reported as invalid, not echoed.
- The backfill has no start times. They come from a listing assembled with it: the backfill run's captures (Handed to
  #8 and #12), or capture files in the folder. A file without meta is set aside and named by id, never staged.
- A held id with no file in the folder is named by id, so a typo in `hold.txt` shows.
- `--final` marks captured recordings as final, for a give-up done by hand.
- The output is counts and the ids set aside with their reasons, never a title, so a never-store recording's name
  stays out of terminals and logs.
- Running it twice stages nothing new: the gate skips what it holds or raw has.
- Not taken: `docket plaud import <folder>`. Every source would grow a command group; one `ingest` command matches the
  MCP tool and dispatches to the profile.

### Note names

Plaud's note-names function gives #11 the forms a note uses for a recording: its file id, and the id without `of_`,
for all three records, so a note naming a recording covers its transcript and summary too.

## Handed to #8 and #12

The fetch is the Plaud skill (#12) with the user's Plaud MCP; the payloads reach the service's `ingest` (#8) through
the plugin's capture hook, never through Claude's output. They need:

| Need | For | What |
|---|---|---|
| the listing | #12 | `list_files` without date filters (they can't be trusted to be exact, review P1), newest first, until a page's oldest `start_at` is before the window's start |
| the window | #8 | per source and machine: the high-water mark less 7 days of lookback; a first run needs a start date |
| a run that stops early | #8 | the window's start is kept until a run finishes (review P2): the listing is newest first, so moving the mark on partial progress would skip the older part for good |
| the cursor | #8 | `state/cursors-<machine>.yaml`, committed: the mark per source, and an open run's window start; read as the furthest mark of any machine; the mark moves only when a run finishes |
| the hold list | #12 | read the held ids through the service and don't fetch them; that only saves calls, since the profile is the control |
| waiting | #8, #12 | only the ids `plaud.ingest()` reports as waiting for a transcript or a summary, local in `.git/docket/` and never committed; a held id never is one; after 7 days the skill asks for the recording as `final` |
| what is kept | #8 | a read of which rids raw or staging holds and which ids are held, so the skill fetches only what is missing |
| the order | #12 | per recording: every page of `get_transcript` for `transaction_polish` (`limit` 500, following `next_cursor`), else for `transaction`; then `get_note`; then the listing captured again after the run's last `get_note`, so the name is the one Plaud gave with its summary |
| the backfill's listing | #12, #8 | once, a backfill run: `list_files` paged down past the oldest backfill recording, with no transcript or note calls, its manifest naming the backfill folder; at its close #8 calls `plaud.ingest()` with the run's captures and the folder, so the files get their `start_at` from that listing; held ids are dropped, the rest dedupe against anything already imported; it doesn't move the mark, and the first live run's start date stays recent |
| a run's captures | #8 | they wait in the service's memory until the run's manifest closes it, then go through `plaud.ingest()` together; nothing verbatim is written to disk or logged; the hook passes only `list_files`, `get_file`, `get_transcript` and `get_note` |
| closing a run | #8 | the manifest counts the run's captures, and a run closes only when the service holds every one; a manifest for a run the service doesn't hold (after a restart) or one short of captures drops the run like one that never closed: nothing is staged and the mark stays |
| assembling | #8 | a run's captures are assembled when its manifest closes it, never on each hook post, so the listing after the notes is there |
| rate limits | #12 | Plaud's error text says `429 Too Many Requests`: pause and retry with growing pauses; still limited, end the run, and the kept window resumes it |
| the capture | #12, #8 | each Plaud result verbatim, with the tool's name without the host's prefix, its arguments and the time; Claude never retypes a payload |
| sign-in | #12 | "not authenticated" means the server's `login` tool, run from the skill |
| setup | #12 | Plaud is one of the choices the plugin offers at setup, and adds the source as `mixed` |
| releasing a hold | #31 | removing an id from `state/holds/plaud.txt`: with `merge=union`, a release merged against another machine's concurrent add can bring the id back; that fails safe (the recording stays held), so the release is checked after the next sync |

## Decided

Taken under the autonomy grant; each one's alternative is the option not taken.

| Decided | Not taken |
|---|---|
| three records per recording | one record: a summary arriving later would version the recording |
| the transcript's rid names Plaud's block | `/transcript`: a fallback to the raw block, then the polished one, would be one record changing engine |
| the polished block, else the raw one | both every time: twice the calls that hit 429, and the backfill has only the polished one |
| `thread` and `container` `plaud:<file id>` on all three, the recording's own included | on the transcript and summary only: the index (#7) would show the recording as a hit of its own |
| zone-less times are UTC | local time: the checked recordings disagree |
| the recording's `native` is its six meta keys | `get_file` as given: the whole transcript again, and signed links |
| signed links and storage paths dropped | left to redaction: no rule catches them, and they would reach staging |
| title in the recording's hash | out: a renamed recording would keep its first name in raw for good |
| the recording staged with its summary, or when final | as soon as listed: every recording gets a second version when Plaud renames it |
| `speaker` in the transcript's hash | `original_speaker`: names given in Plaud's app would never be stored |
| `text` out of the transcript's hash | in: a new rendering would version every transcript |
| tabs normalized as the backfill script did | as given: every imported summary would come back as a second version on its next capture |
| segments and tabs sorted, exact duplicates once | received order: a page boundary or a tab reorder makes a new version |
| a transcript staged only with its whole page chain | whatever pages arrived: a partial transcript stays in raw for good |
| an empty transcript staged as nothing | an empty record: it stays in raw, and the real one arrives under a second rid |
| meta required for every record | a guessed `ts`: the real one later makes a second version of each |
| the newest meta capture wins | the first: the name before Plaud's rename |
| the hold list in the vault, enforced by the profile | `hold.txt` read only by the import: a live run, a listing or a second run without the flag stages held recordings whole; a cursor floor: live runs could never fetch the backfill's missing recordings |
| the hold list at `state/holds/plaud.txt` | a new top-level `holds/`: changes the vault's layout (DR-0019) |
| a bad line in a hold list stops the run | skip it: the id meant to be held is staged |
| any held id waiting in staging stops every Plaud ingest, naming each staged file | only the run that adds the hold: the next run goes on, and one "work" classification sends the left-out stretches to git |
| hold lists merged by union, sorted and deduplicated on the next add | plain text merges: two machines adding at once conflict |
| a capture's file id read before validation and checked against the holds first | validate first: a held payload is parsed, and a validator's message quotes its title |
| `ms` cuts drop whole utterances, the marker widened | trim an utterance: its words have no times |
| `char` cuts on a transcript refused | `cut_text`: it clears the segments, and every time anchor with them |
| outline and highlights left out | captured now: two more calls per recording, for a phase 1 feature |
| profiles registered when `docket.vault` is imported | from `Vault.__init__`: a `version()` call before any vault is opened hashes with the default projection |
| a profile in the core, no package or entry point | a connector package: nothing here runs headless |
| one `docket ingest <source> <folder>` | `docket plaud import`: a command group per source |
| one `plaud.ingest()` for the CLI and #8 | a path each: the hold and the assembly could drift apart |
| backfill files are always final | waiting for summaries Plaud will never write for old recordings |
| `fetched` is the capture time or the file's modification time | now: says the transcript was fetched today |
| counts and ids printed, never titles; held recordings only counted | titles: a never-store recording's name in a terminal or a log |

## Steps

Steps 1 to 3 build on `main` now; the rest start after #5 and #6 merge, on the branch rebased.

1. `docket/sources/__init__.py`, `sources/plaud.py` without cuts or segments, and the call in `docket/vault/__init__.py`,
   with `test_plaud_records.py`: rids; a zone-less time read as UTC; the recording's rid as `thread` and `container`
   on all three; links and paths gone at any depth; a bad file id refused; results read from `structuredContent`, from
   text with a preamble and a trailing note, and refused when there is no JSON; golden hashes per kind; the same hash
   for listing and `get_file` meta, a filled serial number, shuffled or duplicated pages, and a backfill summary
   against a `get_note` one; a new hash for a new title, speaker or tab; the text fallback; a fresh process that
   imports `docket.vault.records` alone versions a Plaud record with Plaud's projection.
2. `assemble()`, with `test_plaud_assemble.py`: each row of its table; a recording listed under a first name, then
   listed again with its summary under a new one, stores one recording version under the new name; a final recording
   without tabs stored under the name it has then; a broken page chain set aside; a meta capture before the tabs and
   another after store the recording once, under the later name; an untranscribed capture (both blocks empty, and a
   list result) stages nothing, and the polished transcript captured later stages exactly one transcript record; a
   final recording with an empty transcript stored without one.
3. `docket/sources/holds.py`, with `test_holds.py` on a temp vault: a BOM, CRLF line endings, a trailing space, blank
   lines, any order and duplicates read; a line that isn't a file id refused with the file and line; ids added, sorted
   and deduplicated, committed with a message that holds none; the `merge=union` line written in the commit that first
   creates a list, and present in a new vault; two clones each add an id, both sync, no conflict, and both read both
   ids.
4. The segment reader, with `test_plaud_segments.py`: keys mapped, sorted, overlaps kept, duplicates once, none for a
   recording or summary, a malformed segment names the rid.
5. The cutter, with `test_plaud_cuts.py`: utterances dropped whole, the widened marker, merged cuts, `[cut]` in
   `text`, no cut word left in `native`; each refusal in the table; a summary cut by characters.
6. `plaud.ingest()` and `docket ingest`, with `test_ingest.py` on a temp vault through #5's gate:
   - backfill files with a captured listing stage three records each, all `pending` (the source is `mixed`); a file
     without meta set aside and named; a malformed file skipped while the rest go on; a second run stages nothing; a
     backfill file and captures of the same recording give no second version; a backfill file with `block` null stages
     no transcript; an unknown source refused; the output holds no title;
   - a held id arriving through a live run's captures, through a backfill run's listing with the folder, and through a
     second import without `--hold` is never staged and never reported waiting; the output says "held" with a count
     and no held id;
   - `hold.txt` with a BOM, CRLF and a trailing space read; a bad line stops the run with nothing staged and the
     vault's list unchanged; `--hold <file>` added from elsewhere; a held id with no file in the folder named by id;
   - a held id with a record waiting in staging stops the run, stages nothing and names the path of each staged file;
     a second run stops too while the files remain, and goes on once they are deleted; so does a run on a second clone
     that staged the recording before a sync brought the hold;
   - a malformed capture of a held id is counted as held and never named or parsed; a malformed listing item's reason
     names the tool, the id and the key and holds no title.
7. Plaud's note names, with a test in #11's suite, after both merge.
8. The hand-over: the Handed to #8 and #12 table posted as a comment on #8 and on #12, each with its own rows.
9. The docs below, including the design's Sources section (main has it since PR #30), then `finish-work`: `uv run
   gate full`, a draft PR, `review-code` until it is clean.

## Risks

Most are accepted for phase 0; none of them loses or duplicates a stored record.

| Risk | Status |
