# Add docket eval, its question file format and an invented question set

## Goal

Search gets a fixed measure: questions with the locators a good answer cites, scored as recall at 10 and MRR per kind
of question, so a change that helps paraphrases and hurts names shows. Embeddings and the reranker (#67), curate rounds
and ranking rules are judged on it (the design's Search section).

| Part | Done when |
|---|---|
| Format | a YAML question file, schema 1: each question's words, the locators a good answer cites, its kind and language |
| Invented set | 72 questions over an invented two-language vault, in the repo, run by the gate against a floor per kind |
| Private set | `docket eval <file>` runs a user's own set against their vault and prints the same numbers; the file is only read |
| Report | a row per kind and per language, the questions missed, or JSON |

- In scope: `docket/questions.py` (the format, the match rule, the scores), `docket eval`, the invented vault and its
  questions, the floors and the gate's check of them, the docs.
- Out of scope: models (#67); search's filters (`people`, `entities`, `sources`) in a question, which a later schema
  can add; an MCP tool or a web page for eval; the index fixture's nine questions, which stay a search test of their
  own; the maintainer's own set, which never enters the repo.

## Design

Eval calls `index.search`, and reads the index itself only to list a thread window's messages and to check that each
wanted locator names something. Nothing in `index/query.py` changes, so #59 (compounds, there now) is left alone.

| Module | Change |
|---|---|
| `docket/questions.py` (new) | load and check a question file; what answers a wanted locator; run a set through search and score it |
| `render.py` | `eval_report`: the table and the misses |
| `cli.py` | `docket eval FILE [-k N] [--json] [--vault PATH]` |
| `tests/eval_vault.py`, `tests/fixtures/eval-vault/` (new) | the invented vault and its questions |
| `tools/devkit/eval-floors.json`, `devkit/evalfloors.py` (new); `devkit/gate.py` | the floors and the full lane's check |

### The question file

```yaml
schema_version: 1
asked: "2026-10-14T10:00:00+02:00"
questions:
  - q: money up front for the translator
    want: ["r:mail:<advance-1@example.invalid>#2"]
    kind: paraphrase
    lang: en
    note: the mail says advance, never money
  - q: múlt héten papír ára
    want: ["thread:chat:C0PROD/1791500000.000100", "minutes:2026-10-08-production#L7"]
    kind: time-bound
    lang: hu
```

| Field | Required | What |
|---|---|---|
| `schema_version` | yes | 1, as in `vault.yaml` |
| `asked` | on the file; a question may carry its own | a date, or a time with its offset: search's now, so time words read the same on every run |
| `q` | yes | the words search gets, as typed |
| `want` | yes, one or more | the locators a good answer cites |
| `kind` | yes | `exact-name`, `paraphrase`, `inflection`, `typo` or `time-bound` |
| `lang` | yes | the question's language code, such as `en` or `hu` |
| `note` | no | for whoever keeps the set |

- Read with YAML's base loader, so every value is text. An unknown key, a missing field, another schema or a locator
  that doesn't parse is refused, naming the question's number: a mistyped `want` would otherwise score its question
  zero, unseen.
- Users keep their own files, so the format is a one-way door (DR-0290): a later schema reads every earlier one.
- A locator is copied from `docket search`'s output or from an answer's citations.

### What answers a wanted locator

A hit's locators are its own and those collapsed under it (`also`), all at its rank. Rids compare exactly, so
`rec-0100` never answers for `rec-0100-second`.

| Wanted | Written | A hit answers it when it is |
|---|---|---|
| a record | `r:<rid>` | on that record: the whole, a window, a part |
| a moment or a stretch | `r:<rid>@12:08`, `r:<rid>@12:08-12:40` | that record whole, or a window of it overlapping the stretch, ends included |
| paragraphs | `r:<rid>#2`, `r:<rid>#2-4` | that record whole, or a part of it overlapping them |
| a doc | `<type>:<slug>` | a section of it |
| a doc's lines | `<type>:<slug>#L7`, `#L7-9` | a section of it whose lines overlap them |
| a thread or a recording | `thread:<rid>` | in that group: a message, a thread window, a transcript, a doc covering only it |

A hit also answers what it holds or cites (DR-0291):

- A thread window answers each message it holds; eval reads its members from the index's `chunks.rids`, since a hit
  carries only its first message's locator.
- A doc's section answers each raw stretch its lines' anchors point into: `verify` takes the reader from that line to
  the raw, so minutes that outrank their raw still count.
- Overlap, not containment: windows share one utterance, so a cited stretch that crosses a window's end lies inside no
  window.

### The scores

| Number | Per question | Per kind, language, all |
|---|---|---|
| recall at k | the share of its wanted locators a hit in the top k answers | the mean over the questions |
| MRR | one over the rank of the first hit answering any of them; 0 when none does | the mean |

- k is 10 by default, 1 to 100 as search takes; each question weighs the same (DR-0292).
- A question whose search is refused (nothing to search for) scores 0 and is listed with the reason. A wanted locator
  naming no record, doc or thread in the index counts as missed and is listed, so a stale question shows.

### docket eval

`docket eval questions.yaml` reads the file wherever it is, opens the vault's index read-only and runs each question
through search with its `asked` as now. It writes nothing: unlike `docket search` it doesn't bring the index up to
date, so two runs compare the same index; when the index is behind the vault it says so first, naming `docket index
update` (DR-0293).

```text
eval      questions.yaml: 72 questions, k 10
kind            n   recall@10    MRR
exact-name     14        0.xx   0.xx
paraphrase     18        0.xx   0.xx
...
en             31        0.xx   0.xx
hu             41        0.xx   0.xx
all            72        0.xx   0.xx

missed at 10
  paraphrase  en  money up front for the translator  r:mail:<advance-1@example.invalid>#2
```

- `-k N` scores at another k; `--json` prints the same numbers and each question's rank per wanted locator, for a
  before-and-after diff (#67).
- `--vault` and how the vault is found are `docket search`'s.

### The invented vault

An invented small publisher of English and Hungarian translations: about 400 chunks, from fixture files a reader can
check each question against, plus seeded filler (DR-0294).

| Part | What |
|---|---|
| calls | 6 recordings of 10 to 15 minutes: 3 in English, 2 in Hungarian, 1 switching between them; one with a second transcript that mishears names |
| mail | about 30, some long enough to split into parts, replies under `RE:` |
| chat | about 45 messages in two channels, 4 threads |
| cal | about 12 events |
| docs | about 10: minutes and recording notes of four calls, a thread summary, a weekly digest, three legacy notes, saying the same facts in other words |
| entities | the test kit's invented cast (Ada Example, Ben Sample, Cleo Test, Dóra Minta, Rita Sample), a printer, a distributor, two books; Hungarian names and one ASR alias |
| filler, in code | about 150 short routine messages and mails in both languages, seeded, sharing the questions' words and holding none of their answers |

- Records run from 1 September to 14 October 2026; the file's `asked` is Wednesday 14 October 2026, 10:00 in
  Budapest, so last week is 5 to 11 October.
- `tests/eval_vault.py`: `build_eval_vault(root)` writes each source's run, the entities and the docs (one
  `put_many`), built once per session through `template_with`. A file of its own, since #59 changes
  `docket_testkit.py`.

| Kind | en | hu | What makes one | Invented example |
|---|---|---|---|---|
| exact-name | 7 | 7 | the name as the text writes it: a person, a firm, a book | `Rita Sample contract` |
| paraphrase | 10 | 8 | none of the answer's words; 4 asked in the other language than the answer's | `money up front for the translator`, where the mail says advance |
| inflection | 0 | 14 | the question's form of a word differs from the text's: suffixes, stem changes (`terem`, `termet`), 2 joined compounds | `nyomdától`, where the call says `nyomdával` |
| typo | 6 | 6 | a word an edit or two off: 8 in the question, 4 in a transcript that misheard | `transaltor contract` |
| time-bound | 8 | 6 | the answer depends on a time word: last week, múlt héten, yesterday, a month; 2 the time table doesn't know | `last week paper price` |
| all | 31 | 41 | | |

### Today's numbers and the floors

Keyword search alone, expected; step 3 measures it. For scale: the index fixture's nine questions, each written to
pass, score recall at 10 of 1.00 and MRR of 0.74 on main today.

| Kind | recall@10 | MRR | Why |
|---|---|---|---|
| exact-name | 0.85 to 1.00 | 0.60 to 0.90 | the words are in the text |
| paraphrase | 0.05 to 0.25 | 0.02 to 0.15 | no shared word: what #67 must raise |
| inflection | 0.45 to 0.75 | 0.35 to 0.60 | Snowball meets suffixes, misses a dropped vowel and a compound's parts |
| typo | 0.25 to 0.50 | 0.15 to 0.40 | no fuzzy match on plain words; the other words and the ASR aliases find some |
| time-bound | 0.65 to 0.90 | 0.45 to 0.75 | the filter narrows well; two time words aren't in the table |

The floors are what main measures, per kind, rounded down to two decimals, never higher (DR-0295):

```json
{
  "$comment": "Recall at 10 and MRR per kind on the invented question set; see DR-0295.",
  "exact-name": {"recall": 0.92, "mrr": 0.78},
  "paraphrase": {"recall": 0.11, "mrr": 0.06, "lowered": "#nn: what was traded for what"}
}
```

| Case | What happens |
|---|---|
| a kind below its floor | `test_eval_set` fails, on every system |
| a kind above its floor | the full lane fails, printing the floor to write: the change that earns a gain raises it in its own diff, so no later change gives it back unseen |
| a floor below the base branch's | the full lane fails unless that kind's entry has a `lowered` note the base didn't: the issue, and what was traded |
| every run | the tests step prints each kind's numbers, as it prints coverage |

- The floors live in `tools/devkit/` beside `coverage-floors.json`: the harness, where `REVIEW.md` asks the reason for
  any loosened check.
- In the full lane the test writes its numbers to the file `DOCKET_EVAL_REPORT` names, as `--cov-report` writes
  `coverage.json`; the gate reads the base's floors with `git show <base>:tools/devkit/eval-floors.json`.
- A kind with no floor, or a floor with no kind, fails, as in coverage.

### Time in the gate

Measured on the maintainer's desktop with today's fixtures: the name vault (190 chunks) builds in 2.7 s and rebuilds
its index in 0.06 s; the index fixture (48 chunks, a commit per doc) in 3.9 s and 0.08 s; a search takes 3 to 7 ms.
So the eval vault should cost about 4 s once per session on one worker, its rebuild 0.2 s and its 72 questions under a
second. The CLI tests copy the template.

### Decided

Taken under the autonomy grant, each proposed for the maintainer's review.

| Decided | Not taken | Entry |
|---|---|---|
| a YAML file, schema 1, read with the base loader, unknown keys refused | JSON: hand-written files want comments; unknown keys ignored: a mistyped `want` scores zero unseen | DR-0290 |
| `r:` for records, `#L` for a doc's lines, `thread:` for a group | bare rids, as `read` takes them: a record, a doc and a thread would read alike | DR-0290 |
| five fixed kinds | any kind name: a typo makes a row of its own | DR-0290 |
| `asked` required on the file | the run's time: last week moves every week | DR-0290 |
| overlap, and a window or a doc's line that holds or cites the wanted | containment: a stretch crossing a window's end matches nothing; the record's own hits only: minutes that outrank their raw would miss | DR-0291 |
| recall as the share of wanted locators, MRR from the first answering hit, means over questions | found when any is: a two-fact answer finding one fact scores whole; means over locators: a question with five weighs five times | DR-0292 |
| eval reads the index as it is and says when it is behind | updating it first, as `docket search` does: a measure that changes what it measures | DR-0293 |
| fixture files plus seeded filler, built from a file of its own | all in code: nobody can check a question against its answer; the perf vault: its seeded syllables mean nothing; growing the index fixture or the name vault: other tests count their chunks | DR-0294 |
| a floor per kind at today's number; the full lane fails above as well as below; a lowered floor needs a new `lowered` note | one floor for the set: a trade between kinds passes; a margin under today: hides a lost question; printing a gain without failing, as coverage does: a later change can give it back | DR-0295 |

## Doors and data

One new one-way door: the question file's format (DR-0290), since users keep their own files. `AGENTS.md`'s list of
doors gains it, and the PR's title names it. Nothing else: eval writes nothing in the vault or its index, the MCP tools
and the index's schema don't change, and no vault moves over.

`conftest.py` sets them; invented names only.

| Test | Asserts |
|---|---|
| `test_questions.py`: the format | a minimal file loads; every value is read as text; refused, naming the question: an unknown key on the file or a question, schema 2 or none, no `asked`, no questions, an empty `want`, a locator that doesn't parse, an unknown kind, a bad language code |
| `test_questions.py`: the match | a table: a record's window, part and whole; a moment at a window's end; stretches that touch, overlap and miss; paragraphs; a doc and its lines; a thread by its group; a thread window holding a reply; a doc's section citing a stretch; `rec-0100` against `rec-0100-second`; an encoded `]` in a rid; a time against paragraphs |

## Risks

| Risk | Status |
|---|---|
| The numbers differ between systems (a SQLite build, hash order), so the full lane fails above a floor on one | open: step 3 compares two hash seeds and the desktop with CI's Linux; if they differ, the above-floor check runs on CI's Linux only |
| #59 lands before or after this and moves the numbers | accepted: whichever merges second measures again and moves the floors in its diff |
| Every change that moves a ranking touches the floors file | accepted: that is the point, one line per kind |
| A paraphrase shares a word with its answer by accident | accepted: `--json` gives each question's rank, and the set's review looks again at a paraphrase found at rank 1 |
| The invented set is easier or harder than real questions | accepted: the maintainer's own set, run with `docket eval`, is the real measure; the invented one guards each kind |
| The vault's build adds seconds to the gate | accepted: about 4 s once per session, on one worker |
| #67 runs a model in CI and the numbers jump | accepted: #67 decides what CI runs and moves the floors in its diff |
| A wanted doc is superseded later in a user's vault | accepted: it scores as missed, and the misses name it |
