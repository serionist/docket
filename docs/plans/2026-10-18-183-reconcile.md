# Reconcile the recorder's and Whisper's transcripts in context

## Goal

Where the recorder's transcript and Whisper's disagree on a name, a number or a word, Claude decides with the meeting's
context, and the recording gets a corrected reading that notes, briefs, decisions and search can rely on. Both raw
transcripts stay as they are (the design's Speech section, step 5; DR-0104).

| The issue's part | This plan | PR |
|---|---|---|
| Spots | the core aligns the two by time, per recorder line, and lists names, numbers and words that differ; none in a `[cut]`; at most 40 a recording, names and numbers first (DR-0583) | 1 |
| Confidence | not stored: the segment format stays as DR-0111 has it (DR-0583) | 1 |
| Tool | a new read-only MCP tool, `spots(rid=None)` (DR-0584) | 2 |
| Skill | the plugin's `reconcile` skill decides each spot and puts the fixes (DR-0584) | 2 |
| Store | one `transcript-fixes` doc per recording, through doc_put, each line anchored to both transcripts (DR-0582) | 2 |
| Unsure | waits for the owner's click on the Recording page; not applied until then; no tool or edit of Claude's sets it (DR-0586) | 3 |
| Reconciled | the core renders the recorder's transcript with the applied fixes, from raw, the fixes doc and the screen in force; chunked beside the other two (DR-0585) | 2, 3 |
| Recording page | each fixed word marked, with its fix and evidence; the unsure ones listed with their clicks | 3 |
| Tests | invented transcripts of one call disagreeing on a name and a number, a cut stretch, a never-store fix, two rebuilds | 1 to 3 |

- In scope: the spots, the fixes doc, the reading, `read` and `verify` showing it, search collapsing it, the `spots`
  tool, the `reconcile` skill, the Recording page's marks and clicks.
- Out of scope: learning from the fixes (an `asr` alias from confirmed fixes, a vocabulary, a fine-tune: the next
  issue); diarization; a stretch only one engine heard (it stays in that engine's transcript, searchable); typed
  extractors for amounts and dates.

## Design

### What a reconciled reading is

| Part | What it is | Who writes it |
|---|---|---|
| raw | the recorder's transcript and `<rid>/whisper`, as stored (#158) | the source and `docket transcribe`, once |
| spots | where the two disagree, worked out when asked, never stored | the core |
| fixes | one doc per recording: a line per decided spot, with its evidence | Claude through doc_put; the owner's click for an unsure one |
| the reading | the recorder's transcript with the applied fixes, at raw's times | the core, in the index and in reads, never in the vault |

A wrong fix is undone by the doc's next rev; raw never changes, so every anchor keeps pointing at the same times.

### Texts and places

Every rule below reads a fix's place the same way:

- **A word** is a match of `plaintext.WORD` in a segment's raw text, with its place there; words are compared after NFC
  and casefold, accents kept, as `docket eval speech` scores (DR-0571). `plaintext.words` isn't used for places: it
  lowercases.
- **A text** is raw's own substring from its first word's first character to its last word's last character: case,
  inner punctuation and spacing as written.
- **Stands once** means it occurs exactly once in its segment's raw text at word boundaries: the characters either
  side, where there are any, aren't letters or digits.
- **A place** is the recorder segment and the span its text stands at. Two places overlap when their spans in one
  segment share a character.
- **Cuts** are every `[cut]` span of either transcript's latest version in raw, merged. A segment is in a cut when it
  overlaps one by its own times, as `cuts.py` takes a segment; rounded anchors and estimated word times never decide.

### Spots (DR-0583)

Worked out on each call, from the latest versions in raw of the recording's two transcripts (a staged one isn't read,
as the Recording page reads raw only). The recorder's transcript is the one the recording's summary covers, else the
first under it by rid, as the page's pair picks it.

| Step | What |
|---|---|
| 1. machine | the recording's source is one this machine ingests (its cursor file names it), as `docket transcribe` asks (#158): withheld marks and private decisions are each clone's own. Elsewhere `why` says to reconcile where the source runs |
| 2. screen | the family screen media's reader asks (`media.screen.refusal`) must pass, a source only off aside: a family withheld, privately decided, or with a version a never-store list matches gets no spots, and `why` says so without a value |
| 3. cuts | a recorder line in a cut, and a Whisper segment in a cut, are skipped whole |
| 4. words | filler sounds of the transcript's language (`um`, `uh`, `öö`) left out of the comparison |
| 5. align | each Whisper word timed by its share of its segment's characters, and given to the recorder line its time falls in, or the nearer one across a gap of at most a second; each line's words aligned to the words it was given with difflib's `SequenceMatcher`, autojunk off |
| 6. edges | every replace, insert and delete is a candidate. An insert or delete at either end of a line is dropped only when its words stand at the touching edge of the neighbouring line: an insert's words are that line's first (or last) words, a delete's words are the first (or last) Whisper words given to it. So "... is ten" against "... ten million" stays a spot. A line given no Whisper words makes none |
| 7. widen | a candidate's texts widen by the agreeing word on each side, where there is one, both transcripts alike, until neither text is empty and the recorder's stands once in its line; an insert or delete starts empty on one side, so it always widens. Past six words on either side it is counted as heard differently, not listed. Candidates whose places would overlap are one spot |
| 8. kinds | **name**: a word of either text within matching's edit distance (`max_distance`) of a word of a meeting entity's name or alias, or of a glossary term, or capitalised mid-sentence; also a capitalised word both engines spell alike that is within that distance of a meeting name and none of its forms, or is one of its `asr` aliases. **number**: either text holds a digit or a word that splits wholly into the language's number words (`tíz` + `millió`), `egy` and `one` alone left out; `reconcile/numbers.py` gives each side's value, and equal values make no spot, so "forty two" against "42" isn't one. **word**: the rest |
| 9. rank and cap | names, then numbers, then words, by time within each; 40 a recording, the rest counted by kind. A place whose every fix line is rejected comes back, with the picks the owner turned down, after the undecided spots of its kind |
| 10. left out | a spot whose texts or line name a person a never-store list holds, in the shapes the brief screen reads (DR-0558), or that touches a redaction marker: counted, never named |

- The meeting's entities are the ones the Whisper prompt already picks (DR-0569): the family's people resolved to
  entities, their related projects, the entities its records name. Glossary terms join them. An entity a list holds by
  any name, alias, contact id or its id is left out whole, as `speech/prompt.py`'s `_listed` leaves it out; that choice
  moves to a shared `meeting.py` both call.
- A spot's id is the first 8 hex digits of the sha256 of the recorder rid, its line's start and the two texts:
  stable while the transcripts are.
- A spot a fix line already decides is shown with that line, not listed again.

**Confidence.** The worker sends each segment's average log probability (#158), and the record drops it. It stays
out: `Segment` forbids other fields (DR-0111), so an older Docket would refuse every new Whisper record until each
machine updates, and an average over a segment of several seconds marks a sentence, not a word. The two engines'
disagreement already finds the word. The maintainer's three recordings show whether a stretch both engines agree on
hides errors; a later issue adds word-level confidence if they do.

### The fixes doc (DR-0582)

```markdown
---
id: transcript-fixes:2026-10-15-3f2a1c9b0d4e
type: transcript-fixes
covers:
  - calls:rec-0101/transcript
  - calls:rec-0101/whisper
  - mail:<offer-1@northwind.example>
by: claude-opus-5.5, reconcile 2026-10-18
entities: [northwind, ben-sample]
---

# Transcript fixes: Supplier call

- "Nortwin" / "Northwood" -> "Northwind", sure: Northwind is the customer on the invite, and its offer mail came the day before. [r:calls:rec-0101/transcript@12:05-12:12] [r:calls:rec-0101/whisper@12:06-12:11] [r:mail:<offer-1@northwind.example>]
- "ten thousand" / "ten million" -> "ten million", unsure: the offer mail speaks of millions, but this sum isn't in it. [r:calls:rec-0101/transcript@14:20-14:31] [r:calls:rec-0101/whisper@14:21-14:30]
- "Monday" / "Sunday" -> "Monday", sure: the invite and the mail both say Monday; the recorder heard it right. [r:calls:rec-0101/transcript@20:02-20:09] [r:calls:rec-0101/whisper@20:02-20:08]
```

- **Id:** `transcript-fixes:<yyyy-mm-dd>-<12 hex>`, the recording's date in the owner's time zone and the first 12 hex
  digits of the sha256 of its rid. `spots` gives it, so Claude never works it out. No name goes in a slug, so a later
  never-store value never sits in a path.
- **Covers:** the recorder's transcript it reconciles, `<recording rid>/whisper`, and the records its evidence anchors.
  No frontmatter key beyond every doc's.
- **A line:** `- "<recorder's text>" / "<Whisper's text>" -> "<chosen>", <state>: <why>`, then a time anchor on the
  recorder's transcript spanning the one line the fix is in (its start rounded down, its end up), one on Whisper's
  spanning the segments its text came from, then evidence: anchors on other covered records, and `[d:]` refs to note
  lines. The two texts are as `spots` gives them.
- **Anchored segments:** the recorder's is the line whose rounded span is the anchor; when two round alike, the one its
  text stands in. Whisper's are its segments other than `[cut]` inside the anchor's span, read in time order and
  joined by a space; the ones its text touches are the fix's.
- **States:** `sure` and `unsure`, written by Claude; `confirmed` and `rejected`, written only by the owner's click
  (DR-0586). A chosen text equal to the recorder's says the recorder was right: the spot is decided and nothing
  changes.
- **Not chunked**, from PR 2 on: search finds the reading, not lines like `"Nortwin" / "Northwood"`. The lines
  are citable with `[d:...]` like any doc's (DR-0540), so a note line built on a fixed name can cite its fix.

What doc_put checks, on top of every doc's rules:

| Check | Refused when |
|---|---|
| the machine | this machine doesn't ingest the recording's source |
| the recording | covers holds no recorder transcript of the Whisper rid's recording, or two; the id isn't the one Docket gives the recording, or the recording has a fixes doc under another id already |
| the family | the family screen refuses it now, a source only off aside |
| a line | it doesn't parse; it lacks either transcript's anchor |
| the texts | on a line new or changed in this put: the recorder's text doesn't stand once in the anchored line, or Whisper's doesn't stand in the anchored Whisper segments, as the latest versions hold them |
| cuts | on every line: the anchored recorder line, or a Whisper segment its text touches, is in a cut |
| bounds | a quoted text over six words, a chosen text more than two words longer than the longer side, a quote or a line break in one |
| one per place | two lines whose places overlap; except that a place whose every line is rejected takes one new line, `unsure`, with a chosen text none of them had |
| never-store | on every line: it, its why or a ref names a listed person in the brief screen's shapes (`brief_form.people_screen`); and each line a line of the put changes, rendered with that fix applied beside its other fixes, holds no keyword and no listed person in those shapes, so a name can't form across a fix's edge ("Ben Simple" fixed to "Ben Sample"). Also: `entities` holds a held entity; a chosen text redaction would change, refused rather than stored with a marker |
| owner lines | a committed line that isn't `sure` is changed, or missing while it isn't now cut or hidden; or the put adds a `confirmed` or `rejected` line |

- Dropping is the one change a put or a take-in may make to a committed line that isn't `sure`, and only when that
  line is now cut or hidden; a line now cut or hidden is refused until it is dropped, so a later cut or list never
  leaves the doc stuck. The skill drops such lines on its next put.
- Every read takes the doc as its last commit holds it, as a final decision is read (DR-0564), and notes one edited
  on disk. A hand edit is taken in under the same owner-line rule; one that sets or changes a state stays on disk.
- Unchanged committed lines aren't checked against raw's texts again, so a transcript's new version never blocks a
  put: the reading lists such a line as no longer matching.
- The redact pass is the one other writer, as for decisions: its rev changes only what a rule now covers, and a fix
  whose chosen text it changes stops applying.

### Who decides what (DR-0104)

| Docket | Claude | The owner |
|---|---|---|
| aligns, finds and ranks the spots, gathers the meeting's names, gives the doc's id | decides each spot: the recorder's text, Whisper's, or another | decides an unsure fix, or rejects any fix |
| checks a fix's form, its texts in raw, its bounds, cuts and never-store | says sure or unsure, why, and cites evidence | |
| renders the reading from the applied fixes | finds evidence with `search` over past calls, mail and notes | |

Docket never picks a text, and never judges whether evidence is enough.

### The reading (DR-0585)

| A fix | Applied when |
|---|---|
| state | `sure` or `confirmed` |
| still there | the recorder's text stands once in the anchored line, and Whisper's stands in the anchored Whisper segments, in the latest versions in raw |
| cuts | the anchored line, and the Whisper segments its text touches, are in no cut |
| screen | the family screen passes, a source only off aside; its chosen text is left as it is by redaction in force; and its line, rendered with every fix that passes the rows above, holds no keyword and no listed person in the brief screen's shapes. A line that fails gets none of its fixes |

Every other fix is listed with why: waiting, rejected, no longer matching, cut or hidden. A cut or hidden fix is
listed without its texts, by the tool and on the page.

- The reading is the recorder's lines, times and speakers as raw has them. In each line the applied fixes' places are
  found in its raw text first, then all replaced at once by their chosen texts, so no fix moves another's place and no
  other word of the line changes. Two rebuilds give the same text. One module renders it, `reconcile/render.py`, for
  three readers:

| Reader | What it gets |
|---|---|
| the index | chunks of kind `reconciled`, cut as transcripts are: the recorder's rid, the recording's group, owner `x <rid>` |
| search | a reconciled chunk and the raw chunks of the same stretch collapse into one hit, the reconciled one leading, the others under `also` |
| `read`, `verify` | a raw span of a transcript with applied fixes gains `reconciled`, its text as the reading has it, and `fixes`, the cite tokens of the fixes in it |
| the Recording page | each fixed word marked in the recorder's column |

- The index re-renders a recording's reading when its fixes doc changes, when either transcript gains a version, and
  when the screen's inputs move: the never-store lists; the people shapes with the names, aliases and contact ids of
  every entity a list holds (`brief_form.phrases`), so an alias curate adds to a listed person counts; redaction in
  force; the sources' sensitivity; and this machine's withheld marks and private decisions. They are kept as one
  fingerprint in the index's meta. Only recordings with a fixes doc are rendered.
- This adds the settings in force, the listed entities' forms and those marks to what the index reads, for readings
  only, and reads the fixes doc from its last commit: two amendments to the index's working-tree rule (DR-0115), as
  DR-0564 made one for final decisions.
- Schema 11: the `reconciled` chunk kind, and a `readings` table (recording, doc, rev, applied, waiting, rejected, no
  longer matching, hidden) for the tool's listing and the page's counts.

### Unsure fixes: a click on the Recording page (DR-0586)

The issue requires that Claude can't set an unsure fix's state. Curate's round can't hold that: Claude runs the writes
on the user's word, and auto mode or an allow rule removes the prompt (DR-0564's reason). So the decisions' pattern:

| Part | Rule |
|---|---|
| the click | each fix line shows the click that sets its other state: Confirm on an unsure or rejected fix, Reject on an unsure, sure or confirmed one |
| the post | `POST /recording/fix`: same-origin, the browser's session only, Authorization refused, checked by the Guard, on the writer thread, carrying the doc's id, the rev shown, the line and the pick; 303 back with `done` |
| the writer | `DocStore.settle`, as `DocStore.decide` works: it builds the next rev from the doc's last commit, and is refused when the file on disk differs from it ("edited by hand; put it with the reconcile skill, or check it out again") or when the doc moved since the page showed it. It sets that line's state, `by: <owner>, Recording page`, commit `Fix: <doc id> line <n> confirmed on the Recording page`. A scan over the package pins that only the page's route calls it |
| Claude's side | doc_put and the take-in keep every committed line that isn't `sure`, dropping one only when it is now cut or hidden; every read takes the doc from its last commit |
| not deciding | an unsure fix left alone is safe: the reading keeps the recorder's text |

Building from the last commit means a Claude edit on disk can't ride along with an owner's click, and refusing an
edited file means an owner's own hand edit is never written over. The floor is DR-0564's: Claude could still drive the
page, post its form with a session got from the token, or commit with git itself, each a deliberate step outside every
door.

### The tool and the skill (DR-0584)

`spots(rid=None)`, read-only. The MCP test pins its fields:

| Field | What |
|---|---|
| `rid`, `transcript`, `whisper` | the recording, and the two transcripts it compares |
| `doc` | the fixes doc's `id` and `rev`; for a recording with none yet, the id Docket gives it and `rev` null |
| `why` | null, or the reason it gets no spots: another machine ingests its source, or the family screen keeps it out, never a value |
| `people` | the meeting's entities and the glossary terms near a spot: id, type, name, aliases with `asr` marked |
| `spots` | id, kind, `left`, `right`, the recorder's anchor and Whisper's, the speaker, the recorder's line and Whisper's words for it, `near` entity ids, `rejected` (the picks the owner turned down at that place) |
| `fixes` | the doc's lines: n, cite, the texts, chosen, state, applied, and why not; a cut or hidden one without its texts |
| `left_out` | counts by reason: past the cap per kind, heard differently, near a never-store value |

Without a rid it lists the recordings to reconcile: at most 10 of the newest 30, from the sources this machine
ingests, with both transcripts in raw and passing the screen, with spots no fix decides or fixes waiting for the owner,
each with its counts; and `hidden`, how many the screen kept out.

The plugin's `reconcile` skill, `/docket:reconcile`. Its description leads with transcripts ("Transcripts: decide where
a recording's two transcripts disagree..."), since the design's phase-3 sync step is called reconcile too.

1. `spots()` for the waiting recordings, or `spots(rid)` for the one the user names.
2. For each spot, a call from the meeting's people and terms, the line on both sides, and `search` for the name or
   number in other calls, mail and notes:

   | Call | When |
   |---|---|
   | sure | evidence settles it: an attendee's or a term's name, a number another record states, the recorder's own text when evidence backs it |
   | unsure | it rests on reading the context alone; and always for a place the owner rejected, with a pick they didn't turn down |

3. The fixes doc, under the id `spots` gives: a new one, or its next rev with the new lines, every line that isn't its
   own `sure` one kept as it stands, and the lines `spots` lists as cut or hidden dropped; `doc_put` asks.
4. To the user: how many fixes went in, and the unsure ones in one table. From PR 3 on, the Recording page's link,
   where they click; in PR 2 the skill says unsure fixes wait, not applied, until the page's click arrives.

It pre-approves `spots`, `search`, `read` and `verify`. A sync run's closing steps gain one line: `spots()` counts the
recordings waiting; say so once, and reconcile only when the user asks.

### Never-store and cuts

Every rule is a shared one:

| Rule | Shared with | Where it holds |
|---|---|---|
| spots and puts only where the source is ingested | `docket transcribe`'s machine check (#158) | spots, doc_put |
| a family withheld, privately decided, out of force or private, or with a version a list matches, gets nothing | `media.screen.refusal`, what the reader and the Whisper job ask | spots, doc_put, the reading, the page |
| a person a list names, in any shape | `brief_form.people_screen` and `phrases` over `person_listed`, `slug_listed`, `listed` (DR-0558) | spots left out, doc_put on each line and each changed line as rendered, the reading by line, the page's lines hidden |
| an entity a list holds, in the meeting's names and the glossary | `speech/prompt.py`'s `_listed` | spots' `people` and near-name matching |
| a keyword | every doc's screen | doc_put; the reading by line, as rendered |
| a cut stretch | the transcripts' `[cut]` spans, merged, against segments' own times (DR-0126) | spots, doc_put, the reading |

A list that gains a value, or an alias of a listed person, later hides the recording's affected fixes on the page and
in `spots`, drops them from the reading at the index's next update, by the fingerprint, and the next put drops them
from the doc.

### Cost

| What | Cost |
|---|---|
| the core, per call | two transcripts read at their places and aligned per line; PR 1 times an hour's call, aiming under half a second |
| Claude, per recording | at most 40 spots with their lines, about 5,000 tokens to read, a few searches, a doc of 40 lines; the cap keeps a long call at a short one's cost |
| a week of 25 recordings | about 200,000 tokens if every one is reconciled; on request only, a batch per session |
| the index | only recordings with a fixes doc are rendered; all of them again only when the screen's fingerprint moves |

Reconciling runs on request, offered once after a sync, never by itself: Claude's time is the user's, and no headless
Claude runs before phase 3 (DR-0018).

### What it feeds

| Reader | How |
|---|---|
| notes and minutes | the writer reads `reconciled` in a span and quotes it; a line resting on a fixed name or number cites that fix with the span's `fixes` token, beside its raw anchor |
| briefs and decisions | cite note lines as today; a fix undone flags the note line (#160), and the brief or decision through it, one rev at a time |
| search | the reconciled chunk leads its collapse, so a query with the right name finds the stretch and shows the fixed text |

The recall skill's writing guide and the brief and decision skills each gain one line saying so.

### Not chosen

| Option | Why not |
|---|---|
| a `read` view for spots | `read` takes a locator and gives raw or a summary; spots are a capped list with context, and the listing has no locator |
| a `read` view `reconciled` | a span's added fields show the reading wherever raw is read, without a new value to ask for |
| the reading as a doc | a second copy of the transcript to keep in step; a hand edit would become a rewrite |
| the reading in place of the recorder's chunks | a wrong fix would hide the raw from search |
| `correction` as the type | it means a doc line's fix, with rules of its own |
| a new anchor kind naming a spot | the grammar is a door, and an older Docket's redaction damages a kind it doesn't read (DR-0541) |
| a word offset in each line | it moves with any new version; a text that stands once names its place and says when it no longer matches |
| a fix's text replaced wherever it stands | a short text such as "the" changes right words elsewhere in the line |
| spots in the index | they change with entities and lists, and cost milliseconds |
| one alignment over the whole call | it drifts across stretches one engine skipped; a recorder line bounds each comparison |

## Steps

PR 1, no doors: the spots and a read-only CLI, so the maintainer can run them on three real recordings before the
format settles.

1. `reconcile/align.py`, `reconcile/numbers.py`. Tests: `test_reconcile_align.py` (places, word times and their lines,
   the edge rule both ways, widening to a text that stands once, fillers, case and accents, cuts by segments' own
   times), `test_reconcile_numbers.py` (digits, `tízmillió`, `egy` alone, equal values).
2. `meeting.py`, with `speech/prompt.py` calling it. Tests: `test_speech_prompt.py` unchanged and passing,
   `test_meeting.py`.
3. `reconcile/spots.py`: kinds, rank, cap, rejected places, the screens, the machine check, the doc's id, the listing.
   Test: `test_reconcile_spots.py`.
4. `docket reconcile spots <rid> [--json]` and `docket reconcile list`. Test: `test_cli_reconcile.py`.

Then the maintainer runs `docket reconcile spots` on three recordings with both transcripts and sets the cap, the
