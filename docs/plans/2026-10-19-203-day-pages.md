# Add the day pages: Ledger, Queue, Meetings and Today

Four pages over the ledger in four PRs, sharing one item panel, one write route where a form post is one batch and its
Undo an undo of that batch, the old app's keys, and a reload when an op file changes. They read through #201's
`ledger/views.py` and write through `store.write`, `by: user`, `via: page`. The owner's old tasks app is the bar.

## Goal

- Done: what the old app does, on four pages: triage by key or a row's quick button, done, drop, snooze, reopen, edit,
  notes, materials (files, folders, text), outcome, a log line, a new item; points added, answered, kept, dropped,
  removed, kept as proposed, turned into items; a meeting's outcome and notes; bulk, undo, a reload on others' writes.
- Out: forget on the pages (#182); joining meetings by hand (Claude's `ledger_batch`); rollover and archive (the
  sync's, #210); streams' status (#208); the Outbox; the old app's lookup in harvest files (raw is in Search now).

## Design

### Built on

| From | What |
|---|---|
| #198, #199, #219 | `store.write`: one batch, all or none, `by` and `via` per op, undo by `of` or `batch`, an undone undo a redo (DR-0614, DR-0639) |
| #201's PR 2 (#222) | `views.read`: snapshot, show, queue, list, suggest; each row's `ref` is what a batch takes; a snoozed item whose day has come counted open and untriaged; a point's `from` and `to` (DR-0638, DR-0643) |
| the web app | the shell, `page()`, `safely`, `read_form`, `history`, `#panel` swaps; plain posts on the writer thread with a 303 (DR-0381, DR-0473); Staging's state as hidden fields |

### The shared parts (PR 1)

| Part | How |
|---|---|
| state | one `DayState` for the four pages: `open`, `q`, `stream`, `kind`, `who`, `k`, `at`, `done`, then each page's own; one canonical URL per page |
| reads | `ledger_tables` in a thread beside the writer, then `views.read`; `list` read whole (`k` None) and cut in the page; two reads added off the tool, `views.matching` (the ids `q` finds) and `views.batch_lines` (the notice's lines); no fold, no query of the pages' own (DR-0616) |
| selection | one: the focused row is the open one, and j and k move the panel with it, as the old app's did; a call (verdict, done, drop, snooze, reopen) moves it to `at`, the row after the acted ones, as the old Inbox did; the panel's other forms keep it (DR-0662) |
| item panel | `day/_item.html` from `show`: the call, fields, its meeting's points, notes, materials, outcome, source, counts, history (DR-0664) |
| buttons | `POST /ledger/write`: a form is one batch, `item` repeated for a bulk, a 303 back with `done=<batch>`, no index update (DR-0616); docket.js disables a form's buttons once it posts and ignores a held key (DR-0661) |
| text fields | title, who, due, description, notes, outcome, a meeting's outcome and notes save on `change`, as the old app saved on click-away: htmx posts to `/ledger/save`, which answers the panel and, out of band, the row and the version, so a page's own save brings no reload; without the script, Save posts to `/ledger/write`. A save whose panel moved on swaps nothing, a panel swap waits for one in flight, and leaving unsaved text by a link, a key or a reload asks first (DR-0661) |
| undo | the notice after a write shows the batch's log lines and Undo, an `undo` of the batch; after an undo, Redo |
| keys | 1 to 4 the verdicts, 0 no call, e done, Delete drop, s snooze, u undo, x tick, n new: on the ticked rows, else the selected item; a meeting's row or panel takes none (DR-0662) |
| refresh | a poll every 5 s with a hash of the op files' names, sizes and times, Today's with the cursor files; changed, the page reloads, the selection and the panel's scroll kept in sessionStorage (DR-0663) |
| search | `q`, every word folded, in an item's or meeting's text and log; `stream`, `kind`, `who` as `list` takes them (DR-0665) |

- The act bar is one form at the list's foot, the rows' ticks belong to it (`form="act"`), and CSS shows it once one
  is ticked: the verdicts and no call, done, drop with its why, snooze (next working day, Monday, a week, two weeks, a
  day), reopen. A group's Select all ticks its rows. An open item's row has the old app's quick buttons: the verdicts,
  ✓ done, and ✕, which opens the drop form, its why focused; each names its row, ticks aside.
- A verdict button carries what it writes, by the old bulk rule: clear when every row it acts on holds that verdict,
  else set it on all; rendered so on the panel and rows, set by docket.js on the act bar. No write toggles: a second
  post says "Nothing changed", a notice. A bulk gives each op the rows it takes, closed ones to reopen, open ones to the
  rest, and names those it skipped.
- A refusal writes nothing and answers the page the form names, 400, the writer's words as its notice, text as
  typed and no poll; a refused save answers its panel so. An add refused as a look-alike shows the items it looks
  like and Add anyway, which posts `force=true`; `RefusedError` gains their refs.

### Each page

| Page | Reads | Lists, in order | Writes |
|---|---|---|---|
| Ledger `/ledger` | `list`, every state | `state`: open (default), snoozed, closed, all. Open by due (snooze ended, overdue, today, this week, later, none) or by `group` (stream, kind, who, meeting); snoozed by the day back; closed by its day, newest first; archived only with `archived=1` | act bar, item panel, New item |
| Queue `/queue` | `queue` | untriaged first, snooze ended leading them, then discuss, claude, me, chase, each by due, none last | act bar, item panel, New item |
| Meetings `/meetings` | `snapshot` over `since` and `until`, 14 days back and ahead; `show`, `suggest` in the panel | by day from today, then earlier days, newest first; each day by start; cancelled and declined dimmed, and one with no points and no open items | meeting panel (DR-0667) |
| Today `/today` | `snapshot`, today to the end of the next working day (Monday to Friday, the owner's zone, as todo.py's); `list` of done and dropped, for those closed today; cursor files, open runs | meetings left today, then the next working day's, not cancelled or declined, each with its open points and open items; due today and overdue; closed today; the last sync per source | both panels; act bar on due items |

- Within a group, rows go by due, opened, number. A list shows `k` rows, 100; Show more adds 100, past the view's
  500. Counts are over all. A snoozed item whose day has come is open and untriaged because #222's views say so;
  `day.py` has no rule of its own (DR-0666).
- The meeting panel (PR 3): subject, time, organiser, where, response, attendees linked to their briefs when an
  entity names them; points and their buttons, a carried point's from and to linking their meetings; add a point;
  keep or remove every proposed one; Suggest (`suggest=1`), each item's why and an Add; outcome and notes; linked
  items; the recording; materials; history with Undo. Once over, it says its open points roll at the next sync
  (DR-0624).

### What a button writes

| Button | Op, through `/ledger/write` |
|---|---|
| a verdict, no call | `triage` with `verdict`, or none, per item, as the button's value says |
| done, its optional why and outcome; drop, its why required (DR-0611) | `done` or `drop` with `note` and `outcome` |
| snooze; reopen | `snooze` with `until`; `reopen` |
| the fields; notes; outcome; a log line; a meeting's outcome, notes | `set` of what changed; `notes` with `set`; `set` of `outcome`; `log`; `set` on the meeting |
| a material added or removed | `material` with `ref` and `label`, or `remove` |
| New item; Add anyway | `add` with `as`, source `page:<day>T<hh:mm>` unless given; then with `force`; the page opens it |
| Undo on a history line; Redo on an undo's line; Undo, Redo in the notice | `undo` with `of`, only where `undone_by` is None, never on the add or a renumber, the undone line naming its undo; the notice's with `batch` |
| a point added, a suggestion added | `point` with `text`, and `item` |
| answer; answered or open; drop; reopen; text | `point_set` by the point's id: `answer`; `state`; `state` with `answer` cleared; `text` |
| keep one proposed; keep all; remove one; remove every proposed | `point_set` clearing `proposed`; `keep` on the meeting; `undo` of each `point` op, one batch |
| → item | `point_item` with `stream` (a select, the meeting's preselected), `kind` and `who`, blank for the writer's default |

### The source and materials

A URL opens as a link. A locator opens Search's panel on its raw (`/search?hit=`), a recording the Recording page; a
text locator naming no record links to Search with its text as the query. Each has Copy. A path from the host repo's
top opens through `POST /ledger/open`, a file with its app, a folder in the file manager, each with Show in folder; a
text file (`.md`, `.txt`, `.json`, `.yaml`, `.yml`) shows in the panel's viewer through `GET /ledger/text` (DR-0664).

| Check, in order | Rule |
|---|---|
| named | only a material the item or meeting names |
| as text | before any filesystem call, refused: absolute, drive-relative (`C:x`), UNC (`\\host`, `//host`), a `..` part, a colon, a part ending in a dot or a space; the panel shows such a ref as text and never stats it |
| resolved | under the host repo's top, links and junctions followed: the target inside the top, a folder or a file whose lowercased suffix is on `day.py`'s `OPENABLE` (documents, images, media; none that runs or carries macros) |
| launched | `os.startfile`, `open` or `xdg-open`; Show in folder `explorer /select,`, `open -R`, `xdg-open` on the folder. A service with no display can't open apps, and the answer says so |

### Navigation and links

- Each PR marks its page built, first in "The day" (DR-0546): Today, Queue, Ledger, Meetings, Outbox later. From
  PR 4, `/` answers 303 to `/today` and the brand links to `/` (DR-0669).
- A brief links to `/ledger?who=<name>`, Today's sync line to `/sync?source=<name>`; the Sync page doesn't change.
  The URLs only gain optional parameters, since the tasks skill (#209) opens them.

## Doors and data

None. The pages write only what the writer writes today, `by: user`, `via: page` (DR-0611): no new op, key, file or
tool parameter; the two reads `views.py` gains stay off the `ledger` tool, and `RefusedError`'s refs are an attribute.

## Risks

- A page load per key press: 50 items triaged are 50 loads of about a tenth of a second. Accepted; `hx-boost` if it
  drags. A read during a full index update waits up to `LEDGER_WAIT`, then folds (DR-0619).
- Two panels on one item: the later save wins, the history keeps both, and Undo brings the other back (#198).
- Opening a material starts a process on the owner's desktop from a post: a named material, checked as text, inside
  the host repo, allow-listed types, the post checked by the Guard (DR-0152). Accepted, as the old app did.
