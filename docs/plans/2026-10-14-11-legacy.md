# Import a notes folder as legacy notes with old paths in the doc format

## Goal

`docket import notes <folder>` turns every markdown note in an existing folder into a `legacy-note` doc, and every
reference to a note by its old path keeps working: `read("notes/calls/2026-09-10-supplier-call.md")` returns the note,
and `read("notes/calls/2026-09-10-supplier-call.md@12:08")` the recording behind it at 12:08. The folder is never
changed, so the old setup runs on while the vault earns its week of real use.

- In scope: the command and its Python API; the two legacy fields in the doc format; old paths as locators in `read`;
  finding the records a note covered; re-running the import; a record's summary naming the legacy notes that cover it.
- Out of scope: search over legacy notes and the index's crosswalk table (#7, which loads what this writes); the MCP
  tool (#8 wraps `read`, which this extends; no import tool yet); Plaud's names for its records (#10 registers them
  through the hook here); turning a legacy note's times into anchors (a later recording note can supersede it); `.txt`
  transcripts in the folder (raw material, #10's import); the ledger and entity imports (later phases); forgetting.

## Design

Two new modules, small changes to four of #6's, and one command. No new dependency.

| Module | What it does |
|---|---|
| `docket/vault/legacy.py` | the old-path rules: normalize, check, and find a legacy doc by its old path |
| `docket/imports/notes.py` | the import: list the folder, build each doc, decide what changes, write one batch; `register_note_names` |
| `docket/vault/processed.py` (#6) | `old_paths` and `import_hash`, on legacy notes only |
| `docket/vault/anchors.py` (#6) | a path locator may end in `@times` |
| `docket/vault/docstore.py` (#6) | `put_many`: several docs checked one by one, the accepted ones in one commit |
| `docket/recall.py` (#6) | `read` takes an old path; a record's summary view names the legacy notes covering it |
| `cli.py` | the `import` group and its `notes` command |

### The legacy doc

A note stays itself: its text is the body, and Docket's frontmatter goes on top.

```markdown
---
id: legacy-note:2026-09-10-supplier-call
type: legacy-note
rev: 1
covers:
  - calls:rec-0042
by: docket import
supersedes: []
entities: []
old_paths:
  - notes/calls/2026-09-10-supplier-call.md
import_hash: sha256:3f1a...
---

# Supplier call

Source: call recorder `rec-0042`, 45 min.

## What was said

- Ben put the consultant at 10 million forints for the quarter (12:08).
```

| Field | Rule |
|---|---|
| `old_paths` | the note's path from its repo's root: `/` separators, NFC, no `..`, no `:`, no leading `/`; a block list, one entry written by the import; legacy notes only |
| `import_hash` | `sha256:` of the body the import last wrote, taken as #6 gives it back (`ProcessedDoc` parsed from its own render), so #6's trailing-newline rule and an empty body hash the same on every run; legacy notes only |
| `covers` | the records the note's head names (Covers below); empty when it names none, which #6 allows for legacy notes; later runs add to it and never remove one |
| `by` | `docket import`, the same on every run, so a re-run with nothing new writes nothing |
| `entities` | empty on a new doc, then kept as stored; mentions come from #7's tagging |
| body | the note's bytes as UTF-8, BOM dropped, CRLF and CR made LF, redacted (#5), then through #6's render and parse; a frontmatter block the note had stays in the body, unread |

- Id and path follow #6: `legacy-note:<slug>`, and a slug starting with a date lands in
  `processed/legacy-note/<yyyy>/<mm>/`.
- The slug is the file name's stem folded to ASCII (accents dropped), lowercased, other runs made `-`, `-` trimmed at
  both ends, cut to 80, trimmed again; an empty result is `note`, a Windows device name gets `-note`. An id is taken
  when it has a file or any `Doc:` commit; a taken id's stem is cut to 73 and trimmed, then gets `-` and the first 6
  hex of the old path's sha256. Once given, an id is never worked out again: a re-run finds the doc by its old path.
- Anchors: #6 never reads a legacy note's body for anchors. A line ending in `@12:08` is text, never refused, and
  `verify` on a legacy note returns no lines. A legacy note reaches its raw through `covers`.

### Old paths

The old path is what other files wrote: the note's path from the root of the git repo the folder is in, so
`notes/calls/x.md` when the folder is `<repo>/notes`. `--as <prefix>` sets the part before the path inside the folder
(`--as .` for none); outside a git repo the default prefix is the folder's own name.

Other files cite a note in more than one way: the bare old path, the old path after a source name
(`calls:notes/calls/2026-09-10-supplier-call.md@12:08`), or an absolute path on one machine
(`D:\work\repo\notes\calls\2026-09-10-supplier-call.md`). Precedence first: `r:` always means raw and a doc id stays
a doc (#6), and a bare `<source>:<id>` that is a rid in the raw log stays a rid. Only then does a locator whose path
ends in `.md` or `.markdown` go through these steps, stopping at the first with exactly one match:

| Step | Matches |
|---|---|
| a vault path | a doc file at that path under `<vault>/processed/` (#6) |
| exact | an old path, character for character after normalizing |
| case-folded | an old path compared case-folded, when only one matches |
| suffix | the longest old path the locator ends with, case-folded, when only one has that length: after a `:`, any old path; after a `/`, only one of two parts or more, so another folder's `README.md` never resolves to the root one. A one-part old path the locator ends with after a `/` is never resolved, but the problem names it as a candidate |
| file name | a locator with no `/` after any `<source>:`, against the last part of every old path, case-folded, when only one matches |
| nothing, or several | a problem naming the candidates, never a guess |

- Normalizing, before any step: `\` becomes `/`, a leading `./` and repeated `/` go, NFC. A `..` part is refused. A
  drive letter or a leading `/` takes part only in the suffix step. Lookups compare strings and never touch the file
  system.
- The grammar #6 has gains one form: `path-locator = path [ "@" times ]`, where the path ends in `.md` or `.markdown`
  in any case. The split is at the last `@` whose rest is a whole `times`, as for rids. A `<source>:<path>` form
  parses as #6's bare rid, and `read` applies the precedence above.
- Until #7's index, the lookup reads the frontmatter of the files under `processed/legacy-note/`, once per call.
  #7 loads `old_paths` into its `crosswalk` table, and the lookup asks the index when there is one.

### Covers

A note covers the records its head names. The head is the lines before its first heading of level two or deeper after
the first line, at most 40; a note's source sits there, and recordings it only mentions further down are not covered.

- Tokens: text in backticks, and words of six characters or more split on whitespace and `()[]<>{},;"'`, with trailing
  `.:!?` dropped.
- A token names a record when it is the record's rid, its id after `<source>:`, or a name the source registered:
  `register_note_names(source, fn)`, where `fn(record)` gives the other strings a note may use for it (a recorder's
  file id written without its prefix). #10 registers Plaud's. The registry works like `register_projection`.
- The import reads the raw log once per run into a name-to-rids map (the index's `records` table once #7 has it).
- A recording imported after its note gives the note its cover on the next run (Re-running below).

### Re-running

A legacy doc follows its note, and an edit made in the vault is kept until the note itself changes. The import finds
each note's doc by old path and compares hashes, never whole texts. Covers are only ever added (stored plus newly
found), and stored entities are kept:

| The note's body against `import_hash` | The doc's body | New covers found | Result |
|---|---|---|---|
| same | any | none | nothing written |
| same | any | some | the next rev: the stored body, the covers added |
| changed | the import's own (matches `import_hash`) | any | the next rev: the note's body, the covers added |
| changed | equal to the note's body (merged by hand) | any | the next rev: only `import_hash` moves, the covers added |
| changed | edited in the vault, and not equal to the note's | any | kept as it is, and reported with the `--take` command; exit 1 |

- "The note's body" is what the import would write now, redaction and #6's render and parse included, so a new
  redaction rule also writes a rev. "Edited in the vault" is any rev whose body isn't the import's: Claude's `doc_put`,
  a hand edit #6 took in, or a legacy doc with no `import_hash`.
- `--take note <old path> <hash>` writes the note's body as the next rev (the vault edit stays in history at its rev),
  and also brings back a doc deleted in the vault. `--take vault <old path> <hash>` keeps the doc's body and sets
  `import_hash` to the note's current hash, so later runs write nothing until the note changes again. The hash is the
  note's short hash the report printed: when the note has changed since, the take is refused and the note reported
  again with its new hash. An old path the import doesn't know is refused.
- Versions are #6's: every change is the next rev of the same file, and git history keeps every earlier one.
- The comparison is against what git has (#6's store), not the file on disk. A doc `put_many` refuses as stale,
  because #6 took in an edit on disk first, is decided once more at its new rev. So a run killed before its commit is
  finished by the next one, and an edit made during a run is kept.
- A note gone from the folder: its doc stays, so old references still resolve. A note renamed in the folder: a new doc
  under the new path, the old one stays.
- A legacy doc deleted in the vault stays deleted: when a doc with no file left held the note's old path in its last
  rev, the import skips the note and says so, with its `--take note <old path> <hash>` command to bring it back.

### The run

`import_notes(vault, folder, prefix=None, dry_run=False, take=None) -> ImportReport` reads the folder and writes the
vault, in this order:

| Step | What happens |
|---|---|
| list | in a git repo, `git ls-files -z -co --exclude-standard`, deduplicated (a conflicted note is listed once per stage): tracked and new files, never ignored ones; outside one, a walk that skips dot folders. A listed path that isn't a regular file on disk (an uncommitted delete or move) counts as gone. Links and nested repos are skipped either way, as counts only; a folder inside the vault is refused, a vault inside the folder skipped |
| screen the path | every listed path, before anything logs, reports or reads it: #5's never-store keywords on the whole old path with its prefix (so a keyword spread over two folders, `project/falcon/`, matches too), and for a note on the slug and id it would get; a match is skipped and counted, never named |
| pick | `.md` and `.markdown` in any case; other files are counted by extension; the old path is the prefix and the path inside the folder |
| read | UTF-8 only; over 2 MB, or not UTF-8: skipped and reported; an old path with `:` or a newline: refused and reported |
| screen the text | #5's never-store lists on the note's text, skipped and counted the same way; then #5's `Redactor.text` |
| place | doc lookup by old path, an id for a new note; notes in old-path order, so clashes come out the same on every machine |
| cover | head tokens against the name map |
| decide | the Re-running table |
| write | `put_many` under the vault lock: #6's checks per doc, one commit for the accepted ones, subject `Import notes: <n> new, <m> updated from <prefix>`, a `Doc: <id> rev <n>` line per doc in its body |

- The folder is only read. Every git call into its repo runs with `GIT_OPTIONAL_LOCKS=0`, so git doesn't refresh the
  repo's index file; a repo git refuses to read stops the import rather than reading it without its ignore rules.
- Both screens call #5's `neverstore.matches_text(text, lists)`, which reads any run of characters that aren't letters
  or digits as a space, splits at a change from lower to upper case, and matches a multi-word keyword's words joined.
  So `dora-example`, `dora_example`, `DoraExample`, `doraexample` and a link like `../people/dora-example/x.md` all
  match the keyword `dora example`. #5 adds that (F8 on PR #27); this change depends on it landing.
- Note text is data: nothing in it is run or followed, and the import logs paths and counts, never text. A note
  screened out leaves no trace: not in a doc, an id, a vault path, a commit message, the report or a log line.

### read

| Locator | `summary` | `raw` |
|---|---|---|
| an old path | the legacy note, as `read(<id>)` gives it | its covered records in full |
| an old path with `@times` | the legacy note, and current docs' lines anchored near that time | the span at that time in its covered record |
| a record (#6) | as #6, plus the legacy notes covering it, by id and old path | as #6 |

- A time is placed in the one covered record that has segments. None: the note comes back with a problem ("covers no
  recording in the raw log; import it, then run `docket import notes` again"). Several: the problem names each as
  `r:<rid>@12:08` to read instead.
- `both` is both. The result names what the old path resolved to (the doc id, and `r:<rid>@times` with a time), so an
  answer cites the canonical locator.

### The command

```
$ docket import notes ~/work/notes --dry-run
prefix   notes  (old paths look like notes/calls/2026-09-10-supplier-call.md)
new      182
updated  3
covers   1
same     40
kept     1  edited in the vault and changed in the folder: notes/calls/2026-09-01-kickoff.md
         settle it: run again with --take note|vault notes/calls/2026-09-01-kickoff.md 3f1a9c2e
skipped  .json 1, .jpg 1, links 1, nested repos 1, not UTF-8 1, over 2 MB 1, never-store 1
dry run: nothing written
```

`--take note|vault <old path> <hash>` repeats for several notes. Exit 0, or 1 while a note is kept or refused, so a
script notices; 2 for a `DocketError`, as every command. Output goes through `cli.main`'s UTF-8 console and #6's
escaping of control characters in paths.

## Doors and data

This extends two of #6's one-way doors, the doc format and the locator grammar, and adds no other one-way door. Each
row becomes a decision in `packages/docket/index.yaml`, `proposed` until the maintainer confirms it:

| Decision | Cost | Holds |
|---|---|---|
| A legacy note keeps its old paths in `old_paths` and the import's body hash in `import_hash` (old paths) | one-way | the two fields, their normalization, the hash taken from #6's render and parse, legacy notes only |
| An old path is a locator, with an optional `@times` (locator) | one-way | the form, the precedence (`r:` and a rid in the raw log first), the lookup steps with the suffix step and its two-part rule after a `/`, a time placed in the one covered record with segments |
| Re-importing follows the note and keeps an edit made in the vault (re-import) | medium | the Re-running table, `--take` with the note's hash, covers only added, one commit per run, deleted and gone notes |
| A legacy note's id comes from its file name and never changes (ids) | medium | the slug, the trims and cuts, the clash suffix, when an id is taken, lookup by old path first |
| A legacy note covers the records its head names (covers) | medium | the head, the tokens, `register_note_names` |
| The import reads a notes folder through git's ignore rules and #5's never-store lists, and never writes it (listing) | medium | the listing, gone and deduplicated paths, the skipped kinds as counts, never-store on every path, slug, id and text before any log, `GIT_OPTIONAL_LOCKS=0` |

- The PR title names the door (the doc format and the locator grammar), and the maintainer's agreement goes in #11
  before the merge. `AGENTS.md`'s doors line gains the two one-way decisions next to #6's.
- Users' data: the notes folder is only read. Existing vaults have no legacy notes, so nothing migrates.
- Needs from #6 before it merges: its rev rule reads a `Doc: <id> rev <n>` line anywhere in a commit's message, not
  only the subject, so one commit can carry many docs. Changing that after #6 merges would change its versions door.
- Needs from #5: a public string screen, `neverstore.matches_text(text, lists)`, that reads non-letters as spaces,
  splits at a case change and matches a multi-word keyword's words joined (F8 on PR #27). The import calls it and adds
  no matching of its own.
- Everything else here is additive to #6 and lands in this PR: the two fields, the path locator's `@times`,
  `put_many`, and `read`'s old paths.

## Steps

## Risks

- Notes imported before their recordings cover nothing, so their times can't be placed yet: the problem says to import
  the recordings and run the import again, which adds the covers. Accepted; the design already imports recordings
  first.
- A head token names an unrelated record and makes a wrong cover. Low with ids this long; the report counts covers.
  Since covers are only added, a cover removed in the vault comes back while the note's head still names it. Accepted.
- Two repos with the same relative paths imported without `--as` look like one note, and the second overwrites the
  first's docs as new revs. Accepted: `--dry-run` shows the old paths, and the help says to give each repo a prefix.
- Old references that wrote a clock time, not an offset, land on the wrong minute or past the recording's end, and
  minutes past 99 are refused by #6's grammar. Accepted: `read` shows the span, and past the end is refused with the
  recording's length.
- Relative links between notes (`../calls/x.md`), heading fragments and editor `file:line` references don't resolve.
  Accepted; a bare file name, a `<source>:` prefix and an absolute path still do when they match one note.
- A never-store keyword added after a note was imported doesn't remove its doc; the run skips the note from then on.
  Accepted: removing stored content is `docket forget` (phase 2).
- The run reads the whole raw log for names, and `read` scans legacy frontmatter per call, until #7's index. Accepted.
- #5's plan says the import writes through the gate; here notes skip staging, since they are docs, and get its
  never-store and redaction directly. Resolved here; flagged for #5's goal line.
- #7 has no plan yet: the crosswalk table and search's handling of old paths fall to whichever merges second.
  Accepted.
- Forgetting (phase 2) has to reach legacy notes and their history too. Accepted, noted for that issue.
