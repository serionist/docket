# Find the sync's closes and stop reading noted recordings again

The fourth rehearsal, every agent on Sonnet, took 11.7 minutes against the old sync's 19.5 but wrote no CLOSES line
where the old sync closed five items, and read three recordings of 14 Oct again. Three changes: every agent back on
the session's model, a bounded closes pass in both prompts, and a legacy note counted as a recording's note. One PR.

## Goal

- Done: a rehearsal on the old sync's window finds its closes and asks, without doubles, and reads no recording twice
  across two syncs (Success, below).
- In: the skill's launch, `agent.md` and `recording.md`, the reconcile's report, the no-note list.
- Out: the block's labels and fields, the reconcile's rules, matching an ask to an item held under an old `00-inbox`
  locator, `ledger_batch`.

## Design

| Finding | Rehearsal 4 | Change |
|---|---|---|
| no CLOSES line in any block | 0 against the old sync's 5: a folder sent, ten invites sent, two calls held, a repo released | a closes pass in both prompts; the reconcile says when no block holds a CLOSES line |
| recordings read again | 3 of 7, from 14 Oct: two with legacy notes, one with an earlier sync's recording note | a legacy note counts as a recording's note |
| asks split or doubled | about 5 of 18 adds | the session's model for every agent; the re-reads gone |

### The closes pass

A step of its own in each prompt, before the block, so its locators go through the source agent's check read.

| | Source agent (`agent.md`) | Recording agent (`recording.md`) |
|---|---|---|
| which items | open and snoozed ones in `context.md` whose who, by name or address, is in what its run read; for an item on a meeting, that meeting's organiser or attendees | whose who is among the speakers or named in the call; for an item on a meeting, this call's meeting, or its people in the call |
| evidence | a message sent, a call held, a file or a link shared, an answer given, an invite sent, a release made; the owner's own messages count | the same; the call itself for an item asking for it to be held |
| not evidence | a plan or a promise | the same |
| line | `CLOSES` with the locator of the record that shows it, `done` or `moot`; nothing when none | the same, the locator a moment of the files |

Bounded by the people the agent read: an item whose people it didn't read is left alone, so a ledger of hundreds of
items costs no more than the items in play.

`docket sync reconcile` adds `no source reported a close: no block holds a CLOSES line` to what it says when no block
has one. A CLOSES line it drops for a locator that doesn't open still counts as reported. The skill says it after the
list.

### The no-note list

`docket sync recordings` gives an agent to each recording in its window that no note covers. The query counted
minutes, recording notes and thread summaries; a legacy note never. `NOTE_TYPES` in `index/build.py` now holds the
four, and one SQL fragment serves the list and `noted()`, which the summary uses and which names a sync's note before a
legacy one. A digest, a brief or a correction still doesn't count: each covers records it doesn't note.

### The model

The skill launches the recording agents as it does the source agents, `general-purpose` with no `model`, and its
Sonnet trial bullet goes.
