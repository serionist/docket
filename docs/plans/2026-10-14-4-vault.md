# Add the vault, its config, raw records and the raw log

## Goal

A user can create a vault with a wizard, and Docket can write raw records into it that never change again, commit
them, and read them back by id. Everything later (the gate, docs, the index, the service) builds on this.

- In scope: `docket init`, a wizard that sets up a vault anywhere, including nested in a working folder that is its
  own git repo; the vault's layout; `vault.yaml`; the raw record model; the raw log; local commits under a lock;
  `docket vault status` and `docket vault check`; the CLI's frame.
- Out of scope: staging and the gate (#5); media content (phase 2, though `init` sets up the attributes); pushing and
  syncing between machines, and joining a second machine to a vault (a later issue).

## Design

Modules under `packages/docket/src/docket/vault/`, the design's data layer section as the reference:

| Module | What it does |
|---|---|
| `config.py` | `VaultConfig` (Pydantic v2, `extra="forbid"`): `schema_version: 1`, `owner` (name, emails, languages, an IANA time zone validated with zoneinfo), `primary_machine`, `sources` (enabled, sensitivity `work`, `mixed` or `private`), `never_store` (people, containers, keywords), `redaction` (built-ins on or off, extra patterns) |
| `machine.py` | this clone's machine name: `DOCKET_MACHINE`, else `.git/docket/machine` (per clone, never committed, written by the wizard), else the host name lowercased to `[a-z0-9-]`; a name may not end in `-<digits>` |
| `records.py` | `RawRecord` (the design's record fields plus `engine` and `lang`), rid rules (`<source>:<id>`, no whitespace); `canonical_projection()` is an explicit allow-list (kind, container, thread, ts, author, to, title, text, attachments by name, kind and ref), with absent and null fields left out; `version()` = `sha256:` of that projection as canonical JSON written by our own function (sorted keys, `,` and `:` separators, UTF-8 unescaped, `ts` in the projection as whole UTC seconds `YYYY-MM-DDTHH:MM:SSZ` so two routes to one instant agree, attachments sorted by name, kind and ref, empty lists and strings treated as absent), never a library's dump; a connector can pass its own projection |
| `rawlog.py` | `write_run()` writes `raw/<source>/<yyyy>/<mm>/<yyyy-mm-dd>T<hhmm>-<machine>.jsonl` (UTC; a second run in the same minute gets `.2`, `.3` before `.jsonl`), through a temp file and a rename, refusing an existing file; the temp file lives in `.git/docket/tmp/` (same volume), never under `raw/`; every record's `run` is the file's stem; records whose `(rid, v)` is already in the log or earlier in the same batch are dropped, from a seen-set that reads any run file it hasn't seen each time the lock is taken; `read(rid)` returns a record's versions in run order |
| `lock.py` | one lock per vault (`filelock` on `.git/docket.lock`) around every write and commit; a `.git/index.lock` older than ten minutes is removed with a warning |
| `git.py` | thin `git` calls; commits always local, with `-c user.name/-c user.email` from the owner when git has no identity |
| `vault.py` | `Vault.init()`, `Vault.open()`, `commit()`, `sync()`, `check()`, `status()` |
| `wizard.py` | the questions behind `docket init`, then `Vault.init()` |

Committing never depends on the network:

- `commit()` takes the lock, adds the paths it was given plus every untracked file under `raw/` whose name matches
  the run-file pattern (a run whose commit was missed before), never a modified tracked file, and commits locally.
- `sync()` is separate: it fetches (offline: a warning, nothing else), rebases with `--autostash` only when
  `origin/<branch>` exists, and on a conflict aborts the rebase, keeps the local commits and reports it. Pushing is the
  later sync issue.

`Vault.init()` refuses rather than overwrites:

- a folder that is already a vault ("already a vault: <path>"), and any folder that exists and isn't empty;
- in a parent repo, a vault folder name the parent already tracks;
- the first commit adds only the files `init` wrote; a failed `init` removes what it wrote.

The wizard asks, each with a default and each also a flag, so `docket init --yes --path ... --owner ...` runs in
scripts and tests:

- where: a path. Inside a parent git repo the vault is a repo of its own nested there (default `vault/`), and the
  wizard refuses while the parent has uncommitted changes (`--allow-dirty-parent` overrides). It appends `/<vault>/` to
  the parent's `.gitignore` and writes three lines to the parent's `.ignore` (`!/<vault>/`, `/<vault>/*`,
  `!/<vault>/processed/`), so ripgrep, Claude Code and editors search the processed docs and nothing else in it;
- the owner: name, emails, languages (default `en`), time zone (default from `tzlocal`; asked when there is none);
- this machine: its name (written to `.git/docket/machine`) and whether it is the primary one (the first one is);
- sources: which known ones to enable, with their sensitivity;
- a remote: none, a local path, an existing URL, or a new private GitHub repo through `gh`. A network URL is checked
  with an anonymous `git ls-remote` (no credential helper, `GIT_TERMINAL_PROMPT=0`): if that succeeds the repo is
  public and is refused. When it can't tell (SSH, offline), the user confirms it is private; under `--yes` that takes
  `--remote-is-private`;
- a summary of what it will create, and a confirmation, before anything is written.

`check()` reports raw files that don't parse, a `(rid, v)` twice in one run file, and raw files changed or deleted
against `HEAD`. `status()` shows records per source, runs, uncommitted run files, records seen in more than one run
file (expected when two machines overlap, only counted), and the last commit.

`cli.py` is a Typer app with `init`, `vault status` and `vault check`. The vault comes from `--vault`, `DOCKET_VAULT`,
the working directory upward, a `vault/` child of the working directory, or the default vault the wizard records in
the user's Docket config (`platformdirs`), in that order.

Alternatives: one JSONL file per source appended forever (merges conflict, "written once" can't be checked);
SQLite as the store (not diffable or mergeable; the design keeps it a cache); argparse (Typer's typed options and help
suit the many commands to come; it brings click, rich and shellingham, all permissive licences).

## Doors and data

This sets the first one-way doors: the vault's layout and run-file naming, `vault.yaml`'s schema, and the raw record's
fields and version function. Each becomes a decision with `cost: one-way`; `vault.yaml` carries `schema_version: 1`
so a later version can read and migrate it. No vault exists yet, so nothing migrates.

## Steps

1. Dependencies (pydantic, typer, filelock, pyyaml, platformdirs, tzdata, tzlocal) and the module layout; `machine.py` with tests
   (env, the per-clone file, the host name, a refused `-<digits>` ending).
2. `records.py`: tests that volatile fields don't change the version and content does, and a golden test: a fixed
   invented record (non-ASCII text, a quote, a newline, a `to` list, two attachments) hashes to a literal `sha256:`
   value, unchanged when an optional unset field is added, the attachments are reordered, or `ts` gains
   milliseconds.
3. `config.py`: load, dump, defaults, refusal of unknown keys, an IANA zone validated on all three systems.
4. `lock.py`, `git.py` and `Vault.commit()` and `sync()`: tests on an empty bare remote, an unreachable remote, a
   dirty tracked file, a remote with a new commit (rebased), a conflicting remote (aborted, local commit kept), a stale
   `index.lock`, and a missing git identity.
5. `rawlog.py`: write, refuse overwrite, the `.2` collision, `run` set to the stem, dedupe across runs and after
   another process wrote; a batch holding one record twice writes it once; `read(rid)` across runs and after a `.2`
   collision; a run whose commit was missed is committed with the next one, while a leftover temp file or a
   `.DS_Store` under `raw/` is not.
6. `vault.py` `init`, `check`, `status`: init refuses an existing vault (its `vault.yaml` byte-identical after), a
   non-empty folder, a name the parent tracks; a failed init leaves nothing; check finds a modified raw file and a
   duplicate within a run; status counts uncommitted runs.
7. `wizard.py` with scripted answers: standalone; nested (ignore lines written, and `rg --files` lists `processed/`
   but not `raw/` when rg is on PATH; refused while the parent is dirty); `--yes`; a public remote refused; an
   unknowable remote needing confirmation; nothing written before the confirmation.
8. `cli.py`: `init`, `vault status`, `vault check` through Typer's runner; after a nested init, `vault status` from the
   parent's root finds the vault.
9. The decisions, `AGENTS.md`'s doors, the package README, a CHANGELOG line.

## Tests

Under `packages/docket/tests/`, on temp folders with a real git run in an isolated config (`GIT_CONFIG_GLOBAL` an
empty file, `GIT_CONFIG_NOSYSTEM=1`), invented data only, on Windows, macOS and Linux in CI. Coverage stays at the
`docket` floor; a line that can't be reached gets a reason.

## Risks

- A raw file changed by hand slips through: `vault check` reports it; the gate (#5) refuses to write over it; the
  service runs `check` on start (#8). Accepted until then.
- Two processes on one machine write at once: the lock serializes them, and the service becomes the single writer (#8).
- Two machines write the same record before either syncs: both run files keep it, `status` counts it, search dedupes
  by `(rid, v)`. Accepted.

## Plan review

Standard tier, Opus, 14 Oct 2026. Round 1: needs-fixes (three majors, seven minors), all fixed in this revision.

| Id | Severity | Finding | Status |
|---|---|---|---|
| P1 | major | every commit failed with an empty or unreachable remote, or a dirty tracked file | fixed: commits are local, `sync()` is separate and never blocks them |
| P2 | major | a run file whose commit was missed was never committed, and its records were deduped away | fixed: `commit()` adds untracked run files; `status` reports them |
| P3 | major | `init` overwrote an existing vault, swept a non-empty folder, could nest over tracked files | fixed: refused, first commit only init's files, failed init cleaned up |
| P4 | minor | `!vault/processed/` in `.ignore` can't re-include under an ignored folder (ripgrep) | fixed: three lines, tested with rg |
| P5 | minor | the machine name the wizard asked for was never kept | fixed: `.git/docket/machine` |
| P6 | minor | the `-2` suffix collided with machine names | fixed: `.2` suffix, names may not end in `-<digits>`, `run` is the stem |
| P7 | minor | duplicates across machines were reported forever; the seen-set went stale | fixed: only within one run file; counted in `status`; seen-set refreshed under the lock |
| P8 | minor | the default time zone on Windows isn't an IANA name | fixed: tzdata and tzlocal, validated, asked when missing |
| P9 | minor | a public remote wasn't refused reliably | fixed: anonymous `ls-remote`, fail closed, `--remote-is-private` |
| P10 | minor | the first commit needed a git identity | fixed: owner identity when none; tests in an isolated git config |
