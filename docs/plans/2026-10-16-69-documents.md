# Add a folder source to vault.yaml for own documents, by page and sheet

Docket reads the user's work folder itself, read-only, and keeps each document as text through the same gate as every
source: a pdf by page, a deck by slide, a workbook by sheet with row n as paragraph n. A hit then cites its path and its
place without any change to the anchor grammar. Three PRs: the readers in a child process with their limits, promotion
in staged order with capped run files (#107), then the folder source, which closes this issue.

## Goal

Search covers what the user wrote next to what was said (the design's own documents row, phase 1).

| Part | Done when |
|---|---|
| Source | `docket scan` reads a folder named in `vault.yaml`, read-only: docx, xlsx, pptx, pdf, md and txt as text, with their paths and modification times |
| Changes | a file whose bytes changed is a new version; a deleted, moved or excluded one gets a gone version and keeps the earlier ones; one that comes back is current again; nothing in the folder is written, git's index included |
| Gate | never-store, redaction, holds and sensitivity, as for every source; the never-store check covers a file's whole text and its people, so a match anywhere keeps the whole file out |
| Hostile files | a file past a cap, damaged or protected is a record that says why, with no text; one that hangs or crashes the reader is tried again once; the scan goes on |
| Search | a hit's group is the file's path, its locator names the page, slide or sheet, and a sheet's rows are its paragraphs |

The issue's attachments row moves to an issue of its own, blocked by the first mail source: the readers it needs ship
here, in the core (DR-0489).

Out of scope: OCR and images (#42 and later); old binary formats (.doc, .xls, .ppt) and macro or binary workbooks
(.xlsm, .xlsb); a folder source's fields on the Settings page (#73); a scheduled scan (phase 3); scans on the Sync page.

## Design

### Mapper or core: the core

A folder source is the core's own connector, not a mapper run (DR-0480).

| Reason | What it means here |
|---|---|
| no Claude session | nothing to capture and no window by time: a folder is listed whole each time, and changes are found by stat and hash |
| extraction needs libraries | a mapper is plain JSON in and out and never imports Docket (DR-0119); pdf and Office files need pypdf and openpyxl |
| bytes don't fit the contract | a run's captures are JSON held in memory and passed whole to the mapper; a folder is gigabytes of binary |
| the design names it | a Python connector where no skill can harvest, for headless runs (DR-0108) |
| attachments will share it | a mail's attachments need the same readers and limits, kept in one place |

It keeps the contract all the same: rids `<source>:<native id>` checked by `RawRecord`, versions computed by the core,
holds, then `Gate.stage`. It lives in the core package as `docket.documents`, not a connector package under
`packages/`.

### The three PRs

| PR | What | Closes |
|---|---|---|
| 1 | the readers, the child process and its limits, with pypdf, openpyxl and defusedxml; nothing a user sees yet | none |
| 2 | promotion writes a source's ready records in `staged_at` order, in run files of at most 16 MiB (DR-0488) | #107 |
| 3 | the folder source: the `vault.yaml` keys, `docket scan`, records, gone versions, search and read; its title names `vault.yaml`, a door | #69 |

The promotion order is a bug every source has: two staged versions of one rid promote in the staging key's order, so
the older can land last in raw. It ships on its own, before the folder source makes it routine.

### The source in vault.yaml

```yaml
sources:
  documents:
    sensitivity: work
    folder: ~/Work                  # or a path relative to the consuming repo
    exclude: ["archive/*", "*.draft.md"]
```

- `folder` makes a source a folder source (DR-0481): relative to the consuming repo (`docs`), or under the home folder
  (`~/Work`). Both read the same on every machine. An absolute path is refused, and the message gives the fix below.
- A machine whose folder lives elsewhere, a work folder on another drive, names it in the user's config, which is never
  committed (DR-0490). The key is `folders`, by the vault's root and the source's name:

  ```yaml
  folders:
    D:/vaults/work:
      documents: E:/Work
  ```

  On that machine it replaces `vault.yaml`'s `folder`. Ids don't change with it, since they come from the path inside
  the folder.
- The folder itself may be a link or a junction: it is resolved before listing. Links and junctions inside it are left
  out.
- A machine without the folder scans nothing and says so.
- `exclude`: fnmatch patterns on the path inside the folder, case-insensitive.
- A folder source has no `mapper`, `tools` or `media_hosts`, and its sensitivity is `work`. `mixed` is refused (every
  page would wait on the Staging page one by one) and so is `private`, with the fix: `enabled: false`.
- `run_open` and the Sync page name it as a folder source, with `docket scan` as its way in.
- `docket source new <name> --folder <path>` adds the entry as it does for a mapper's source, so setup can offer it.

### What is read

| Listed | Rule |
|---|---|
| a folder in a git repo | `git ls-files -co --exclude-standard` with `GIT_OPTIONAL_LOCKS=0`, as the notes import lists: a file kept out of git never reaches the vault, and git's index is never refreshed |
| any other folder | walked, leaving out dot folders and nested repos |
| the vault | always left out |
| extensions | .docx, .xlsx, .pptx, .pdf, .md and .txt; the rest counted by extension |
| skipped and counted | a path with a link or a junction in it under the folder (`is_symlink()` and `is_junction()`, which the notes import gains too); anything not a regular file (reading a FIFO blocks); Office lock files (`~$*`); cloud placeholders (below); git-lfs pointers; `exclude` matches; a path holding a never-store keyword, checked before anything reads, logs or reports it |

- A placeholder is a file whose bytes aren't on disk, so reading it would make a sync client download it. On Windows,
  `st_file_attributes` holds `FILE_ATTRIBUTE_RECALL_ON_DATA_ACCESS` (0x400000), `FILE_ATTRIBUTE_RECALL_ON_OPEN`
  (0x40000) or `FILE_ATTRIBUTE_OFFLINE` (0x1000); on macOS, `st_flags` holds `SF_DATALESS`.
- The listing moves from `imports/notes.py` to `docket/folders.py`, and both use it.

### Records and rids

| Record | rid | kind | title | text |
|---|---|---|---|---|
| a file | `documents:<id>` | `document` | its path in the folder | docx, md, txt: the whole text; pdf, pptx, xlsx: none; a file not read: the line saying why |
| a pdf page | `documents:<id>/page3` | `page` | `<name>, page 3` | the page |
| a slide | `documents:<id>/slide4` | `slide` | `<name>, slide 4` | the slide, then its speaker notes |
| a sheet | `documents:<id>/sheet2` | `sheet` | `<name>, sheet Costs` | a paragraph per row (see Locators) |

- `<id>` is the first 12 hex of the sha256 of the file's path from the folder's root: NFC, `/`-separated (DR-0482).
  Every machine derives the same id, the folder can move inside its repo or to another drive without changing one,
  the anchor stays short, and the title holds the path.
- A part's container and thread are its file's rid, as Plaud's records sit under their recording, so search groups a
  file's pages.
- `ts` is the file's modification time. A gone version's `ts` is the scan's time, and so is the `ts` of a file or part
  that comes back after a gone version, so its version is a new one (see Gone).
- `fetched` is the scan's time; `via` is `docket-scan`; `engine` names the reader and its version (`pypdf 6.19.0`,
  `docket-docx 1`), outside the version hash.
- `native` holds the file's identity hash: for pdf, docx, xlsx and pptx the bytes' sha256 and size, since the bytes
  can't be rebuilt from the text; for md and txt the sha256 of the redacted text, and no size. Then the format, the
  part count, the people a file names (`creator` and `last_modified_by` from `docProps/core.xml` in docx, xlsx and
  pptx, and a docx's comment authors, so the never-store people list matches them), and, when they apply, `problem`,
  `gone`, `moved_to` and `moved_from`. No path: the title has it.
- Nothing derived from a file's text before redaction goes into raw: no hash and no size of it (DR-0483). A hash of
  the text as extracted would let anyone holding the vault test guesses against what redaction hid. It is the rule
  staging already keeps, whose key is taken over the record as redacted (DR-0024). The scan's cache, private to the
  machine and naming no file, may keep anything.
- A sheet goes by position: its name can hold spaces, which a rid can't.
- Two listed paths with one id: the second is refused and counted.

### Locators

The anchor grammar is a one-way door (DR-0198), and this plan leaves its grammar as it is.

- The page, slide or sheet is part of the rid: `r:documents:3f9a1c2b7d4e/page3`. A position inside it is the grammar's
  paragraphs: `[r:documents:3f9a1c2b7d4e/slide4#2]`.
- Paragraphs are separated by a blank line: a docx paragraph or table row, a slide's shape, a sheet's row (DR-0483).
- In a sheet, row n is paragraph n. Each row from 1 to the last with a value is its own paragraph, starting with its
  row number (`41: Widget | 3 | 4.50`); an empty row is `41:`; line breaks inside a cell become spaces; rows are
  numbered by the sheet's own `r` attribute, never counted. So `r:documents:3f9a1c2b7d4e/sheet2#41-80` is
  `Costs!41:80` in A1 notation, and `read` and `verify` take it as they are.
- A paragraph over 500 words (a pdf page, a txt file without blank lines, a long docx paragraph) is split at sentence
  ends into paragraphs of at most 500 words, else at the last space before the 500th word, so chunks stay the search's
  size. A sheet's row is never split, so row n stays paragraph n; a long row is a chunk of its own.
- Not chosen: a new position kind (`#p3`, `!A41:F80`). `[r:x#p3]` parses today as the rid `x#p3`, so a new kind would
  change what stored anchors mean, and columns add little to a row.
- An anchor on a gone folder record resolves against its last version with text, in `verify` and `doc_put` (DR-0491).
  That refines how DR-0198 resolves an anchor, never its grammar.
- What is new and one-way: the folder source's rid shape (DR-0482).

### Text per format, and the libraries

| Format | Reader | Licence | Reads | Misses |
|---|---|---|---|---|
| pdf | pypdf, with its `crypto` extra | BSD-3-Clause | each page's text layer; a file locked by an owner password only | scanned pages (the page says it has no text; no OCR); reading order across columns; text in images; form field values |
| docx | ours, on `zipfile` and defusedxml | Apache-2.0; defusedxml PSF-2.0 | body paragraphs and tables in order, content controls, text boxes, field results, tracked insertions in and deletions out; then headers and footers, footnotes, endnotes and comments; the core properties' and comments' authors into `native` | list numbers (Word computes them), deleted text, images, charts, equations' layout |
| pptx | ours, the same way | the same | slides in the deck's order: shapes, groups and tables, then the speaker notes; hidden slides marked | charts, SmartArt, images |
| xlsx | openpyxl, read-only, `data_only` | MIT; et-xmlfile MIT | each cell's saved value, dates as ISO dates; hidden sheets marked | formulas (a workbook no app has calculated shows its formula cells empty), comments, charts, pivot caches |
| md, txt | ours | Apache-2.0 | UTF-8 with or without a BOM, UTF-16 by its BOM, else Windows-1252, which the record says | other encodings, read wrong |

Text is NFC with LF line ends and no control characters but the tab; a table row is one paragraph, its cells joined by
` | `.

Why these (DR-0484):

| Library | Checked on 16 Oct 2026 | Why, or why not |
|---|---|---|
| pypdf | 6.20.1 of 12 Oct; 45 advisories published in 2026, every one a long runtime or memory use, the last fixed in 6.19.0 | pure Python, nothing required beside it, fast enough; floor `>=6.19.0`, locked at the newest release a week old (DR-0157); its `crypto` extra brings cryptography, already in the lock through the MCP SDK; those advisories are why it runs in a child with limits |
| pdfminer.six | 20260107, MIT | finer layout analysis than search needs, several times slower, and brings charset-normalizer |
| PyMuPDF | AGPL-3.0 | out |
| python-docx | 1.2.0 of June 2025, MIT, needs lxml | its paragraph text skips runs inside `w:ins`, so a document under review loses its inserted text, and it lists only the body's direct paragraphs, missing content controls and text boxes |
| python-pptx | 1.0.2 of August 2024, MIT, needs lxml, Pillow and XlsxWriter | two compiled packages and an image library for text alone, and no release in two years |
| openpyxl | 3.1.5 of June 2024, MIT; one XXE advisory, fixed in 2.4.2 | the standard reader, though releases are rare; read-only mode streams rows, and it parses through defusedxml whenever defusedxml is installed, which a test checks inside the child |
| defusedxml | 0.7.1 of March 2021, PSF-2.0, no advisories | refuses entity declarations and external references; a thin layer over the standard library's parsers, so a gap in its releases costs little |

Our docx and pptx readers are about 150 lines each: they follow the package's relationships from `_rels`, never fixed
part names, and read `w:t` and `a:t` in order.

### Hostile files

Extraction runs in a child process, never in the service's or the CLI's own (DR-0485): `python -I -X utf8 -m
docket.documents.child`, started in a temp folder with the mapper runner's stripped environment. The child reads a file
once, hashes those bytes and extracts from them, so the text always matches the bytes' hash the scan caches. It sends
a part a line; the scan keeps a file's parts only once the child says the file is done.

| Threat | Guard |
|---|---|
| memory | 2 GiB per child, set by the child on itself before it says ready: `RLIMIT_AS` on Linux, a job object of its own with `JOB_OBJECT_LIMIT_PROCESS_MEMORY` on Windows; its hello gives its pid and the cap it got, and the parent stops one without; the parent's job with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` takes it down on a stop; macOS has the time limit and the caps only |
| a slow or looping file | 120 s a file, then the child is killed |
| a reader that leaks or keeps state | a fresh child every 100 files |
| zip bombs | before any part is read: at most 10,000 members, stored or deflated only, none sharing or overlapping another's bytes, each counted by what its deflate stream really holds, inflated a MiB at a time from its raw bytes and never past what is left of the package's cap, at most 64 MiB each and 256 MiB together, and at most 100 to 1 for a member over 1 MiB; an embedded package is never opened |
| XML | a DTD refused at the parser in every part we or openpyxl parse: defusedxml with `forbid_dtd` in our readers, and openpyxl's parse functions rebound to it before a workbook is read, with lxml kept out of the child; a part nothing parses, an SVG image, is never judged |
| huge sheets | rows read as a stream, never trusting the declared dimension |
| caps | 64 MiB of bytes; 2,000 pages, 1,000 slides, 100 sheets, 10,000 rows and 256 columns a sheet; 1 MiB of text a part and 4 MiB a file |
| encryption | a pdf opens with an empty password, or reads `Not read: encrypted with a password.`; an Office file in an OLE container (a password or a sensitivity label) reads `Not read: protected.` |
| damage | `Not read: damaged (<the exception's type>)`, never the exception's message, which can quote content |

What happens to a file that isn't read whole:

| Outcome | Record | Next scan |
|---|---|---|
| past a cap, damaged, protected | the file's record with one line saying why (`Not read: 2,412 pages, over the cap of 2,000.`), no parts, no text; parts it had before get gone versions, as lost pages do | read again only when its bytes change |
| stopped at the time limit, or the child crashed | none: the file keeps its last version, and is never gone for it | tried once more on the same bytes; a second stop or crash makes the record above |
| locked, a permission error, a placeholder, a held id | none: the file keeps its last version, and is never gone for it | tried again |

A file is stored whole or not at all, so the never-store check always covers all the text a file has (DR-0485).

md and txt are the one exception to the child: decoding them is plain UTF-8, or UTF-16 by its BOM, else
Windows-1252, with no parser, so the scan may read one in its own process to compare it (DR-0485).

### Changes

Cheap on thousands of files: a stat each, a hash when the stat moved, the child only when the bytes moved (DR-0486).

1. The scan keeps a cache per machine, never committed: `<private>/documents/<source>.json`, each id's size,
   `mtime_ns` and bytes' sha256, its identity hash as raw holds it, the never-store lists' hash, and the bytes'
   sha256 of a try that stopped or crashed. It is keyed by id, so it names no file.
2. A file is done when its stat matches the cache and the vault's newest version of it still carries the cached
   identity hash. A version from another machine, or a gone version since, sends it on to the next step. A file with
   no identity in raw is done while its stat matches: one the never-store lists kept out, while the cache's lists
   hash is current; an md or txt file past a cap, whose record holds no hash.
3. Otherwise the stat is taken and the bytes hashed. Bytes the cache knows, whose identity the vault's newest version
   still carries (a touched file, a restored copy): the cache moves, nothing else. Else, for pdf, docx, xlsx and pptx
   the bytes' sha256 is compared with the newest version's identity; for md and txt the text is read, redacted with
   the gate's current rules and hashed, then compared. A gone version carries no identity, so a file that comes back
   is never the same.
4. Different: the child extracts. The file record gets a new version. A part gets one only when its title or its
   text, each run through the gate's current redaction rules, differs from its newest version's in raw, so a renamed
   sheet takes its new name. No hash of a part's text is stored, and a redacted credential compares equal on every
   scan. A change to the redaction rules versions the parts it touches once, at the file's next extraction.
5. The cache keeps the stat taken before the read. If the stat after the read differs, the file changed while it was
   read: its records still go in, since they match the bytes the child hashed, and its cache entry is dropped so the
   next scan looks again.
6. What the vault holds, each record's newest version with its identity hash and its text, comes from the source's
   own run files, read once and then only the new ones, as the raw log reads them, and from its records in staging.

- A file a list kept out is looked at again when the never-store lists change.
- A rename or a move is a gone record at the old id and a new one at the new id, since the id follows the path. When
  the same identity leaves one path and arrives at another in one scan, the two records carry `moved_to` and
  `moved_from`.
- A scan runs only on the vault's primary machine: two checkouts of one repo at different commits would otherwise
  turn each other's edits back, version by version. Elsewhere it names the machine that scans.
- A folder that isn't there scans nothing. A scan that would mark more than half the files it knew as gone, and at
  least 20, stages nothing until `docket scan --accept-gone`: an unmounted share must not look like a deleted folder.
- One scan at a time, under a lock in the private folder. The cache is saved after each batch, so an interrupted scan
  goes on where it stopped.

### Gone

A file deleted from the folder, moved, newly excluded, or whose new bytes the never-store lists keep out gets a gone
version of its record and of every part it had (DR-0487). A passing reason (locked, a permission error, a placeholder,
a held id, a stopped or crashed read) never makes a file gone.

- A gone version is written only when the newest version isn't gone already, so a file stays gone with one version,
  not one a scan.
- Its text is one line, `Not read from the folder since 2026-10-16.` for a file and `Not read from the file since
  2026-10-16.` for a part, with `native.gone`; its `ts` is the scan's time. Search finds the file by name with that
  line, and none of its old text.
- A file now not read (past a cap, damaged, protected) keeps a record that says why, and the parts it had get gone
  versions, as lost pages do.
- A file or part whose newest version is gone and that comes back is a new version with the scan's time as its `ts`,
  even with the same bytes and the same modification time as before: otherwise its version would equal the old one,
  which the raw log already holds, and the gate would skip it, leaving the file gone.
- A pdf that lost pages, a deck that lost slides, a workbook that lost sheets: those parts get gone versions too, and
  come back the same way.
- `read` of a folder source's record whose newest version is gone shows that version and the last one with text, so
  the earlier text is one call away. No MCP tool's parameters change.
- `verify` and `doc_put` resolve an anchor on such a record against its last version with text, and name `moved_to`
  when there is one (DR-0491). A summary written before a file went keeps working.
- Raw keeps every version. Forgetting is `docket forget`'s, never a scan's.

### The gate

- Records reach `Gate.stage` like any source's, in batches of at most 32 MiB of text, since each call reads all of
  staging.
- The scan checks each file whole before staging any of its records: its path, its whole text and the people in its
  `native`. A match keeps the whole file out, counted, never named. The gate then checks each record again.
- Redaction and holds are the gate's, unchanged. A held id isn't read at all.
- Promotion is PR 2's (#107): a source's ready records in `staged_at` order, so the last version staged is the last in
  raw, in run files of at most 16 MiB, each named as a run of its own (DR-0488). A first scan of a large folder would
  otherwise write one file past GitHub's 100 MB limit. The names and the layout don't change, so an older Docket reads
  them.

### Search and read

- A file's group has the kind `document` and its path as the title; each hit's locator names its page, slide or sheet.
- `render.search` adds a document hit's place: `page 3`, `slide 4`, or `Costs!41:80` from the sheet's name and the
  paragraphs.
- Chunks are the generic record chunks: a page, a slide, or up to 500 words of a sheet's rows or a docx's paragraphs,
  the title on top. The design's chunk row says so.

### Attachments, an issue of their own

- Extraction is always the core's, never a mapper's (DR-0489): a mapper never imports Docket (DR-0119), and one set of
  readers and limits is the one to keep safe.
- An attachment becomes `<mail rid>/att<n>`, kind `attachment`, its pages under it, its container the mail and its
  thread the mail's thread. How a mail run hands the bytes to the core (a file in the run's folder, `media_put` from
  #42, or a contract that names it) is settled in that issue's plan, with the first mail source.

## Risks

| Risk | Status |
|---|---|
| pypdf's steady run of runtime and memory advisories | resolved: a child with time and memory caps; Dependabot brings each fix |
| macOS has no enforced memory cap | accepted: the time limit and the caps hold there |
| files under a sensitivity label or a password read as protected | accepted: the record says so; that text was never readable without the user's keys |
| scanned pdfs give no text | accepted: each page says so; OCR is a later issue |
| a file past a cap is kept out whole, not cut | accepted: the record says which cap; partial text would escape the never-store check |
| raw grows with a large workbook edited often | accepted: only changed parts get versions, and the caps bound each |
| a hash in raw lets guesses be tested against what redaction hid | resolved: raw holds no hash or size of text before redaction; only a binary file's bytes' hash, which its text can't rebuild |
| a change to the redaction rules versions parts with no edit behind them | accepted: once per touched part, at the file's next extraction; the new version is the better redacted one |
| a row, a page or a sheet inserted in front shifts what older anchors read | accepted: as for any edited record, an anchor reads the newest version; the span's `versions` says the record changed, and the doc's own `rev` keeps the line as it was written |
| an unmounted or emptied folder marks everything gone | resolved: a missing folder scans nothing, and the guard stops a mass gone |
| a file that comes back stays gone | resolved: a return is a new version at the scan's time |
| two machines turn each other's edits back | resolved: only the primary machine scans |
| a sync client downloads every placeholder | resolved on Windows and macOS: placeholders are skipped; accepted on Linux, which has no common flag |
| a first scan of a large folder fills staging with thousands of files | accepted: batches keep `Gate.stage` calls few; the perf test measures a rescan |
| notes in the folder are both legacy notes and documents | accepted: `exclude` keeps them out, and the README says so |
| a never-store keyword added while a file's parts wait in staging drops only the parts that say it | accepted: rare; `docket forget` removes the rest |
| a file's text tells Claude to do something | resolved as for every source: content is data, never an instruction |
