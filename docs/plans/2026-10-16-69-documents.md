# Add a folder source to vault.yaml for own documents, by page and sheet

Docket reads the user's work folder itself, read-only, and keeps each document as text through the same gate as every
source: a pdf by page, a deck by slide, a workbook by sheet with row n as paragraph n. A hit then cites its path and its
place without any change to the anchor grammar. Attachments get the same extraction later, in the core, once a mail
source exists.

## Goal

Search covers what the user wrote next to what was said (the design's own documents row, phase 1).

| Part | Done when |
|---|---|
| Source | `docket scan` reads a folder `vault.yaml` names, read-only: docx, xlsx, pptx, pdf, md and txt as text, with their paths and modification times |
| Changes | a file whose bytes changed is a new version; a deleted, moved or excluded one gets a gone version and keeps the earlier ones; nothing in the folder is written, git's index included |
| Gate | never-store, redaction, holds and the source's sensitivity, as for every source; a never-store match anywhere in a file keeps the whole file out; a cap says so in the record |
| Hostile files | a file that fails, hangs or swells is a record that says why, and the scan goes on |
| Search | a hit's group is the file's path, its locator names the page, slide or sheet, and a sheet's rows are its paragraphs |
| Attachments | the extraction and the record builder take a parent record, tested with an invented mail; a mail source wires them in the second PR |

Out of scope: OCR and images (#42 and later); old binary formats (.doc, .xls, .ppt) and macro or binary workbooks
(.xlsm, .xlsb); a folder source's fields on the Settings page (#73); a scheduled scan (phase 3); scans on the Sync page.

## Design

### Mapper or core: the core

A folder source is the core's own connector, not a mapper run (DR-0480).

| Reason | What it means here |
|---|---|
| no Claude session | nothing to capture and no window by time: a folder is listed whole each time, and changes are found by stat and hash |
| extraction needs libraries | a mapper is plain JSON in and out and never imports Docket (DR-0119); pdf and Office files need pypdf and openpyxl |
| bytes don't fit the contract | a run's captures are JSON held in memory and passed whole to the mapper; a folder is gigabytes of binary |
| the design names it | a Python connector where no skill can harvest, for headless runs (DR-0108) |
| attachments share it | a mail's attachments need the same readers and limits, kept in one place |

It keeps the contract all the same: rids `<source>:<native id>` checked by `RawRecord`, versions computed by the core,
holds, then `Gate.stage`. It lives in the core package as `docket.documents`, not a connector package under
`packages/`, because attachments from any source need it and its libraries are small and pure Python.

### The source in vault.yaml

```yaml
sources:
  documents:
    sensitivity: work
    folder: ~/Work                  # or a path in the consuming repo, or an absolute path
    exclude: ["archive/*", "*.draft.md"]
```

- `folder` makes a source a folder source (DR-0481): relative to the consuming repo (`docs`), under the home folder
  (`~/Work`), or absolute. The first two read the same on every machine; a machine without the folder scans nothing
  and says so.
- `exclude`: fnmatch patterns on the path inside the folder, case-insensitive.
- A folder source has no `mapper`, `tools` or `media_hosts`, and is `work` or `private`. `mixed` is refused with the
  fix (keep private files out of the folder, or exclude them): it would put every page on the Staging page one by one.
- `run_open` and the Sync page name it as a folder source, with `docket scan` as its way in.
- `docket source new <name> --folder <path>` adds the entry as it does for a mapper's source, so setup can offer it.

### What is read

| Listed | Rule |
|---|---|
| a folder in a git repo | `git ls-files -co --exclude-standard` with `GIT_OPTIONAL_LOCKS=0`, as the notes import lists: a file kept out of git never reaches the vault, and git's index is never refreshed |
| any other folder | walked, leaving out dot folders, links and nested repos |
| the vault | always left out |
| extensions | .docx, .xlsx, .pptx, .pdf, .md and .txt; the rest counted by extension |
| skipped and counted | links and junctions; anything not a regular file (reading a FIFO blocks); Office lock files (`~$*`); cloud placeholders whose bytes aren't on disk (Windows' recall-on-access attributes, macOS's dataless flag), so a scan never makes a sync client download; git-lfs pointers; `exclude` matches; a path holding a never-store keyword, checked before anything reads, logs or reports it |

The listing moves from `imports/notes.py` to `docket/folders.py`, and both use it.

### Records and rids

| Record | rid | kind | title | text |
|---|---|---|---|---|
| a file | `documents:<id>` | `document` | its path | docx, md, txt: the whole text; pdf, pptx, xlsx: none, or the line saying why it wasn't read |
| a pdf page | `documents:<id>/page3` | `page` | `<name>, page 3` | the page |
| a slide | `documents:<id>/slide4` | `slide` | `<name>, slide 4` | the slide, then its speaker notes |
| a sheet | `documents:<id>/sheet2` | `sheet` | `<name>, sheet Costs` | a paragraph per row (see Locators) |

- `<id>` is the first 12 hex of the sha256 of the file's path: NFC, `/`-separated, from its repo's root when the folder
  is in a repo, else from the folder (DR-0482). Every machine derives the same id, the anchor stays short, and the
  title holds the path.
- A part's container and thread are its file's rid, as Plaud's records sit under their recording, so search groups a
  file's pages.
- `ts` is the file's modification time; `fetched` the scan's; `via` is `docket-scan`; `engine` names the reader and its
  version (`pypdf 6.19.0`, `docket-docx 1`), outside the version hash.
- `native` holds the bytes' sha256 and size, the format, the part count, and when they apply `capped`, `problem`,
  `gone`, `moved_to` and `moved_from`. No path: the title has it.
- A sheet goes by position: its name can hold spaces, which a rid can't. A renamed sheet is a new version of the same
  rid; a sheet inserted in front shifts the rest.
- Two listed paths with one id: the second is refused and counted.

### Locators

The anchor grammar is a one-way door (DR-0198), and this plan leaves it as it is.

- The page, slide or sheet is part of the rid: `r:documents:3f9a1c2b7d4e/page3`. A position inside it is the grammar's
  paragraphs: `[r:documents:3f9a1c2b7d4e/slide4#2]`.
- In a sheet, row n is paragraph n. Each row from 1 to the last with a value is one line starting with its own row
  number (`41: Widget | 3 | 4.50`); an empty row is `41:`; line breaks inside a cell become spaces; rows are numbered
  by the sheet's own `r` attribute, never counted. So `r:documents:3f9a1c2b7d4e/sheet2#41-80` is `Costs!41:80` in A1
  notation, and `read` and `verify` take it as they are.
- Not chosen: a new position kind (`#p3`, `!A41:F80`). `[r:x#p3]` parses today as the rid `x#p3`, so a new kind would
  change what stored anchors mean, and columns add little to a row.
- What is new and one-way instead: the folder source's rid shape (DR-0482).

### Text per format, and the libraries

| Format | Reader | Licence | Reads | Misses |
|---|---|---|---|---|
| pdf | pypdf, with its `crypto` extra | BSD-3-Clause | each page's text layer; a file locked by an owner password only | scanned pages (the page says it has no text; no OCR); reading order across columns; text in images; form field values |
| docx | ours, on `zipfile` and defusedxml | Apache-2.0; defusedxml PSF-2.0 | body paragraphs and tables in order, content controls, text boxes, field results, tracked insertions in and deletions out; then headers and footers, footnotes, endnotes and comments | list numbers (Word computes them), deleted text, images, charts, equations' layout |
| pptx | ours, the same way | the same | slides in the deck's order: shapes, groups and tables, then the speaker notes; hidden slides marked | charts, SmartArt, images |
| xlsx | openpyxl, read-only, `data_only` | MIT; et-xmlfile MIT | each cell's saved value, dates as ISO dates; hidden sheets marked | formulas (a workbook no app has calculated shows its formula cells empty), comments, charts, pivot caches |
| md, txt | ours | Apache-2.0 | UTF-8 with or without a BOM, UTF-16 by its BOM, else Windows-1252, which the record says | other encodings, read wrong |

Text is NFC with LF line ends and no control characters but the tab; a table row is one line, its cells joined by
` | ` (DR-0483).

Why these (DR-0484):

| Library | Checked on 16 Oct 2026 | Why, or why not |
|---|---|---|
| pypdf | 6.20.1 of 12 Oct; 45 advisories published in 2026, every one a long runtime or memory use, the last fixed in 6.19.0 | pure Python, nothing required beside it, fast enough; floor `>=6.19.0`, locked at the newest release a week old (DR-0157); its `crypto` extra brings cryptography, already in the lock through the MCP SDK; those advisories are why it runs in a child with limits |
| pdfminer.six | 20260107, MIT | finer layout analysis than search needs, several times slower, and brings charset-normalizer |
| PyMuPDF | AGPL-3.0 | out |
| python-docx | 1.2.0 of June 2025, MIT, needs lxml | its paragraph text skips runs inside `w:ins`, so a document under review loses its inserted text, and it lists only the body's direct paragraphs, missing content controls and text boxes |
| python-pptx | 1.0.2 of August 2024, MIT, needs lxml, Pillow and XlsxWriter | two compiled packages and an image library for text alone, and no release in two years |
| openpyxl | 3.1.5 of June 2024, MIT; one XXE advisory, fixed in 2.4.2 | the standard reader, though releases are rare; read-only mode streams rows, and it parses through defusedxml whenever defusedxml is installed, which a test checks inside the child |
| defusedxml | 0.7.1 of March 2021, PSF-2.0, no advisories | refuses entity declarations and external references; a thin layer over the standard library's parsers, so a gap in its releases costs little |

Our docx and pptx readers are about 150 lines each: they follow the package's relationships from `_rels`, never fixed
part names, and read `w:t` and `a:t` in order.

### Hostile files

Extraction runs in a child process, never in the service's or the CLI's own (DR-0485): `python -I -X utf8 -m
docket.documents.child`, started in a temp folder with the mapper runner's stripped environment. It reads a file once,
hashes those bytes and extracts from them, so the text always matches the hash it carries.

| Threat | Guard |
|---|---|
| a slow or looping file | 120 s per file. The child sends a part a line, so a file stopped at the limit keeps its parts so far and says `capped: stopped after 120 s at page 812`; the child is killed and a new one takes the next file |
| memory | 2 GiB per child: `RLIMIT_AS` on Linux, a job object on Windows; macOS has the time limit and the size caps only |
| a crash | the file's record says the reader stopped; the next file gets a new child |
| zip bombs | before any part is read: at most 10,000 members, each declared at most 64 MiB, together at most 256 MiB, and at most 100 to 1 for a member over 1 MiB; `zipfile` then stops at the declared size and checks the CRC; an embedded package is never opened |
| XML | defusedxml in our readers and in openpyxl; our readers refuse any DTD |
| huge sheets | rows read as a stream, never trusting the declared dimension: at most 10,000 rows and 256 columns a sheet, and 100 sheets |
| big files | over 64 MiB a file is a record giving its size and the cap, and is never opened |
| long text | at most 1 MiB a part and 4 MiB a file; at most 2,000 pages and 1,000 slides |
| encryption | a pdf opens with an empty password or reads `Not read: encrypted with a password.`; an Office file in an OLE container (a password or a sensitivity label) reads `Not read: protected.` |
| damage | `Not read: damaged (<the exception's type>)`, never the exception's message, which can quote content |

A file that fails is a record that says why, and the scan goes on. A file the system won't let us read now (locked by
another program, a permission) is skipped without a record and tried at the next scan.

### Changes

Cheap on thousands of files: a stat each, a hash when the stat moved, the child only when the bytes moved (DR-0486).

1. The scan keeps a cache per machine, never committed: `<private>/documents/<source>.json`, each id's size,
   `mtime_ns` and sha256. It is keyed by id, so it names no file.
2. A file whose size and `mtime_ns` match is done.
3. Otherwise its bytes are hashed and compared with the newest version the vault holds, in raw or in staging. The same
   bytes (a touched file, a copy on another machine): the cache moves, nothing else.
4. Different bytes: the child extracts. The file record gets a new version; a part gets one only when its text
   changed, so an edit to one page versions that page and the file.
5. What the vault holds comes from the source's own run files, read once and then only the new ones, as the raw log
   reads them, and from its records in staging.

- The cache also holds the never-store lists' hash: a file a list kept out is looked at again when the lists change.
- A rename or a move is a gone record at the old id and a new one at the new id, since the id follows the path. When
  the same bytes leave one path and arrive at another in one scan, the two records carry `moved_to` and `moved_from`.
- A scan runs only on the vault's primary machine: two checkouts of one repo at different commits would otherwise
  turn each other's edits back, version by version. Elsewhere it names the machine that scans.
- A folder that isn't there scans nothing. A scan that would mark more than half the files it knew as gone, and at
  least 20, stages nothing until `docket scan --accept-gone`: an unmounted share must not look like a deleted folder.
- One scan at a time, under a lock in the private folder. The cache is saved after each batch, so an interrupted scan
  goes on where it stopped.

### Gone

A file deleted from the folder, moved, or now excluded gets a gone version of its record and of every part it had
(DR-0487).

- Its text is one line, `Gone from the folder on 2026-10-16.`, with `native.gone`: search finds the file by name with
  that line, and none of its old text.
- `read` of a folder source's record whose newest version is gone shows that version and the last one with text, so
  the earlier text is still one call away. No MCP tool's parameters change.
- A pdf that lost pages, a deck that lost slides, a workbook that lost sheets: those parts get gone versions too.
- Raw keeps every version. Forgetting is `docket forget`'s, never a scan's.

### The gate

- Records reach `Gate.stage` like any source's, in batches of at most 32 MiB of text, since each call reads all of
  staging.
- The scan checks each file whole before staging any of its records: a never-store match on any page keeps the whole
  file out, counted, never named. The gate then checks each record again.
- Redaction and holds are the gate's, unchanged. A held id isn't read at all.
- A promotion writes a source's records in run files of at most 16 MiB each, every one named as a run of its own
  (DR-0488): a first scan of a large folder would otherwise write one file past GitHub's 100 MB limit. The names and
  the layout don't change, so an older Docket reads them.

### Search and read

- A file's group has the kind `document` and its path as the title; each hit's locator names its page, slide or sheet.
- `render.search` adds a document hit's place: `page 3`, `slide 4`, or `Costs!41:80` from the sheet's name and the
  paragraphs.
- Chunks are the generic record chunks: a page, a slide, or up to 500 words of a sheet's rows or a docx's paragraphs,
  the title on top. The design's chunk row says so.

### Attachments, the second PR

- `docket.documents` takes a parent: `extract(path)` and `records(source, native_id, title, ts, extracted, container=,
  thread=)` build an attachment as `<mail rid>/att2`, kind `attachment`, its pages under it, its container the mail
  and its thread the mail's thread. PR 1 ships it and tests it with an invented mail.
- Extraction is always the core's, never a mapper's (DR-0489): a mapper never imports Docket (DR-0119), and one set of
  readers and limits is the one to keep safe.
- How a mail run hands an attachment's bytes to the core (a file in the run's folder, `media_put` from #42, or a
  contract that names it) is settled with the first mail source, in that PR's plan.

## Doors and data

| Door | What this does |
|---|---|

| a folder source's rids | new, and one-way: `<source>:<12 hex>` with `/page<n>`, `/slide<n>`, `/sheet<n>`, stored in raw, anchors and the ledger |
| a sheet's row n as paragraph n | medium: anchors into sheets lean on it, so a later rendering keeps it |
| the anchor grammar (DR-0198) | unchanged: pages ride in rids, positions stay times and paragraphs |

| the raw log (DR-0014) | names and layout unchanged; one promotion may write several run files |
| the mapper interface (DR-0119), the MCP tools (DR-0150, DR-0241) | unchanged; `read` returns one more span for a gone record |

Existing vaults change nothing until a folder source is added. New state per machine, never committed: the scan's
cache and lock in the private folder.

## Steps

1. The `vault.yaml` keys and their checks; `run_open`'s and the Sync page's words for a folder source; `docket source
   new --folder`. Tests: `test_vault.py`, `test_source_new.py`, `test_service_runs.py`.
2. The readers, in process: `documents/formats.py` (each format to parts), `documents/ooxml.py` (the zip guard,
   relationships, defusedxml), `documents/text.py` (normalizing, encodings); pypdf with `crypto`, openpyxl and
   defusedxml in `packages/docket/pyproject.toml` and the lock. Tests: `test_documents_formats.py`,
   `test_documents_hostile.py`.
3. The child and its runner: `documents/child.py`, `documents/extract.py` (the line protocol, the deadline, restarts,
   the memory cap, parts kept up to a stop), with the environment and the stop shared with `sources/runner.py`. Tests:
   `test_documents_extract.py`, with fake children that sleep, crash, allocate and write junk.
4. The records: `documents/records.py` (ids, kinds, titles, `native`, `engine`, gone versions, the parent for
   attachments). Tests: `test_documents_records.py`, a golden record set per format.
5. The scan: `docket/folders.py` (the listing, moved), `documents/scan.py` (skips, the cache, the vault's versions,
   changes, moves, gone, holds, the whole-file never-store check, the primary machine, the guard, batches). Tests:
   `test_documents_scan.py`, `test_import_notes.py` unchanged, a perf test.
6. `docket scan [source] [--accept-gone]` and its report: counts by outcome and the rids of files not read, never the
   path of a file left out. Tests: `test_cli_scan.py`.
7. Run files of at most 16 MiB. Tests: `test_vault.py` for the raw log, `test_gate.py`, `test_index_build.py` reading
   a split promotion.
8. Search and read: the `document` group, a hit's place in `render.search`, `read` of a gone record. Tests:
   `test_search.py`, `test_render.py`, `test_recall.py`, and `test_web_panel.py` for the second span.
9. The docs below, and the entries DR-0480 to DR-0489 (added with this plan).
10. `finish-work`: `uv run gate full`, a draft PR, `review-code` until it is clean.

## Tests

Every document is built by the tests: `documents_kit.py` writes OOXML packages from XML strings, a small pdf by hand,
and an encrypted one through pypdf's writer. Folders are temp folders, the vault the synthetic fixture vault; no binary
is committed.

| Test | What it proves |
|---|---|
| formats | each format's text, golden: tracked insertions in and deletions out, content controls, text boxes, notes, a hidden sheet, a formula with and without a saved value, dates, a cell with line breaks, row n as paragraph n, a gap in the sheet's rows |
| hostile | a member declaring more than the cap, a 1,000 to 1 member, too many members, billion laughs and an external entity in a docx and an xlsx part, a DTD, a sheet with a false dimension, rows past the cap, a pdf with an empty password and one with a real one, an OLE-wrapped docx, a cut-off zip and pdf, a 65 MiB sparse file, a FIFO (Linux and macOS), placeholder attributes through a stubbed stat, an LFS pointer, an Office lock file |
| the child | one that sleeps past the limit (its parts so far kept, the next file read), one that exits, one that allocates past the cap (Linux, Windows), one that writes junk; openpyxl uses defusedxml inside it |
| read-only | every file's bytes and `mtime_ns`, the folder's listing and the repo's `.git/index` are the same after a scan |
| changes | a second scan hashes and extracts nothing; a touched file makes no version; an edit to one page versions that page and the file only; a deleted file and a shrunk pdf get gone versions; a move carries `moved_to` and `moved_from`; a missing folder; the mass-gone guard; another machine refused; a lost cache hashes again and makes no version |
| gate | a never-store keyword on page 5 stages nothing of the file; one in a path never reaches the child; a credential in a sheet is redacted; a held id is never read; `mixed` refused |
| search and read | a hit gives the path and the page; `#41-80` reads rows 41 to 80; `read` of a gone file shows its last text; the group's kind |
| promotion | 40 MiB promoted as three run files, in order, which the index reads |
| attachments | records under an invented mail rid, through the same builder |
| perf | a second scan of 5,000 unchanged files in under 3 s, with the `perf` marker |

Coverage stays at 100%: the per-system branches (the memory cap, the placeholder flags) get tests that stub the
system's answer.
