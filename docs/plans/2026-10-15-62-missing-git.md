# Never recreate a missing git dir, and never commit a folder vault into an outer repo

## Goal

A vault whose git dir went missing stays reported as missing: no write of Docket's makes a folder under a git dir that
isn't there, and Open counts a `.git` only when git would use it. Measured on main, a write through an open repo vault
whose `.git` was deleted fails at its commit but leaves `.git/docket/tmp` behind, and the next `Vault.open` succeeds.

A folder vault whose host lost its `.git` is refused too, when Open would otherwise take the repo above the host
for it.

- In scope: every writer of Docket's private files, in both modes; Open, `Vault.find` and `stopped_convert`; Open's
  check that a folder vault's `vault.yaml` is tracked in the repo it found; the tests.
- Out of scope: convert's own checks of the vault's `.git`, since with this change nothing makes a fake one
  mid-convert.

## Design

### One test, one helper

In `vault/home.py`:

- `is_git_dir(path)`: git's own test for a git dir (`is_git_directory` in git's `setup.c`): a `HEAD` file, `objects/`
  and `refs/`. A `.git` holding only Docket's folders fails it, and git skips such a folder and looks further up.
- `make_private(git_dir, folder)`: makes a folder for Docket's own files, and refuses with a `DocketError` naming the
  git dir and saying to restore it when `is_git_dir(git_dir)` is false. It never makes the git dir itself.

### Every place that makes a folder

| Site | Makes | After |
|---|---|---|
| `lock.py:33`, `VaultLock.__enter__` | the lock's folder: `.git` itself in a repo vault (the lock is `.git/docket.lock`), `<host git dir>/docket/<vault path>/` in a folder | `make_private(self.git_dir, ...)`; every write takes the lock first, so a write stops here |
| `rawlog.py:142`, `_write_new` | `tmp/` | `make_private` with its lock's git dir |
| `staging.py:117`, `write_replacing` (hold lists, release log) | `tmp/` | takes the vault's `Home` instead of its temp folder |
| `staging.py:142`, `Staging.write` | `tmp/` | `Staging` takes the `Home` |
| `config.py:229`, `write_config` (`source new`, redaction settings) | `tmp/` | takes the `Home` |
| `docstore.py:496`, `_replace` | `tmp/` | `make_private(vault.home.git_dir, ...)` |
| `machine.py:53`, `remember` (init) | the private folder | takes the `Home` |
| `git.py:215`, sync's marker | the private folder | `make_private(home.git_dir, ...)` |
| `git.py:239`, `_hooks_off` | the private folder | refuses instead of skipping, so Docket's add and commit never run in a repo git found above a missing git dir |
| `convert.py:93`, `State.save` | the host's private folder | `make_private(where.git_dir, ...)` |

Left as they are, none under a git dir: `rawlog.py:143` (`raw/`), `staging.py:202` (`staging/`), `docstore.py:497`
(`processed/`), `holds.py:142` and `releaselog.py:208` (`state/`), `vault.py:183,190` (init's tree),
`index/build.py:479` (`index/`), `host.py:220,224` (a scratch repo in a temp folder), `convert.py:277` (git-lfs's
store, reached only after a fetch into the host has worked).

### Open

- `Vault.find`, `_own_repo` and `stopped_convert` test `.git` with `is_git_dir` instead of `exists()`. A `.git` an
  older Docket left with only its own folders is refused as missing; the message says the `.git` holds no repository.
- `_folder` keeps refusing any `.git` in a folder vault: one has no business there, Docket's or git's.

### Folder vaults

Their private folder is under the host's git dir, so the same helper covers them: with the host's `.git` gone, the
lock refuses. Measured on main, a write through a folder vault whose host's `.git` was deleted made
`host/.git/docket/notes/vault/` with `tmp/` and `hooks-off`, and its add staged the run file in the repo above the
host. Open was never fooled there: git skips the half-made `.git`.

### A folder vault in the wrong repo

Opened fresh, the same vault is taken for a folder of the repo above its host, and Docket commits there. Measured on
main: `host/notes/vault/raw/...` landed in the outer repo's `HEAD`.

- `Vault.open` of a folder vault checks that its `vault.yaml` is tracked in the repo it found (`git ls-files
  --error-unmatch`), and otherwise refuses, naming the vault and that repo, and saying either to restore the lost
  `.git` or, for a vault moved there on purpose, to commit its `vault.yaml` first.
- A tracked answer is kept per process by (git dir, vault path), so the service, which opens the vault on every call,
  pays one git call. An untracked one is never kept: restoring the `.git` works without a restart.
- Init and convert never go through `Vault.open` before their first commit (init resolves its `Home` itself; convert
  finds the vault with `Vault.find`), so neither needs an exemption.

### Not taken

- Testing that the git dir is a folder, as `_hooks_off` does today: the folder the lock makes passes.
- `git rev-parse --git-dir` on every write and open: a process for what three stats answer.
- Calling a `.git` missing when it holds only Docket's names: any other leftover would pass.
- The lock alone: init's machine file and convert's state are written outside it.

## Doors and data

None. Where Docket's files live (DR-0141) and what `storage` means (DR-0140) stay as they are; Open's refusal of
`storage: repo` without a `.git` now also covers a `.git` git won't use, which can't commit today either. No stored data
moves. A vault an older Docket left with only its folders in `.git` is reported as missing until the real `.git` is
restored over them.

The decision is in `packages/docket/index.yaml`, proposed, by Claude (autonomy grant), from this branch's block that
starts at DR-0270:

| Id | Decision | Cost |
|---|---|---|
| DR-0270 | Docket never makes a vault's git dir, and a `.git` counts only when git would use it | cheap |
| DR-0271 | Open refuses a folder vault whose `vault.yaml` the repo it found doesn't track | cheap |

## Tests

In `test_home.py`, on the kit's vaults:

- The issue's: a repo vault inside a host repo, its `.git` moved away; `write_run` through the open vault raises; the
  vault has no `.git` and no new run file; `Vault.open` still says there is no `.git`; the host's `HEAD` is unchanged.
- The folder twin: a folder vault whose host sits inside an outer repo, the host's `.git` moved away; `write_run`
  raises; the host has no `.git`; the outer repo's index and log are empty.
- A leftover: a vault's `.git` holding only `docket/tmp` and `docket.lock`, as main leaves it. `Vault.open` refuses it
  as missing, `Vault.find` still finds the vault by its `vault.yaml`, and another tool's `vault.yaml` beside such a
  `.git` is no vault. A stopped convert still points at `docket vault convert` with such a `.git` in the vault.
- The writers: one test per row of the table, parametrized, each called with the git dir gone; each raises and leaves
  no `.git`.
- The outer repo, the measured shape: a folder vault whose host sits inside an outer repo with a commit, the host's
  `.git` deleted; `Vault.open` refuses, naming both, so the write never starts, and the outer repo's `HEAD` and index
  are unchanged. A second open of a healthy folder vault in the same process runs no git call for the check.
- Changed: `test_edges.py`'s held-lock test, `test_staging.py`'s fixture and `test_config_machine.py`'s machine test
  run `git init` instead of making an empty `.git`, which now fails the test.

Coverage stays at 100% for `docket`.

## Risks

| Risk | Status |
|---|---|
| A repo vault whose `.git` is a file (a submodule's link) is now refused at Open as missing | accepted: Docket can't keep its files under a file today, and its first write already fails |
| A `.git` without `objects/` because `GIT_OBJECT_DIRECTORY` points elsewhere reads as missing | accepted: git's `init` always makes `objects/` |
| A folder vault moved into another repo by hand is refused until its `vault.yaml` is committed there | accepted: the message says what to commit, and a vault that isn't in its repo's history is one Docket can't trust to be there |
| Each process pays one more git call on its first open of a folder vault | accepted: tens of milliseconds, once per process and vault |
| A service opened before a convert moved the vault's `.git` writes during the convert | resolved: the write now refuses; before, it made a `.git` the convert's resume took for the vault's own |
