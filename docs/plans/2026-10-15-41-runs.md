# Run syncs through the service with runs, captures, cursors and the ingest tool

## Goal

A source syncs live from any Claude Code session. `run_open` opens a run, names the source's skill and gives the run's
steps; the plugin's capture hook posts what the source's tools return, as given, into the service's memory; `ingest`
closes the run, maps it in the mapper's own process and stages the records through the core's checks, holds and the
gate. A run that comes up short, fails or never closes is dropped and its window fetched again. A whole one moves its
machine's cursor, committed in the vault.

- In scope:
  - the MCP tools `run_open` and `ingest`, and their REST routes;
  - open runs in the service's memory: bind, captures, close, drop, expiry;
  - the PostToolUse capture hook, `docket hook post-tool-use`, and a console entry that keeps it cheap;
  - the run's steps, given by `run_open` for every source;
  - cursors: `state/cursors-<machine>.yaml` with the mark, the lookback, the retry and waiting sets;
  - each of #10's eight hand-over rows to the service;
  - the Plaud reference: its `SKILL.md`, its mapper's `final` rule, its copy in the wheel, and the blank template;
  - tests on invented payloads, the Plaud example's included.
- Out of scope:
  - the plugin's `sync` skill and reconciling the ledger, where a close names the raw record that answered (phase 3);
  - the Sync and Staging pages (the web app's issues); records wait in staging and `docket staging list` shows them;
  - `media_put` and media on hold (#42);
  - replacing a captured result with a short stub in Claude's context (Risks);
  - the deny hook for `docket hold release` that #31 deferred to these hooks: still deferred (Not taken).

### One sync run

| Step | Who | What |
|---|---|---|
| open | Claude | `run_open("plaud")`, alone: the run's id, its window, the skill's path, the skip lists, the budget, the steps |
| bind | the hook | on `run_open`'s result, ties the run to this session and agent; Claude sees `docket: run <id> is this session's` |
| read | Claude | the source's `SKILL.md`, by the path given: the source's own calls, paging and limits |
| fetch | Claude | the source's own tools, within the budget |
| capture | the hook | posts each successful listed call's input and result as given; Claude sees `docket: kept capture <n> ...` |
| close | Claude | `ingest(run, captures=<the highest n seen>, skipped=[...])` |
| map | the service | the mapper in its own process; the core's checks, holds and the gate into staging |
| cursor | the service | the mark, the retry and waiting sets, the cursor file committed |
| promote | the user | as for any staged record: nothing reaches git before the gate |

Claude never retypes a payload, and nothing of a capture reaches a commit before the gate classifies it. Ids that have
waited more than 7 days get a run of their own after that one: `run_open(source, final=true)`, each id fetched by id,
no listing, no window, and a close that never moves the mark.

### Runs

A run lives in the service's memory from `run_open` to `ingest` (DR-0240).

| State | Entered by | Left by |
|---|---|---|
| open, unbound | `run_open` | the hook's bind, within 60 seconds; else dropped |
| open, bound | the bind | `ingest`; or dropped |
| closing | `ingest` | closed, staged and the cursor moved; dropped; or back to open (below) |
| dropped | a count that doesn't match, a run marked short, a failed close, 30 minutes with no capture, 6 hours open, a newer `run_open` of its source, a second run bound to its session and agent, the service stopping | its captures freed, nothing staged, the mark kept |

- The run's id is `run-<yyyymmddThhmmss>-<16 hex>`, random, in `Manifest.run`'s pattern.
- A run is bound to Claude Code's `session_id` and, inside a subagent, its `agent_id`. One open run per source on the
  machine, and one per session and agent. Where step 1 finds no `agent_id`, the steps say to run one source at a time
  in a session.
- A newer `run_open` of a source replaces its open run, so a session that crashed mid-run doesn't block its source; the
  replaced run's close says why it is gone. A closing run is never replaced or expired: that `run_open` is refused.
- Captures are held tagged with the run and numbered in the order they arrive; a second post with the same
  `tool_use_id` is ignored, so a retried hook never counts twice. A capture refused from the bound session (a cap, a
  tool not listed) marks the run short, and its close drops it.
- A service restart drops every open run: the registry is memory and the marker is deleted at start. Claude sees no
  more `kept` lines, which the steps treat as a stop, and `ingest` answers `no open run <id>: the service restarted or
  the run was dropped; nothing staged, the mark stays`.
- Each finished run's outcome, its `RunClosed` or why it dropped, stays in memory for an hour, so a repeated `ingest`
  gets the truth.
- Nothing of a capture goes to disk or to a log through Docket: no spool, no temp file, the mapper's input on its stdin
  pipe. Claude Code's own session log keeps every tool result it showed Claude; that is Claude Code's, outside Docket,
  as for `hold show` (DR-0204).

### The capture hook

```json
{"PostToolUse": [{"matcher": "mcp__.*", "hooks": [
  {"type": "command", "command": "docket", "args": ["hook", "post-tool-use"], "timeout": 30}
]}]}
```

Added beside SessionStart in `plugin/hooks/hooks.json` (DR-0242). It runs for MCP tools only, synchronously. Claude
Code runs the hooks of parallel calls at once, so the steps have Claude call `run_open` alone and wait for its bind
line before any source call.

| The call | What the hook does |
|---|---|
| a tool named `run_open` under any server prefix, its result in the shape of docket's `RunOpened` | posts the bind with `session_id` and `agent_id`; the service binds only a run it opened; line: `docket: run <id> is this session's` |
| any other MCP tool, and `runs.json` names no run of this session and agent listing the tool's own name | nothing: no token read, no request, no output |
| a listed tool of this session's run, its result whole | reads the token, posts the capture; line: `docket: kept capture 7 of run <id> (get_transcript), 182 KB of 400 KB` |
| a listed tool whose result isn't whole (a file reference, a truncated result) | posts nothing; line: `docket: not kept: get_transcript (too large)` |
| that post refused, the run gone, no service | line: `docket: not kept: get_transcript (<reason>)` |
| anything unexpected | line with the error's type, never its message |

- The tool's own name is what follows `mcp__<server>__`: `mcp__plaud__get_note` and `mcp__plugin_x_plaud__get_note`
  both give `get_note`, the name `vault.yaml` lists (DR-0124). Docket's own tool is
  `mcp__plugin_docket_docket__run_open` from the plugin, or whatever name a user's own entry gives it.
- The capture is `tool_input` as `arguments` and `tool_response` as `result`, unchanged, with `tool_use_id` and the
  time. The mapper reads whichever shape Claude Code gives (`structuredContent`, a content list, text), as Plaud's
  `unwrap` does today.
- The hook posts only a result it can tell is whole; step 1 records the shapes Claude Code gives a result over 50,000
  characters, and those are refused. A failed call (an MCP error result) fires PostToolUseFailure, not this hook, so it
  gets no line and isn't counted; step 1 checks that.
- The line goes to Claude in `additionalContext`. The prefixes `docket: kept capture` and `docket: not kept` are bound
  in DR-0242, since the steps quote them. It never prints a result, never blocks or replaces the output, and exits 0.
- `runs.json` in Docket's state folder lists each open run's id, source, session, agent and tools: ids and names, never
  content. The service writes it through a temp file and a rename, retried as staging's writes are, before the route
  answers. A read that fails is retried for 100 ms, then taken as no run.
- The no-run path is the common one, on every MCP call of every session. `docket.entry:main` becomes the console
  script and answers it with the standard library and platformdirs only: it finds the state folder without yaml, and
  `docket.__version__` turns lazy through a module `__getattr__`, so `importlib.metadata` isn't read at import. Typer,
  keyring, pydantic, yaml and `docket.index` load only on the run path. The command's name doesn't change, so no door
  moves.

### Security on localhost

The run routes sit behind DR-0152's checks and add their own (DR-0243):

| Check | Refuses |
|---|---|
| Host is `127.0.0.1:<port>` or `localhost:<port>` | a site rebinding its name to 127.0.0.1 |
| a write's Origin and Sec-Fetch-Site, when sent, are this origin; OPTIONS answered 405; no CORS header | any page of another origin |
| the bearer token, and never the session cookie | a page of the web app, an XSS in it included, and another user of the machine |
| the bind once, within 60 seconds of the open, for a run the service opened | a late, second or made-up bind |
| a capture only from the bound session and agent, for a tool the source listed when the run opened | another session's call of the same tool, such as the user browsing recordings at the same time |
| 32 MiB a capture and 256 MiB across open runs, counted while the body streams, so a body with no Content-Length stops at the cap | a flood: the capture is refused and its run marked short |

Can another local process post captures into a run? Yes, a process running as the user can, as it can write the vault
itself: it reads the token from the keychain or its file (DR-0152 accepts that) and the run from `runs.json`. A capture
it adds alone breaks the run's count, so the run is dropped rather than taking it; one that also closes the run with
its own count gets its captures mapped, and they go through the mapper's own checks, the core's, the holds and the
gate into staging, never into raw. Another user has no token; a web page can't send one; nothing off the machine
reaches 127.0.0.1. While the service is down, a process of another user that binds its port gets what the hook posts,
the same accepted risk as the token helper's; the hook posts only when the marker names an open run, and the service
deletes the marker when it stops.

### Closing: the mapper and the gate

`ingest` checks, maps, stages, then moves the cursor (DR-0244).

1. The run is open and bound, not short, and the captures that arrived equal the count. Otherwise it is dropped: `the
   manifest counts 12 captures and 11 arrived; the run is dropped and nothing is staged; the next run fetches them
   again`.
2. A folder, when given, passes the folder rule below.
3. The manifest is the run's: `source` and `window` from the run, the rest from `ingest`'s parameters.
4. `ingest_run`'s steps: the folder's hold file, if any, on the writer; the mapper on a thread of its own for at most
   90 seconds; the core's checks, holds and `Gate.stage` on the writer.
5. On the writer, under the vault lock: the retry and waiting sets, the mark, the cursor file committed.

| When | The run |
|---|---|
| another close is mapping (one at a time) | refused at once; the run stays open and its idle clock restarts |
| the vault lock times out before anything is staged | back to open; the answer says to call `ingest` again |
| a mapper past its time, a crash, refused output, a held record waiting in staging | dropped, the mark kept; the mapper's stderr is neither logged nor returned, and the error says to run its tests |
| staged, the cursor written, its commit failed | closed; `RunClosed` says the mark moved but isn't committed, and the next close commits it |
| staged, the cursor not written (a lock, a file another program holds) | closed; `RunClosed` says the mark didn't move, and the next run fetches the window again while the gate skips what staging or raw has |

- 90 seconds, not DR-0123's 300, because the plugin's MCP entry gives every Docket tool call 120 seconds (DR-0160),
  and `ingest` should answer within it. A run that needs more goes in through `docket ingest`, which keeps 300.
- The gate is unchanged: `mixed` sources wait in staging to be classified, never-store and redaction apply at intake,
  releases cut a released recording (DR-0201).

The folder rule (DR-0250): `ingest`'s folder is taken only when its real path, links followed, is a folder `docket
ingest` read for that source on this machine, or under one, and outside the vault; `docket ingest` records each folder
it reads in the private folder (DR-0248). It replaces #10's row, a folder `vault.yaml` names: `vault.yaml` is shared by
every machine, and a folder's path belongs to one. It is no wall against a process running as the user; it keeps the
MCP route from reading a folder nobody imported by hand.

### Cursors

Each machine commits its own file; a run starts from the furthest point any machine reached (DR-0245, DR-0246).

```yaml
# Where this machine's syncs reached. Docket writes it after each whole run; ids and times only.
schema_version: 1
sources:
  plaud:
    mark: "2026-10-15T09:12:00Z"
    lookback_days: 7
    retry:
      - {id: of_00c0ffee00c0ffee00c0ffee00c0ffee, reason: later, since: "2026-10-14"}
    waiting:
      - {id: of_00decaf000decaf000decaf000decaf0, for: summary, since: "2026-10-13"}
```

| Rule | What |
|---|---|
| where | `state/cursors-<machine>.yaml`, the path the layout already names (DR-0141) |
| written | only by its machine, through a temp file in the private folder and a rename, never through a link; committed alone as `Cursors: <source> on <machine>`, naming no id, once per whole close that changed it |
| merged | git's default text merge, which takes two machines' edits to different sources cleanly; a conflict needs two clones with one machine name (the host name is the default), and then this machine's read stops on the markers until the user keeps one side, the one with the older mark being safe |
| read | this machine's file fails closed: a bad line, an unknown key, an unquoted time, a conflict marker or a link refuses `run_open`, naming the file and the line number; another machine's file that doesn't read is left out and `run_open` says so, since its marks only shorten a window |
| window | from the latest `mark` of any machine's file, leaving out a mark later than this machine's clock (named in `notes`), less this machine's `lookback_days` (7 when Docket writes it), to the moment the run opened; with no mark, from now less the lookback; `run_open(since=...)` starts it elsewhere |
| the mark | moves to the run's open time on a whole close that kept at least one capture and whose window started no later than that default; a dropped run, a failed close, a close with no captures, a narrower `since` or any final close leaves it |

The retry and waiting sets (DR-0247), on a whole close:

| Set | Gains | Loses |
|---|---|---|
| retry | each `skipped` entry with an id that isn't held, with its reason and first date; a re-skip takes the newer reason and keeps the first date | ids the run reached (a record under it, a waiting or set-aside entry), unless the run skipped them again; held ids; ids whose reason isn't `later` after 30 days, `gone` among them, named in `RunClosed` as expired |
| waiting | the mapper's waiting ids, less held ids, the ids the run skipped (they stay in retry) and the ids the run was told to skip | ids the run reached with a record, unless the mapper reports them waiting again; held ids; on a final close, every entry older than 7 days at its open, whatever it gave, named in `RunClosed` as expired |

- The ids a run was told to skip are its window's whole kept set, worked out at open and kept with the run, less the
  ids waiting then. `run_open` hands Claude only part of it, or none (`kept` below), but the close uses all of it.
- `gone` is the reason for an id a by-id fetch found missing at the source (not found, or an error): a recording the
  user deleted leaves retry after 30 days and waiting at its final close, so nothing asks for it forever.
- `run_open` hands over this machine's sets and, while another machine's mark is under 30 days old, that machine's
  waiting entries as its file lists them and its retry entries under which raw and staging hold no record yet. A new
  laptop picks up what a retired one left, for a month. Held ids are left out of every set it hands over.
- The sets are committed with the mark, since a private set is lost with a clone and a mark taken from another machine
  skips past it.

A final run, `run_open(source, final=true)`, has no window and no listing. It hands over only the waiting ids older than
7 days and the retry ids older than 7 days whose reason isn't `later`, from this machine and others by the rules above;
each is fetched by id, the close is `final`, and it never moves the mark.

A skill closes a run only after its listing reached the window's start. One that can't finish stops without closing:
the run drops and the mark stays.

### What `run_open` answers

```
run      run-20261015T091200-3f9a1c2e4b5d6e7f  plaud
window   2026-10-08T09:12:00Z to 2026-10-15T09:12:00Z
skill    D:/work/project/.claude/skills/sources/plaud/SKILL.md
tools    list_files, get_file, get_transcript, get_note
budget   400 KB of results
held     2: rec-held-01, rec-held-02
kept     6: of_00c0ffee00c0ffee00c0ffee00c0ffee, of_00c0ffee00c0ffee00c0ffee00c0ffee/summary, ...
waiting  1: of_00decaf000decaf000decaf000decaf0 (summary, since 2026-10-13)
retry    none
notes    none

How this run goes:
1. Wait for "docket: run <id> is this session's" after this answer; without it the capture hook isn't running: stop.
2. Follow the skill above for this source's own calls. Skip held ids, and kept ids unless waiting; fetch retry and
   waiting ids by id.
3. List until the window's start. Each successful call of a listed tool gets "docket: kept capture <n> ...". A
   successful call of a listed tool with no docket line: stop without closing.
4. "docket: not kept: <tool> (too large)": put that item in skipped as too-large and go on. Any other "not kept":
   stop without closing.
5. Past the budget, fetch no new item; put each one left in skipped as later.
6. Close: ingest(run, captures=<the highest n you saw>, skipped=[...]). Stopping without closing is safe: the run
   drops in 30 minutes and the next sync covers the window again.
7. After closing this run: run_open(source, final=true), and fetch only the ids it gives, each by id.
```

- The steps are the same for every source and live in Docket, so a source's `SKILL.md` never goes stale on them
  (DR-0251, DR-0252). The server's instructions carry the first and last of them.
- A final run's answer has no window, `kept` or listing step: its steps are 1, then fetch each id it gives by id within
  the budget, a missing one as `gone`, then `ingest(run, captures=<n>, final=true, skipped=[...])`.
- `held`: the hold list's ids (DR-0121).
- `kept`: the native ids of the source's records in raw (the index, brought up to date first) and in staging whose
  `ts` falls in the window. A run opened with `since`, which is for a backfill's listing, gets none. The skip lists
  save calls; the core stays the control (DR-0249).
- Every list has its room, so the whole answer stays under about 20,000 characters: `kept` 8,000, `held` 1,500,
  `waiting` and `retry` 3,000 each, the oldest owed first. Past its room a list says it is incomplete; the run keeps
  every id, and a final close expires only the ids its answer showed.
- `budget`: 400 KB of captured results a run, so a run doesn't fill Claude's context; each `kept` line says how much
  is used. It bounds the items fetched, never the listing, which a close needs whole.
- `notes`: a cursor file of another machine left out, a mark from the future left out, `kept` incomplete.
- Refused before any work: a source not in `vault.yaml` (the answer lists those that can run), disabled, `private`,
  with no `mapper` or no `tools`, no `SKILL.md` in its folder, this machine's cursor file unreadable, a held record of
  it waiting in staging, its run closing, `since` and `final` together. A `SKILL.md` without the marker line the
  current reference and template carry, `<!-- docket: steps from run_open -->`, is refused too: `copy the reference's
  SKILL.md and mapper.py over yours`, or, for a source with no reference, the blank template's run sections.

### The tools and the routes

| MCP tool | Parameters | Returns |
|---|---|---|
| `run_open` | `source`; `since`, optional, a date or a time as `search` takes it; `final`, false, a final run with no window | `RunOpened`: the run, window, skill, tools, budget, held, kept and whether it is whole, waiting, retry, notes, the steps |
| `ingest` | `run`; `captures`, 0 or more; `final`, false; `skipped`, `{id, reason}` items; `folder`, optional | `RunClosed`: the `docket ingest` report's counts and ids, the mark before and after, the retry and waiting counts, the ids that expired, whether it repeats an earlier answer |

Both are annotated as writes that destroy nothing, return compact text beside their model (DR-0159), and join
`fixtures/mcp-tools.json` (DR-0241). A failed close is a tool error naming why, ids and counts only.

| Route (bearer token only) | Does |
|---|---|
| `POST /api/runs` | opens: `source`, `since`, `final`, and `session` and `agent` for a caller that knows them (the CLI, tests) |
| `POST /api/runs/{run}/session` | the hook's bind |
| `POST /api/runs/{run}/captures` | one capture: `session`, `agent`, `tool_name`, `tool_use_id`, `arguments`, `result`, `captured` |
| `POST /api/runs/{run}/close` | the same call as `ingest` |
| `GET /api/runs` | open runs: id, source, bound or not, captures and bytes, times; never content |

`/api` stays Docket's own and no door (DR-0151). `ingest` shares `ingest_run` with `docket ingest`: one path for the
hold steps and the checks.

### The source skill

A source's skill stays at `.claude/skills/sources/<source>/SKILL.md`, read by path (DR-0168), and `run_open` is how a
session reaches it (DR-0251). It now holds only what is the source's own; the run's steps come from `run_open`.

| Section | Plaud reference | Blank template |
|---|---|---|
| marker | `<!-- docket: steps from run_open -->` | the same |
| sign in | "not authenticated" means the server's `login` tool | how signing in looks |
| list | `list_files` newest first, no date filters, until a page's oldest `start_at` is before the window's start | the same rule, for its listing |
| each item | every `get_transcript` page of `transaction_polish` with `limit` 100, following `next_cursor`, else `transaction`; then `get_note`; then `list_files` again after the last note | the calls that fetch an item whole, paged under 50,000 characters a result |
| by id | for retry and waiting ids: `get_file`, then the transcript and the notes; not found or an error: skip it as `gone` | how one item is fetched by its id, and what "gone" looks like |
| rate limits | `429`: pause and retry with growing pauses; still limited in the listing, stop without closing; on one recording, skip it as `rate-limited` | what a limit looks like |
| backfill | after `docket ingest plaud <folder>` in the user's terminal: `run_open(since=<the oldest backfill day>)`, the listing only, `ingest(run, captures, folder=<folder>)`, without `final`: backfill files are final by themselves | none |
| what it makes, changing the mapper | unchanged | unchanged |

- Plaud's `limit` drops from 500 to 100 utterances, which step 1 checks stays under 50,000 characters a page in the
  example's payload shape, so no result reaches Claude Code's file threshold.
- The Plaud mapper applies `final` only to a recording the run fetched by id (`get_file`, `get_transcript`,
  `get_note`) or that has a backfill file. A recording the run only listed gives no record. When its `start_at` falls
  inside `manifest.window` it is reported waiting `{id, for: fetch}`; outside the window, or with no window, it gives
  nothing. The close drops a `fetch` entry the run was told to skip or skipped, like any waiting id.
  - A final run never stores a bare recording it didn't fetch, and an old item on a listing's last page never joins
    the waiting set: S1 and S2 stay fixed.
  - A listed item nobody fetched is still caught: a backfill run's listing over recordings the folder lacks (a
    backfill that ends on 1 Oct, live runs from 20 Oct), or an item Claude forgot to skip; the next run fetches it by
    id.
  - Records for fetched recordings don't change, so no version moves.
- A project's copy from before this change is refused by `run_open` until it is refreshed: an old `SKILL.md` pages at
  `limit` 500, which the hook now refuses as too large. The CHANGELOG and both READMEs say to copy the reference's
  `SKILL.md` and `mapper.py` over the project's after upgrading.
- `test_scaffold_templates.py` keeps the wheel's copy byte for byte.

### #10's hand-over

| Row | Status |
|---|---|
| a run's captures: in memory, tagged with their run until the manifest closes it, nothing verbatim on disk or in logs | done: Runs (DR-0240) |
| closing a run: a count that doesn't match drops the run, as does one the service doesn't hold after a restart; the mark stays | done: Runs, Closing |
| a failed mapper: drop the captures, keep the mark, never log stderr | done, with the service's limit at 90 seconds (DR-0244) |
| the window: the mark less 7 days, the start kept until a run finishes | done: Cursors (DR-0246) |
