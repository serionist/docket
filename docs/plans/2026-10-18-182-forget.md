# Forget a record for real, on every clone

`docket forget` takes a record, everything under it and the audio it is in out of the vault's current tree, deletes
the audio's keys, and keeps it out for good on every clone through a committed list of hashes that the gate, every
reader and the index obey. By default it only shows what it would take; it forgets with `--now`, at the owner's
console, with a code typed back. The text stays in the host repo's history, and forget says so and writes the
rewrite for the owner to run in a fresh clone (DR-0102).

## Goal

| The issue's part | This plan | PR |

| Tombstone | `state/forgotten.jsonl`, one line per forget, merged by union: rid hashes, version keys, folder files' identities, media rid hashes, key ids, legacy notes' old path and body hashes | 1 |
| Media | stored and staged files out of the tree, this clone's keys deleted, every other clone's at its next gate call, its reader or its service's start; exports and imports skip listed keys | 1 |
| Staging | the family's staged versions and media dropped, its rids marked withheld | 1 |

- In scope: a folder vault, the default, and a repo of its own the same way until #58 pushes one.

## Design

### The command (DR-0577)

```
docket forget <rid>...      [--vault <path>] [--now]
docket forget --never-store [--source <name>] [--vault <path>] [--now]
docket forget --held        [--source <name>] [--vault <path>] [--now]
docket forget --check-rewrite <folder> [--vault <path>]
```

`--check-rewrite` is read-only and needs no console: it says whether the history rewrite a forget wrote leaves HEAD
as it is (The history, below).

| Part | Rule |
|---|---|
| without `--now` | the dry run, in any shell, Claude Code's too. It writes nothing but the index's own update, as a search does |
| `--now` | refused before anything is read in Claude Code's shell, without a console on stdin and stdout, or through a pipe or a redirect (`console.problem` with a new act, `console.FORGET`) |
| the question | the screen, then one code for the whole forget: `console.typed_back` today, `console.confirm` once #143 merges |
| under the lock | the plan worked out again; any difference from the screen stops it with nothing written: "the vault changed since the screen; run it again" |
| kinds | one per call; `--source` only with `--never-store` and `--held` |
| a rid | staged, in raw, or with records under it; "nothing stored as <rid>" otherwise; one already forgotten says so |
| no other door | no page, route or MCP tool forgets, and only `cli.py` calls `forget()`: a test scans for it, as for `release()` (DR-0202) |

Not chosen:

- `--yes`, or a confirm parameter: Claude passes a flag as easily as the owner (DR-0202).
- The question by default, the dry run only on n: Claude Code's shell would get a refusal instead of the counts it
  shows the owner.
- `--dry-run`, forgetting by default as `docket doc redact` does: a deleted key can't come back, so the short command
  is the safe one.
- An MCP tool: nothing over MCP can give the owner's yes.

### The family (DR-0578)

| Kind | What it takes |
|---|---|
| a rid R | R and every rid under `R/`, every version, staged or in raw; the media staged or stored on R and on each rid R sits under, as any drop of a version takes it (DR-0547), with every key of those files; the machine transcripts made from that media (`<that rid>/whisper`), which hold the same speech. R and each rid it sits under go on the list's `media`: no media is stored on them again |
| a rid under a hold not released | its versions in raw, the uncut copies stored before the hold, and the media staged or stored on it and on each rid it sits under, with every key, listed. Nothing goes on `media`, and the hold stays, so its release can still let a cut version and its cut audio in |
| a folder source's file or part (`<source>:<12 hex>`, the hash of its path, DR-0482) | its versions, staged and in raw, its parts following their file, and its identity as `native` holds it (DR-0483): the bytes' sha256 for pdf, docx, xlsx and pptx, the redacted text's for md and txt. That content stays out at any path, after a reader changes or the scan's cache is reset too; a changed file, or a new one at that path, comes in. The dry run says so, and to move the file out of the folder, since forget never writes there |
| `--never-store` | each rid with a version in raw that a list in force matches now (DR-0521), as its kind above says |
| `--held` | each rid in raw under a held id not released, the ingest's `held_in_raw`, as a held rid |

- `docket forget plaud:<id>` takes the recording, its transcripts, its notes, its Whisper transcript and its audio.
  `docket forget plaud:<id>/<block>` takes that transcript, the audio and the Whisper transcript, and the dry run says
  the recording itself stays and how to take it whole.
- Rid nesting only, as media's family: a Slack reply never takes its thread or its channel.
- A file's keys: the stored file's from its header, else its media cut log line; every key the cut log names for
  those rids (files a recut replaced); a staged sidecar's. A stored file that is an LFS pointer with no cut log line
  naming its key stops the forget, naming `git lfs pull` for it: a key forget can't name can't leave other clones.

What stays, and why:

| Thing | Stays because |
|---|---|
| entities | names and ids the owner curated, never what was said, and later records use them. The dry run counts those no other record mentions, and the `--now` screen names them with the curate ops whose locators all lie in the family, each with its `docket curate undo <op>` |
| the curate log | names, counts and locators, never a snippet (DR-0460); a locator to a forgotten rid reads as forgotten. A round's snippets come from the index, so none comes from the family after the rebuild |
| hold lists, release logs | ids and times; a hold still keeps out what it covers by thread or container |
| the media cut log | hashes, key ids and times; it is where forget finds every key ever stored for the family |
| `_decided.jsonl`, the speech queue's tried file, the run history | hashes or ids on one clone |
| other machines' cursor files | each machine writes only its own (DR-0245) and drops its own retry and waiting entries under listed rids at its next gate call |

### The list (DR-0579)

`state/forgotten.jsonl`, one line per forget, written through a temp file and a rename and committed alone before the
forget changes anything else:

```json
{"schema_version": 1, "rids": ["<32 hex>"], "versions": [{"rid": "<32 hex>", "key": "<32 hex>"}],
 "files": ["sha256:<64 hex>"], "media": ["<32 hex>"], "keys": ["<64 hex>"], "old_paths": ["<32 hex>"],
 "import_hashes": ["sha256:<64 hex>"], "at": "2026-10-18T09:14:02Z", "machine": "desk"}
```

| Field | Means |
|---|---|
| `rids` | staging's rid hash of each rid forgotten whole: it and every rid under it, every version, now and later |
| `versions` | one version each, by the rid's hash and staging's key of rid and version: a held rid's uncut copies, a folder file's and its parts' versions. A release's `keep` of that exact version beats it, being the owner's later word at the console |
| `files` | a folder file's identity as `native` holds it, its key and value: `sha256:` for its bytes, `redacted_sha256:` for its redacted text. A file record with that identity stays out at any path, and so do the parts under it |
| `media` | the hashes of the rids no media is stored on again: each rid forgotten whole and every rid it sits under |
| `keys` | the media key ids (DR-0549) every clone deletes |
| `old_paths` | the hashes of the old paths of the legacy notes a forget removed |
| `import_hashes` | each removed legacy note's `import_hash`, its redacted body's hash, which its frontmatter holds already, so nothing new enters git. With `old_paths`, what `docket import notes` refuses for good, a note renamed, moved or copied included |
| `at`, `machine` | when and where, as a release line has them |

- Merged by the vault's own `*.jsonl merge=union` (DR-0142): no attribute line to add, and an older Docket's cursor
  reader skips the file by its name.
- Hashes only: never a rid, a path, a key or a wrapped key. A history rewrite takes the raw lines out of history; the
  list stays in it for good, and a rid can name a channel or a host.
- Fails closed as a release log: a line that isn't one, or the file or `state/` a link, stops every ingest and every
  gate call, named by its line number.
- In force: HEAD's lines and the disk's together, read as `inforce` reads `vault.yaml` (DR-0521), HEAD's cached by its
  commit id. A line on disk that HEAD lacks acts at once and is committed by the next gate call. A line HEAD has and
  the disk lacks still acts, is named as a problem ("restore it with git checkout"), and Docket never commits the
  file while it lacks one: an edit only adds.
- A line with only `keys` is the apply's, for a key no line names (The order of writes), and retention's later; every
  field but `at` and `machine` may be empty.

What reads it:

| Reader | Does |
|---|---|
| every reader of run files: `RawLog`, `RawLookup`'s load, the index build, `vault.status`, the gate's cut scan, the notes import | skips a listed line, so a line a union merge brought back reads as gone at once |
| the index | built under the list's digest; the build and `read` drop docs' lines by the docs' rule (below) |
| intake, `Gate.stage` | drops a listed record in memory before every other rule, counted as `forgotten`: by its rid, its version, or a folder file's identity, its parts with it; a whole rid's media dropped and withheld, as for never-store |
| the sweep | drops a listed staged version and its media |
| media's screen and reader | refuse media on a listed rid or a `media` rid; the reader gains the state `forgotten`, and the Recording page says "This recording was forgotten" |
| the reader, the service's start, `docket media keys export` and `import` | the reader and the service's start delete any listed key they meet; an export leaves listed keys out, and an import skips them, each counted (DR-0595) |
| `docket import notes` | refuses a note whose old path's hash is listed, or whose redacted body hashes to a listed `import_hash`, `--take note` included |
| `read`, `verify` | say a listed rid was forgotten |
| run file caches (`RawLog`, the gate's cut scan) | keyed by path, size and modification time, not path alone, since a forget changes a run file in place |

Not chosen:

| Shape | Why not |
|---|---|
| plain rids | they stay in history after a rewrite |
| a list per source, as hold lists | a never-store forget spans sources, and the hash hides which already |
| a `.txt` list with its own union line | every existing vault would need a `.gitattributes` edit |
| a separate key-id file | each forget writes both, and one line keeps a forget's parts together |
| the disk's list alone | an edit that deletes a line would bring a record back at once, a loosening by edit DR-0521 never allows |
| HEAD's list alone | the line a failed commit left on disk must act already |

### The index (DR-0593)

The index can't tell a forget from run files' sizes and times alone: the list can move while no run file does (a
crash after the list's commit, or clone B pulling a line while the record sits in its own unpushed run file), a
rebuild can fail (on Windows `_replace` gives up after 5 s while the embedding pass holds the file, and the service's
updater keeps the old index), and `docket search --no-update` reads what is there.

| Part | Rule |
|---|---|
| the digest | `expected_meta()` gains `forgotten`: the sha256 of what the build reads from the list in force, sorted: `rids`, `versions`, `files`, `media`, `old_paths` and `import_hashes`. Never `keys`, `at` or `machine`, so a keys-only line, an apply's now or retention's expiry later, rebuilds no index, and a merge that only reorders lines changes nothing |
| `update` | an index built under another digest is stale, so it rebuilds, as for another schema |
| `open_index`, `lookup.open_read` | refuse an index built under another digest: a search refuses ("the index is being rebuilt; run docket index rebuild") rather than answers, and `read` takes the load route, which skips listed lines |
| the build | leaves out listed records, their chunks, segments, mentions and vectors, the docs' lines the docs' rule drops, with their dependents through `derived_from`, and a legacy note whose old path or body hash is listed, as the apply removes it |
| `read`, a final decision's HEAD read | drop the same lines, so a doc the apply hasn't rewritten yet reads as it will |

### The order of writes (DR-0581)

All under the vault lock, after the question and the plan worked out again:

| Step | What | A crash after it leaves | The next gate call |
|---|---|---|---|
| 1 | the list's line, through a temp file and a rename, fsynced | the line on disk, in force | commits it, then applies it |
| 2 | its commit, alone: `Forget: the list from <machine>` | the list in git; the index refused until rebuilt | applies it |
| 3 | this clone's listed keys deleted | audio unreadable here | |
| 4 | staging: the listed versions and media dropped with their keys; withheld marks | | finishes it |
| 5 | the tree: run files, media files, docs, this machine's cursor file, each whole through a temp file and a rename | some files done | finishes the rest |
| 6 | one commit: `Forget: <n> record(s), <m> media file(s), <k> doc(s) from <machine>`, with a `Doc: <id> rev <n>` line for each doc it rewrote | | |
| 7 | the lock let go; the index rebuilt under its own lock; the rewrite's files and the history lines | an index under the old digest, refused | the next update rebuilds |

- Steps 3 to 6 are one function, the apply: the list against what the tree, staging and the key store hold. The
  forget runs it once, and every gate call on every clone runs it first. Nothing is ever half gone to a reader: every
  reader skips listed lines and refuses an index built before them, whatever the files say, and the next gate call
  finishes the files.
- When the apply deletes a key no line names (a clone's own stored file for a listed rid), it appends a line with only
  that key and commits it with the rest, so the clones that imported that clone's export delete it too (DR-0595).
- A run file left with no line stays, empty. Deleting it gives a modify/delete conflict in the owner's pull when
  another clone rewrote it too, which union can't settle.
- The index is rebuilt after the lock, not in it: the vault lock's waiters give up after 60 s, and the service's
  syncs would wait behind a long rebuild. Vectors carry over by hash (DR-0115), so nothing embeds again; until the
  rebuild lands, the digest keeps the old index refused.
- The apply is cheap when nothing moved: with no list, one stat. Otherwise `<private>/forget/applied.json` keeps the
  list's digest and the size and modification time of each run file, doc and media file it checked, and only what
  moved since is read again.
- A commit that fails leaves its files on disk for the next gate call. `docket vault check` names a run file changed
  only by listed lines gone as a forget not finished, not as a raw file changed after its commit.

### Two clones (DR-0581)

| On clone B | When |
|---|---|
| the list, the rewritten run files, the files gone, the docs arrive | at the owner's own pull (DR-0102) |
| every read skips listed lines, and the index built before the pull is refused | at once |
| its listed keys deleted | its next gate call, its next read of that media, or its service's next start |
| its staged copies dropped and withheld; listed lines a merge or its own run brought back removed; its own media for listed rids removed, each key read from its file's header first and listed; doc lines on the family dropped; its own cursor entries dropped; one commit, `Forget: applied on <machine>` | its next gate call |
| its index rebuilt, without the family | its next update |
| the key exports it made before | out of reach; the dry run said so. An export made from now on leaves listed keys out |

A union merge of two forgets of neighbouring lines in one run file can bring both lines back (the issue's note):
every reader skips them, and the next gate call takes them out again and commits.

### Docs (DR-0580)

An anchor is judged by where it reads, not by the rid it names. `[r:<recording>@12:08]`, and a bare `@12:08` on a
doc covering the recording, read on the transcript under the recording (DR-0370), so a forgotten transcript takes
the lines whose times land on it. At a later apply, where that transcript is gone, a time anchor on a rid the list's
`media` holds that no longer lands on a transcript counts as on the family.

| A doc | Then |
|---|---|
| a content line with a raw anchor that reads on the family | dropped in the doc's next rev, whatever else it cites |
| a line with a ref to a line dropped this way, in the rev the ref names, read from git when it isn't the current one, as pinning reads it (DR-0540) | dropped too, to a fixed point: its words carry what was said |
| a version forget's lines (a held rid, a folder file) | dropped at the forget, and by a later apply only while no version of the rid is in raw, so lines on a released cut version, or a new file at the path, stay |
| `covers` | the family's rids out |
| a confirmed or rejected decision | keeps its frontmatter, title and links, so what it superseded stays superseded; its evidence lines go; with none left it reads "its evidence was forgotten" in the decisions tool's `note`, the Briefs page and `read`, with empty `covers` and no content line (Doors and data). Forget's rev, which only drops lines, is the second rev Docket writes to a final decision, after the redact pass's (DR-0564) |
| any other doc left with no content line: a note, a brief, a proposed decision, a correction | removed; the brief skill rebuilds a brief from what is left |
| a legacy note whose every covered rid is in the family, or is a recording whose times land on a family transcript (an imported `.transcript.md` is such a note) | removed; its old paths' hashes and its `import_hash` go on the list, and the import refuses that note for good, renamed, moved or copied |
| a legacy note covering other records too | its text kept, since it has no anchors to tell its lines apart; the family out of `covers`; the dry run counts it and the `--now` screen names it, to edit by hand |
| a doc with a hand edit not taken in | taken in first, as every put does |
| a doc whose anchor run this Docket can't read and whose text holds a family rid | stops the forget, named by id and line on the screen, by type and line in the dry run (DR-0541) |

Not chosen:

- Flagging the lines built on a dropped line and leaving them (DR-0542), the issue's first idea. A flag leaves their
  words in the tree, the index and search until each brief is rebuilt, so a search finds the forgotten amount in a
  brief right after the forget. #160's refs find those lines exactly, so they go with the line they were built on, and
  the forget leaves nothing flagged. DR-0542 gains that bind.
- Judging an anchor by the rid it names: a forgotten transcript would leave every note line on its recording's times,
  and the next put of that note would be refused, its anchors reading on nothing.
- Removing a final decision left with no evidence: what it superseded would read as current again.

### The dry run

```
forget    plaud:of_0123 and 3 records under it: 7 versions in 3 run files, 1 staged
media     1 stored file and 1 staged; 3 keys, 2 of them here
docs      9 lines in 3 recording notes (4, 9, 12; 3; 7, 8, 11, 14, 20); 1 legacy note removed
built on  3 lines in 1 brief (7, 8) and 1 decision (5): dropped too
decision  1 confirmed decision keeps its title, with no evidence left
stays     2 entities nothing else mentions, 1 curate op whose locators all lie here: named at the console
history   the text stays in the history of <repo>; the forget writes how to take it out
can't     key exports made before; the LFS server's encrypted copies; the source itself; other clones until their next gate call
next      run in your own terminal: docket forget plaud:of_0123 --vault "<vault>" --now
```

- The dry run names docs by type, with counts and line numbers, never by id: a legacy note's id is `legacy-note:`
  and its old file's stem (a call's subject and names), and a decision's id carries its words. With `--never-store`,
  the matched records are counted by source, not named: which records a listed value reaches is the list's to keep.
- The `--now` screen, at the owner's console, shows the same lines with ids: docs by id, the matched rids, the
  entities and curate ops above. A doc id a never-store list names is counted there too (DR-0558).
- Each list stops at 20, then a count. Never a line's text, a title, a note's old path or a listed value.
- It brings the index up to date first, as a search does, for the entities' counts.

Every dry run names what forget can't reach:

| What | Why |
|---|---|
| key exports made before | each holds every key: make a new one, then destroy the old (DR-0550); an import skips listed keys, and a new export leaves them out |
| the LFS server's encrypted copies, and each clone's `.git/lfs` | unreadable without the key |
| chunks sent to an API provider | named when `vault.yaml` allows one (DR-0536) |
| the source itself | Plaud, the mail server, a documents or notes folder: Docket never writes there |
| git history | the history, below |
| other clones | until their next gate call after a pull |
| files outside the vault that quote it | question and speech files for `docket eval`, a Claude session that read it; with `--never-store`, docs that say a listed value without citing these records |

### The history (DR-0594)

The forget ends by saying the text stays in the history of `<repo>`, and Docket never rewrites it (DR-0102). It
writes its files to `<private>/forget/<stamp>/`, the stamp colon-free (`20261018T091402Z`) so the folder is valid on
Windows, and prints the lines to use them. Nothing in them is text from the family.

| File | Holds |
|---|---|
| `lines.txt` | `--replace-text` expressions, each blanking one line and keeping its newline: a raw run file's line by its leading `{"rid":"<rid>` field, the rid and the rids under it for a whole forget, the rid with its `"v"` for a version; a doc line dropped for a rid forgotten whole, by its own `[r:` token on that rid or its pinned `[d:...=<hash>]` ref to a dropped line. No later line can hold such a token: the rid never comes back |
| `scoped.txt` and `scoped.py` | every other dropped doc line, a version forget's (a held rid, a folder file) and a time anchor on a kept recording whose transcript went, blanked only in the blobs that held it: the blob ids recorded when the lines were dropped, each with the sha256 of each of its lines to blank, for `--blob-callback` to read. A note written later on the cut version at the same utterance times is another blob, and stays |
| `blobs.txt` | for `--strip-blobs-with-ids`: the blob of every rev of each removed doc, and each removed media file's pointer, not their paths, so a doc rebuilt later at a removed path survives |

The printed lines, in order:

- `docket forget --check-rewrite "<private>/forget/<stamp>" --vault "<vault>"`: read-only, it applies the files to
  HEAD's tree, the expressions as filter-repo's Python reads them, and refuses, naming each path and line number it
  would change, unless HEAD stays as it is;
- back up the repo;
- `git clone --no-local "<repo>" "<fresh>"`, then `git filter-repo --replace-text ... --blob-callback ...
  --strip-blobs-with-ids ...` in `<fresh>`, never in the working repo: filter-repo refuses a clone that isn't fresh,
  and its `--force` there would risk the owner's uncommitted work;
- force-push its branches from `<fresh>`, then re-clone every machine, this one too;
- the remote keeps commits a force-push left behind, reachable by their ids: on GitHub until its support purges them,
  and in forks and pull request refs;
- other branches of the repo keep the text, with no list line to keep it out of their trees;
- `git filter-repo` isn't Docket's dependency: install it to run this. A repo of its own is the same until #58.

### Alternatives

| Not chosen | Why |
|---|---|
| the index trusting run files' sizes and times alone | the list moves without a run file moving, and a failed rebuild keeps the old index answering |
| a targeted delete in the index instead of a rebuild | every line after a removed one moves its byte offset (DR-0445), and a reply in a thread window re-chunks its thread; a rebuild gives the same rows by construction |
| deleting a run file left empty | a modify/delete conflict in the owner's pull |
| a held rid forgotten whole | its release could never let the cut version in |
| a folder file forgotten whole | its rid is its path's hash: every later file at that path would stay out |
| a folder file by its version keys alone | a version key comes from the extracted, redacted text: a changed reader or a reset scan cache re-reads the same file into a version no line lists |
| a version forget's doc lines matched by their token | a note written later on the released cut version at the same utterance times holds the same token, and HEAD would lose it |
| keys in the index's digest | a keys-only line changes no row, yet would rebuild every clone's index and refuse its searches meanwhile |
| taking the rid's ancestors' records too | a Slack message's rid sits under its channel |
| removing entities only the family mentions | an entity is a name the owner curated; the screen names them and their undo instead |
| a rewrite by rid anywhere in a blob | it blanks a kept reply whose thread names the rid, curate locators, cursor ids, a held rid's released cut version, and lines outside the vault |
| removing docs from history by path (`--invert-paths`) | a doc rebuilt later at that path goes too |
| running filter-repo on the working repo | it refuses a clone that isn't fresh, and `--force` risks the owner's uncommitted work |
| a forget that waits for every clone | clones are offline; the list reaches each at its pull |
