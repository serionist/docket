# Ask for an OS prompt before a release or a loosening

The owner's yes becomes the system's own prompt (Windows Hello; Touch ID, the watch or the login password; polkit)
wherever the machine has one set up, through one call in `docket/console.py`. The code typed back stays where none
is. The console's refusals stay first, and once a prompt is set up nothing falls back to the code.

## Goal

| Part | The issue's "done when" | This plan |
|---|---|---|
| One call | one `docket.console` call asks for the prompt, and the release and the loosening both use it | `console.confirm`, in place of `typed_back` at every caller; confirm-cuts and the key export use it too (Which steps ask, below) |
| Three systems | it works on all three, with the console code as the fallback where no prompt is set up | Windows Hello through ctypes, LocalAuthentication through rubicon-objc, polkit through `pkcheck`; the code only where the system reports none set up |
| Tests | the fallback on each system, and the prompt where CI can fake it | each system's answers with its calls faked, on every runner; the real availability check in CI on each system; the real polkit path in Linux CI, with a rule that answers |

- In scope: `docket/osprompt/`, `console.confirm`, its four callers, a line in `docket vault status`, the polkit
  action file, the docs, the CI steps.
- Out of scope:
  - the console's refusals (`CLAUDECODE`, a pipe or a redirect): unchanged;
  - minting a browser session, the key import, `models install --api` and `models key`: no prompt (DR-0575);
  - a yes that Docket's own code can't be tampered with around: nothing running as the owner can promise it (What
    it stops, below);
  - the release line's and the commits' format: unchanged.

## Design

### The call

`console.confirm(act, lines, do, keep, kept)` is the one question (DR-0572):

| Step | A prompt set up | None set up |
|---|---|---|
| refused | `CLAUDECODE` set, or no console on stdin and stdout, as today | the same |
| the screen | shown | shown |
| the console asks | `Press Enter to <do> with Windows Hello, n to <keep>, q to stop:` | `no OS prompt on this machine: <why>`, then `Type ABCD to <do>, n to <keep>, q to stop:` |
| the yes | the prompt's verified answer | the code typed back |
| a cancel, a failure, no desktop, Ctrl+C, 2 minutes with no answer | a no that names why; never the code | - |

- The prompt shows the act's own line, such as `Docket: release a held recording`, and never a value from the vault.
- Asked outside the vault lock, as the code is (DR-0519). One prompt per question: a release of five recordings asks
  five times.
- `typed_back` stays as the branch without a prompt, and `asker` stays for the reference source's copied tests.

### The three systems

`docket/osprompt/` finds a prompt without showing anything, and asks it (DR-0573):

| System | Set up when | Asks with | Dependency |
|---|---|---|---|
| Windows 10 1709 and later | `CheckAvailabilityAsync` answers `Available` | `IUserConsentVerifierInterop.RequestVerificationForWindowAsync`, the desktop's form, with the terminal's window | none: ctypes into `combase.dll`, the IIDs from the SDK's headers |
| macOS | `canEvaluatePolicy` with `LAPolicyDeviceOwnerAuthentication` | `evaluatePolicy`: Touch ID, an Apple Watch or the login password, a fresh context each time | `rubicon-objc` 0.5.7: BSD-3-Clause, pure Python, 64 KB, no dependencies, macOS only |
| Linux | Docket's action file is in polkit's actions folders, and `/usr/bin/pkcheck` exists | `/usr/bin/pkcheck --process <pid,start-time,uid> --allow-user-interaction --enable-internal-agent`: the desktop's agent, or with none a text agent at the console | none: polkit's own `pkcheck`, by its absolute path |

- Windows: the `IAsyncOperation` is polled through `IAsyncInfo` on a worker thread with its own `RoInitialize`. The
  window is the console's root owner under Windows Terminal, else the foreground one; the hardware test picks.
- Linux: one action, `io.github.serionist.docket.confirm`, `auth_self` for any, inactive and active sessions; never
  `auth_self_keep`, which passes again for five minutes. Its message is fixed in the file ("Confirm the step Docket
  shows in your terminal"), as polkit refuses a message from a caller that isn't root. The file ships in the
  package, and `docket vault status` prints `sudo install -m 0644 <file> /usr/share/polkit-1/actions/`.
- Not chosen: pywinrt (a runtime and a package per namespace, and no interop interface for a desktop process),
  pyobjc (several MB, compiled), a Swift or C helper (a build per system, signing on macOS), polkit over D-Bus with
  jeepney (no text agent, so nothing asks over SSH), pkexec's own action (asks for an admin, says a program runs as
  root), one action per act (each new act would need the file installed again).

### Fallback, and no opt-out

The system decides, at each question (DR-0574):

| System | The prompt | The code | Refused |
|---|---|---|---|
| Windows | `Available` | `DeviceNotPresent`, `NotConfiguredForUser`, `DisabledByPolicy`, no interop interface | `DeviceBusy`, any error |
| macOS | `canEvaluatePolicy` true | `passcodeNotSet` | any other error; rubicon-objc not loading, since removing it must not give the code |
| Linux | the action file and `pkcheck` there | either missing | - |

- Once a prompt is set up the code is never asked: a failed prompt is a no, and the owner runs the command at the
  machine. Over SSH on Linux, `pkcheck`'s text agent asks the password at the console.
- No flag, variable, config key or token picks the code: whatever an owner's switch reads, an agent running as the
  owner flips (DR-0520).
- What decides set-up takes the owner's factor or root to change: Hello is removed in Settings after the PIN or the
  password, and polkit's folders are root's. An owner who wants the code back removes the factor.

### Which steps ask

| Step | Asks the prompt | Why |
|---|---|---|
| `docket hold release` | yes | DR-0202 |
| a loosening through `rewrite`: `redaction set off`, `source new`, `media host add`, `media folder add`, `models allow` | yes | DR-0517 |
| `docket media confirm-cuts` | yes | it lets in for good audio an old private classification may have kept out (DR-0561) |
| `docket media keys export` | yes, before the file is written; the last four letters are still typed back after | every key leaves the clone (DR-0550) |
| `docket media keys import` | no: console only | the passphrase is the factor; no key leaves, nothing reaches git |
| `models install --api`, `models key` | no: console only (DR-0539) | nothing is sent until the vault allows it, and that asks |
| minting a session (`POST /api/session`, `docket open`) | no | below |

Minting a session stays DR-0564's floor (DR-0575):

- a session can't release or loosen (DR-0382, DR-0506); what it adds over the token is a decision's click, which
  lets nothing in, and the token already reads everything over MCP;
- the route is the service's, with no console or window of the owner's to anchor a prompt;
- `docket open` runs many times a day, and a prompt each time teaches a yes without reading;
- a browser agent works in the owner's own signed-in browser, so it needs no session minted.

### What it stops, and what it doesn't

The prompt says a person answered, not that Docket's code is intact. On every system a process running as the owner
can still patch Docket, or import it and call the internals: the floor DR-0202 accepts. What ends is the common way
round the console check, a pseudo-terminal of the agent's own with `CLAUDECODE` cleared, reading the code and typing
it back.

| System | What a process running as the owner can still do | Human-only |
|---|---|---|
| Windows | start the prompt while the owner faces the camera, where face recognition may pass with no act; type into the PIN box, or log the PIN, if the dialog takes same-user input; with an admin owner, a UAC bypass that turns Hello off by policy and gets the code | a fingerprint, yes; the PIN, only if the dialog's input is isolated; face is presence, not consent (each: the hardware test) |
| macOS | send keystrokes into the password dialog, if its terminal has Accessibility and the dialog takes them, and only with the password known | Touch ID and the watch, yes; the password, yes unless the process knows it |
| Linux | on X11, read or inject keys in the agent's dialog; register an agent of its own, which still needs the password PAM checks; with passwordless sudo, add a rule that says yes, or remove the file and get the code | a fingerprint, yes; the password on Wayland or at the console, yes unless known; on X11, no |

## Doors and data

- Two one-way doors change, both made stricter: the release's yes (DR-0202) and the gate's loosening (DR-0517).
  AGENTS.md's lines read "with the OS prompt, or a code typed back where the machine has none", and the PR's title
  names them.
- Stored data: none. The release line keeps its keys, and the commits keep `confirmed at the console`.
- The polkit action's id and defaults are a new contract with what owners install under `/usr/share` (DR-0573): kept,
  so a file installed once keeps working.
- Existing vaults need nothing: a machine with Hello asks it at its next release.

## Steps

1. `docket/osprompt/`: `find() -> Prompt | NoPrompt`, `Prompt.ask(line) -> Verified | Refused`, one backend per
   system, each system call behind one function. Test: `test_osprompt.py`, each system's answers with the calls
   faked, on every runner.
2. `console.confirm`; the conftest gains an autouse fixture that makes `osprompt.find` answer no prompt, and the
   `owner` fixture stands in for the prompt too. Test: `test_console.py`'s new cases.
3. The four callers move to `confirm`, and the export gains it. Tests: `test_release.py`,
   `test_console_question.py`, the confirm-cuts tests and `test_media_backup.py`, each with a prompt that verifies and
   one that cancels; `test_settings_scan.py`'s importers.
4. The polkit file as package data, and `docket vault status`'s line. Test: the status line per answer, in
   `test_cli.py`.
5. CI: the real availability check on each runner, and the real `pkcheck` path in the Linux job. Test: the
   `osprompt`-marked tests.
6. The docs (Docs, below).
7. The hardware checks with the maintainer (Tests, below), their results recorded in the plan.

## Tests

| Test | What it proves | Runs against |
|---|---|---|
| `test_osprompt.py` | each availability answer maps to the prompt, the code or a refusal; each ask's answer to a yes or a no; a timeout cancels; an error never gives the code | fakes of the system calls, on all three runners |
| `test_console.py` | with a prompt: Enter and verified is a yes, a cancel or a failure is a no with no code asked, `n` keeps, `q` stops; without: the why line and the code, as today | the fake prompt |
| the callers' tests | each caller asks through `confirm`; a no writes nothing, and the export leaves no file | the synthetic vaults, invented data |
| `test_settings_scan.py` | only `docket.console` imports `docket.osprompt`; `models/api.py` calls only `problem` | the package's source |
| `osprompt`-marked, deselected by default; CI runs them with `-m osprompt` | Windows runner: no Hello, so the code; macOS runner: `canEvaluatePolicy` answers through the binding, and `evaluatePolicy` is never called; Linux runner: no file, so the code, then the file installed and a `rules.d` rule answering yes, then no, through the real `pkcheck` | GitHub's runners |
| the terminal test in `test_console.py`, POSIX | its child process patches `osprompt.find` before Docket's main, so it still types the code | a pseudo-terminal |

No test shows a real prompt: the fixture, the child's patch, and the marker deselected on the maintainer's machine.
Docket itself reads no variable about the prompt.

On hardware, with the maintainer:

| System | Check |
|---|---|
| Windows (his) | `Available` with his Hello; the dialog in front of Windows Terminal and of conhost, for each window; whether face passes with no click; a cancel and a timeout are a no; over SSH, if he has a server, a no |
| macOS (a Mac he has, or a contributor's) | uv's Python gets the dialog, and what name it shows; Touch ID, the password; over SSH, a no |
| Linux (a desktop) | the file is picked up without a restart; GNOME's or KDE's dialog; over SSH, the text agent; a fingerprint through PAM |
