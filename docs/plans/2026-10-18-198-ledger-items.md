# Keep the ledger's items as ops in the vault

Each change to an item is one JSON line in `ledger/ops/<yyyy-mm>-<machine>.jsonl`, written once and merged by union,
so every ask, chase and close keeps its history; the index folds each item from its own lines. Its id is its add op's
ULID, and its A- number is held by that add. Two PRs: the op format, the writer and `vault check`, then the index.

## Goal

- Done: every field todo.py keeps on an item is kept as ops, each saying who made it (kind, title, who, stream,
  source, opened, due, state, until, closed, triage, description, notes, materials, outcome, the log with `by`).
- Out: meetings, points, streams and an item's `meeting` (#199); the `ledger` tool, `docket ledger batch` and history
  counts (#201); the import (#202); the pages (#203 on); a forget or retention over ops (an issue to file).

## Design

### The op line

One op per change, one line in the file (wrapped here):

```json
{"schema_version": 1, "id": "01JAB3W8Q4X5M2Z7K9R0T6YVNC", "item": "01JAB3W8Q4X5M2Z7K9R0T6YVNC", "op": "add",
 "day": "2026-10-18", "at": "2026-10-18T09:14:02Z", "machine": "desk", "by": "claude", "via": "cli", "number": 302,
 "fields": {"kind": "reply", "title": "Send Ada the dates", "who": "Ada", "stream": "pilot", "source": "chat:C0X/1"}}
```

| Key | What |
|---|---|
| `id`, `item` | the op's ULID (Ids); the item's id, its add op's `id`: every op names one item |
| `day`, `at` | the owner's day in `vault.yaml`'s zone, always; the UTC second, absent when only the day is known |
| `machine`, `batch` | the writer's, as the file name says; the first op id of its write, so a write undoes whole |
| `by`, `via`, `note` | `user` (todo.py's `me`), `claude` or `sync`; `cli`, `page`, `tool`, `import`; the why, any op |

Read as the curate log is: an unknown key is ignored, a line that doesn't read is a problem and is skipped, and
`schema_version` 2 is a later Docket's. Kinds, verdicts and streams (slugs until #199) are checked when written and
read as text. The fold never reads the clock: every date comes from `day`, `opened` too unless the add sets it.

| Op | Carries | What it does |
|---|---|---|
| `add` | `number`; `fields`: kind, title, who, stream, source; opened, due, description, notes, outcome | a new item |
| `set` | `fields`, any of add's; `null` clears an optional one | the plain fields; notes and outcome whole |
| `log` | `note`, required | a log line, nothing else |
| `triage` | `verdict`: discuss, claude, me, chase, or `null` | an open or snoozed item open with it, or cleared |
| `snooze` | `until`, a day | snoozed; triage cleared |
| `done`, `drop` | `note`, required for drop | closed on its day; triage and until cleared |
| `reopen` | - | open again; closed, until and archived cleared |
| `material` | `ref` and `label`, or `remove: true` | a path, URL or locator added, relabelled or removed |
| `archive` | - | a closed item out of the day's lists |
| `undo`, `renumber` | `of`, an op of the same item; `number` | that op left out of the fold; a new number (Ids) |

- todo.py's `notes --append` and `done --outcome` are the writer's: notes written whole, a `set` of the outcome
  before the close. An op that doesn't apply to the state it meets (a second `done` after a merge) changes nothing;
  the writer refuses one up front, as todo.py does.
- The log is every op in order, its `note` or a line rendered from it (`due: - -> 2026-10-21`); an imported op other
  than `log` shows none, since the import brings the old log as `log` ops.
- Undo: the fold reads undos from the latest back, each leaving out the op it names unless undone itself, then
  replays the rest. An undone undo is a redo, an undone add hides the item, a renumber can't be undone.
- Archive, now that history is kept, is a flag, not a move: the item leaves Today, the Queue and the Ledger's default
  lists, and search, `show` and history keep it. The sync writes it for items closed 14 days (todo.py's rule), so a
  rebuild on another day gives the same ledger; the mirror puts archived items in `_archive/`.

### Files and merging

- `ledger/ops/<yyyy-mm>-<machine>.jsonl`, the month of the op's `day`, as DR-0141 and the curate log (DR-0460) have
  it. A write replaces this machine's month file through a temp file and a rename, so a batch lands whole or not at
  all, and commits `Ledger: done A-0281, triage A-0302 on desk`, never a title, signed by `console.who()`.
- Two clones write their own files, and `*.jsonl merge=union` keeps both sides when a merge meets one file from two.
  The fold sorts by id, so any merge order gives one ledger, and a line twice is one op.

### Ids and numbers

- Order is a hybrid logical clock in ULID form: a fresh ULID, or one above the highest op id the ledger holds when
  this clock is behind, each op of a batch above the one before. An edit made after a pull sorts after what it
  pulled, whatever the clocks say, and the random bits keep two clones from minting one id.
- An item's id is its add's ULID, for good. Its number is in the add, one past the highest any item has held, as
  todo.py numbers from `meta.next_id`, so imported numbers carry on (#202).
- A clash, two clones apart both giving out A-0301: the add that sorts first keeps it, the next write anywhere writes
  a `renumber` for the other, and `A-0301` then finds its holder and says which item held it before. A number is
  never given out twice. The design's numbers handed out by the fold would move one already written in a chat.

### The fold into the index (PR 2)

| Table | What |
|---|---|
| `items` | each item's state: every field, `state`, `archived`, its number, the add's `by`, its last op |
| `item_log` | every op: item, id, day, at, by, via, kind, its keys as JSON, its log line, the undo that left it out |
| `item_numbers` | each number and the items that held it, now or before |
| `ledger_files` | each op file's size, modification time and sha256, as `run_files` and `doc_files` |

- A file that only grew, its old bytes the same, is read from where the index stopped, and the items its new lines
  name fold again from their `item_log` rows; anything else folds the whole ledger, a few thousand items in well under
  a second. Two rebuilds give one database; schema 11. The writer checks against it; `docket ledger show` reads it.

### Text and the check

- An op's text passes the gate's rules for derived text (DR-0195): redaction writes a match as its marker; a
  never-store keyword, or `who` naming someone on the people list, refuses the write, never naming the value.
- `docket vault check` names: a file in `ledger/ops/` misnamed, a link or not UTF-8; a line that isn't an op, or
  sits in another month's or machine's file; one id twice with other content; an op with no add, or sorting before
  it; an undo of another item's op or of a renumber; a number two items hold; a committed line changed or gone;
  attributes other than `merge=union` and `eol=lf`. The fold skips the same lines.

## Doors and data

Set for good, PR 1's title naming them, each entry `cost: one-way`: the folder, its file names and lines written once
(DR-0610); the op line, its keys, `by` and `via`, its kinds and what each does (DR-0611), undo (DR-0614) and archive
(DR-0615); the op's ULID and its order (DR-0612); an item's id, its add's, and its number, held by the add, renumbered
only after a clash, never given twice (DR-0613). Not doors: the index tables, the log's words, `docket ledger show`.
Data: none yet, every vault's `ledger/ops/` is empty. AGENTS.md's door list gains the ledger's line.

## Steps

1. PR 1, "Keep the ledger's items as ops in the vault (one-way door)": `ledger/ops.py`, the line and its order;
   `ledger/fold.py`, ops to items, pure; `ledger/store.py`, the one writer (a fold of the files, ids, numbers, the
   text rules, the replace, the commit, a dry run for #201); `vault check`'s part and its attribute samples.
2. PR 2, "Fold the ledger's ops into the index": the tables, the fold in `rebuild` and `update`, the writer on the
   index, `docket ledger show`.

## Tests

- PR 1: a golden line per op; each op, undo of undo, archive and reopen; a clock behind, a clash and its renumber, a
  sync batch undone whole, a refused write leaving no line, a marker in a title; only `ledger/store.py` writes ops.
- The merge property (design, How we know it works): a seeded history split across three machines, lines shuffled
  and doubled, folds to one ledger every time; two real clones merged by git give it with no conflict.
- PR 2: rebuild equals update for a grown file and a merged one; a `perf` test, 5,000 items and 50,000 ops folded in
  under a second. The fixture vault, invented people and streams only.

## Risks

| Risk | Answer |
|---|---|
| a clock runs ahead, and every later id follows it | accepted: the order stays right, `at` keeps the time |
| two machines edit one item's notes apart | the later op wins; both stay in the history |
