# Cut the test suite's time by 80%

## Goal

A PR's tests cost 77 runner-minutes and this PC's `gate os` 9.8 minutes; after this plan a PR's tests cost about 15.7
runner-minutes (-80%) and this PC's `gate os` about 1.8 minutes (-82%), and every PR still runs on Windows and macOS
whatever can differ there, plus a smoke set that touches every surface once.

| Measure | Before | After, projected | Target |
|---|---|---|---|
| CI test runner-minutes per run | 76.7 | 15.7 | 15.3 (-80%) |
| this PC, `uv run gate os --only tests` | 9.8 min (the owner's run: 9.6) | about 1.8 min: the OS-sensitive files and the smoke set | 2 min |
| this PC, the whole suite (`gate os --all`) | 9.8 min | about 2.6 min (-73%) | reported |
| push to green, a PR's median | 9.1 min | about 5 min | reported |
| the nightly full matrix | none | about 40 runner-minutes a night | reported |
| coverage | 100% for docket, 88% for devkit, per module, only rising | 90% for the whole repo; the kept suite measures about 95% | 85 to 90% |

- In scope: the CI matrix and a nightly run; the gate's selection, shares and floor; the test kit; the tests (dropped,
  merged, moved to nightly); fewer git calls in the core (PR C, which #234 left for later); docket processes in tests.
- Out of scope: the Models, the OS prompt and service, Checks, Web and Browser (Linux) jobs, 16.8 runner-minutes a run,
  which stay as they are; this PC's own settings (Defender's scanning of git.exe and the temp folders); git-lfs in the
  tests (DR-0221 stands).

## The baseline

Measured on 20 Oct 2026 on main at d9acb0f, on this PC (Windows 11, 32 threads, `-n auto`) with another branch's agent
building beside it, and on CI's last green run on main, 39426959882.

| CI, every job of the run | 93.5 runner-minutes in 36 jobs; 7.8 minutes from push to the last job |
| CI, the test jobs | 76.7 runner-minutes: Windows 42.5 in 12 shares, macOS 23.7 in 6, Linux 10.5 in 4 |
| CI, a PR's push to green | median 9.1 min, quartiles 8.2 and 10.1, over 25 green runs on 19 and 20 Oct; 25 to 34 min when runners queue |

## Design

### The levers

Each lever measured alone on this PC, then all of them in the order of the PR split on CI's recorded times, with the
shares the suite then needs:

| Lever | This PC, worker-seconds saved alone | CI test runner-minutes after it |
|---|---|---|
| before | | 76.7 |
| the OS matrix: Windows and macOS run the OS-sensitive files and the smoke set | none: it changes where a test runs, not what it costs | 42.4 |
| the timed tests on big vaults nightly | 562, and 200 s of the timed run's wall | 39.9 |
| PR C: fewer git calls in the core | 1,195 (12,728 calls) | 35.1 |
| docket processes in process | 7 | 34.9 |
| setup-heavy fixtures, the kit's commits without hooks | 1,142 | 30.7 |
| tests other tests cover, dropped | 3,788 | 18.5 |
| merges in the files the rule keeps whole | about 830 (a quarter of their time, estimated) | 16.6 |
| a share imports only its own test files | collection: 4.6 s for all 241 files here, 0.8 s for one | 15.7 |

All together on this PC: 10,793 worker-seconds to about 4,250 (-61%). The fallback if the measure at the end comes out
above 15.3: Windows in one share instead of two, 1.4 runner-minutes less and about 2 minutes more push to green.

### The OS matrix

| Run | Linux | Windows | macOS |
|---|---|---|---|
| every PR and every push to main | the whole suite, covered, one share; the floor | the OS-sensitive files, the smoke set and the small timed tests, two shares | the same, one share |
| nightly on main, `workflow_dispatch`, a PR labelled `full-matrix`, a `v*` tag | the whole suite uncovered with every timed test, beside the covered run | the whole suite with every timed test, and every page in Chrome | the same |

- The OS-sensitive files are listed in `tools/devkit/test-systems.json`, each with its reason, and the gate fails a
  test file the list doesn't name. 100 of the 241 files are on it, generously: anything doing file system, git, process,
  console, keyring, socket or encoding work, and every file in doubt. The appendix lists them.
- The smoke set is one new file, `test_smoke.py`, marked `smoke`, on a copy of the fixture vault: one case per CLI
  command group, each read from the CLI itself so a new group fails until it has one; the service started as a process
  on a free port and every MCP tool called through it, the tool list held to the golden names; a sync run with an
  ingest; a forget at the faked console; the ledger's import; a media put and its promotion in an LFS vault pushed to a
  bare remote. One browser test loads every page of both apps in the system's own Chrome and fails on a console error
  or a CSP violation. Projected: about a minute on Windows, 50 s on macOS.
- `gate os` runs the selection by default, on this PC too, and `gate os --all` the whole suite; the nightly passes
  `--all`.
- A red nightly opens an issue labelled `nightly`, or comments on the open one, from a job of its own with `issues:
  write`. A release tag runs the full matrix, and the release step, once one exists, needs it.
- Before, 66 of a run's 77 test runner-minutes went to Windows and macOS, 55% of it on files that run the same code on
  every system.

What a PR and a night cost once every lever is in, in runner-minutes, the smoke set included:

| Job | Before, per PR | After, per PR | The nightly |
|---|---|---|---|
| Linux tests | 10.5 in 4 shares | 2.9 in 1 | about 5: uncovered, with every timed test |
| Windows tests | 42.5 in 12 | 7.9 in 2 | about 21 in 4, with every timed test and every page in Chrome |
| macOS tests | 23.7 in 6 | 4.9 in 1 | about 15 in 3, the same |
| all | 76.7 | 15.7 (-80%) | about 40, once a night |

The nightly adds about 40 runner-minutes a day; the cut saves about 61 on each of the 109 runs a day, so the nightly
gives back under 1% of it. Fewer jobs a PR (from 36 to about 18) also end the queue for the five macOS runners, which
is what pushed some PRs to 25 or 34 minutes.

### Tests other tests cover

A coverage context per test (the C tracer, since `sys.monitoring` records no contexts) shows how much of the suite runs
lines other tests already run:

| Lines kept | Tests needed | Worker-seconds |
|---|---|---|
| every line the suite runs (99.34%) | 2,220 | 3,563 of 10,793 |
| 95% | 1,484 | 595 |
| 90% | 1,152 | 211 |

So lines are cheap and the time goes to tests that run them again. The cut keeps by the rule below first, then one test
of every file and the cheapest test that runs each CLI command and route handler, then the cheapest tests that bring the
statements to 95%:

| Kept | Tests | Worker-seconds, before the other levers |
|---|---|---|
| by the rule | 3,392 | 5,782 |
| and one test a file, a command and a route handler | 3,467 | 5,889 |
| and the cover to 95% | 3,647 | 5,899 |

With the tests the context run didn't see (skipped here, the browser's) kept and the timed ones moved, 3,839 tests stay
on a PR, 2,595 go and 34 move to the nightly. The appendix lists them by file. Within the files the rule keeps whole, tests
that build the same vault to check different outcomes merge, the cases of one rule shrink to the ones that differ (the
six commands of `test_console_question.py`, which `test_settings_scan.py` already proves share one writer), and their
setups become templates (`test_forget_rewrite.py`'s 101 s of setup, `test_forget_ledger.py`'s 68 s).

### PR C: fewer git calls in the core

| Call | Where | In the suite | After |
|---|---|---|---|
| `diff --cached` after the add | `Git.commit` | 3,215 | only when the commit exits non-zero: nothing new staged returns None as today |
| `ls-files -u` | `Vault.refuse_unmerged` | 3,661 | the index file's stage bits, read in `gitfiles.py`; a version or extension the reader doesn't vouch for asks git |
| `config --get-regexp ^user` | `Git._has_identity_once` | 1,769 | gone: the commit runs with `user.useConfigOnly=true` and, only when it fails for want of an identity, again with the fallback |
| `diff HEAD` beside `status` | the ledger's `pending` | 735 | one status gives both |
| `cat-file`, `show` of a blob | `forgotten`, `docstore`, `inforce`, `show_at_head`, the index build, convert | about 1,900 | one `cat-file --batch` per `Git`, for its one command or service call |
| `rev-parse`, `remote`, `config` of a folder | `toplevel`, `home.rev_parse`, the host's hooks dir, remotes and LFS state | about 2,100 | asked once per process and folder, kept while `.git/config` is unchanged |
| `whoami /user` | the Windows SID in `owner_only` | 318 | once per process |

- A Docket commit goes from six calls to three: `status -- raw`, `add`, `commit`. A doc put from seven to four, a
  promote from eight to four, a curate add from eight to five, a `vault.yaml` write from six to three, a ledger write
  from eight to four. Every write a user makes saves them, the service's Ledger page clicks included.
- About 12,700 of the suite's 33,136 git processes go: 1,195 worker-seconds here, likely more on CI's Windows runner,
  where a git call costs about 40 ms on four busy vCPUs.
- What Docket commits stays: paths, messages, identity, hooks off. `test_git_calls.py` holds each new list.

### docket processes

Each of the 12 spawns tests the process itself: the console's UTF-8 through a pipe, a non-ASCII argument, two rebuilds
under two hash seeds, the server. The suite already runs the CLI in process (`main([...])`) everywhere else. The trim
moves the setup halves of three pipe tests in process (an init, a doc put, an import) and saves about 10
worker-seconds. It is its own PR, as asked, and a small one.

### The timed tests

| Per PR on all three systems, alone after the rest | Nightly, on the label and on a tag, on all three |
|---|---|
| a redaction's linear time, a child left holding its output, a write's STATUS.md render, a rerank's budget, the parse route's priority, an hour's call's spots, a worker killed at its timeout, a hostile archive's cap, an update while the worker is busy, a write's wait for its vault | the index's 100,000 chunks, the ledger's 5,000 items, the curate miner, recall on 50 MB of raw, the scan of 5,000 files, the day pages, the service's search, the ledger's import and calendar catch-up at size, a week's hundred events, a report among hundreds of entities |
| 15 s here | 200 s alone here, and their vaults' 400 worker-seconds |

A PR that changes the index, the ledger, search or the scan takes the `full-matrix` label. Under coverage the limits
are off, so in the covered run these were pure cost: about a minute of Linux's file times.

### Fixtures and the kit's commits

- About 40 files spend more than half a second of setup per test, mostly a copy each of a vault the test only reads
  (`test_web_ledger.py`, the Briefs, Settings and a11y pages, `test_status_render.py`, `test_search_rerank.py`,
  devkit's `test_docs.py`): those tests share one module copy, read-only, held by DR-0531's template check. About 600
  worker-seconds.
- The kit's own setup commits (`sh(..., "commit")`) run the repo's hooks, git-lfs's post-commit among them, at 1.36 s
  each under load. They take the hooks-off file Docket's own commits use; a test about hooks makes its commits itself.
  About 570 worker-seconds.

### The floor

- One number, 90%, for docket and devkit together, in `tools/devkit/coverage-floors.json`. `gate full` holds it on
  its one run and `gate coverage` on CI's shares combined, as today; a failure names the ten files with the most lines
  no test ran.
- It doesn't follow the measure up. A change that falls below it adds tests; only the owner moves it.
- The cut stops at 95% of statements here, which costs 10 worker-seconds more than stopping at 90%, so a change has
  five points of room. This PC measures docket at 99.96% where Linux measures 100%: a few lines differ by system.

## Doors and data

None. No one-way door moves: PR C changes how Docket asks git, not what it writes (the commits, their paths, messages
and identity stay), and the rest is tests, the test kit, the gate and CI. Every test that pins a door's format stays,
by the rule. No user data moves.

## Steps

Each PR leaves main green and safe: nothing runs less often before the nightly that catches it exists, and the floor
drops before any test does.

| PR | What | Safe because | Projected after it |
|---|---|---|---|

| 2. Run the OS-sensitive files and a smoke set on Windows and macOS | `test-systems.json` and its check, the `--select system` option and `pytest_ignore_collect` in the shard plugin, `test_smoke.py` and the browser smoke, CI's Windows and macOS jobs on the selection | the nightly from PR 1 runs the rest every night | 42.4 |
| 3. Run the timed tests on big vaults nightly | a `nightly` marker on those files and tests; `gate os` and `gate full` leave it out unless `--all` | the nightly runs them on all three systems | 39.9 |
| 4. Hold one coverage floor for the whole repo | `coverage.py` and `coverage-floors.json`, the gate's message; AGENTS.md, CONTRIBUTING.md, `finish-work` | the suite still measures 99%, far above 90% | 39.9 |
| 5. PR C: make fewer git calls in the core | the seven call sites above; `gitfiles.py` reads the index's stage bits; `test_git_calls.py`'s lists | each call keeps today's answer, a test per call site holds it; the old call stays on every path the new one can't vouch for | 35.1 |
| 6. Run docket in process where the process isn't the subject | three pipe tests' setup halves | the pipe halves stay | 34.9 |
| 7. Share setup-heavy fixtures and commit the kit's setups without hooks | module copies for read-only tests; `sh()`'s commits with the hooks-off file | the template check catches a write into a shared copy | 30.7 |
| 8. Drop the tests other tests cover: the vault, the CLI, the service | the appendix's rows for those areas | each PR lists its tests with the kept test that runs their lines; coverage stays above 90% | about 28 |
| 9. Drop them in the ledger, the index and search, and the pages | the same | the same | about 23 |
| 10. Drop them in media, speech, the models, documents and curate, and merge in the kept files | the same, and the merges | the same | 16.6 |

## Risks

| Risk | Status |
|---|---|
| A platform break in code the matrix calls pure merges and shows the next morning | accepted, narrowed: the smoke set runs every surface on all three per PR, the list is generous, and a red nightly opens an issue the same night |
| A new test file that can differ by system isn't listed as OS-sensitive | resolved: the gate fails a test file `test-systems.json` doesn't name, so each new file is classified in its PR |
| A dropped test proved something no kept test proves | open, reviewed: the rule keeps every door, forget, redaction, never-store, guard and recovery test; each drop PR lists its tests beside the test that runs their lines, and review-code reads the list |
| Coverage erodes below the floor over time | resolved: the floor fails the gate; it only moves on the owner's word |
| A perf regression merges and the nightly finds it | accepted: the small budgets run per PR, and a PR touching the index, the ledger, search or the scan takes the label |
| PR C's index reader misreads an index and Docket commits over a conflict | resolved: it reads versions 2, 3 and 4 and refuses any other version, a split index or an extension it doesn't know, asking git as today; a test per form |
| The identity on the failure path commits as an identity git guessed | resolved: `user.useConfigOnly=true` stops git guessing, so a missing identity fails and takes the fallback as today |
| The projection misses 80%: it scales this PC's per-file savings onto CI's times | open: PR 11 measures; Windows in one share is the fallback, and PR C likely saves more on CI's Windows than here |
| Another agent's tests on this PC skew the numbers | accepted: the before was run clean and repeated; the after is measured on a quiet machine |
| The nightly's red issue is noise when a runner flakes | accepted: the job comments on the one open issue rather than opening a new one each night |
