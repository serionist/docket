# Add the index and full-text search, with the entity file format

## Goal

Any Claude session can find a sentence said or written weeks ago, in well under a second, with keywords alone. Each
hit comes back with a locator `read` and `verify` take, grouped with the recording or thread it belongs to and next
to that conversation's summary. Garbled transcripts in English and the owner's other languages are found because
entities and their aliases, kept as YAML in the vault, are matched into every chunk. This is the "finding anything
already kept" half of phase 0.

- In scope: the entity file format and its loader; the index database at `<vault>/index/docket.sqlite`, built from
  `raw/`, `processed/` and `entities/` and never committed; chunking per kind; FTS5 over a folded column and a stemmed
  column per owner language; alias matching and mentions; the search API the service (#8) wraps as the MCP `search`
  tool; `docket index rebuild | update | status` and `docket search`.
- Out of scope: vectors and the reranker (phase 1; the schema leaves room); the ledger's tables (phase 3); typed
  extracts (amounts, tickets) and the crosswalk; writing entity files and the curate tiers (phase 1); making #6's
  `read` find records through the index (a follow-up once both have merged); the MCP tool itself (#8); the Search page
  (#9); weekday and month names as time words; languages written without spaces between words (Chinese, Japanese,
  Thai), which need an FTS5 trigram column later.

## Design

The entity format goes in `docket/vault/`, next to the other formats; the index is a new package, `docket/index/`.
One new dependency: `snowballstemmer`.

| Module | What it does |
|---|---|
| `vault/entities.py` | `Entity`, `Alias`, the loader of `entities/<type>/<id>.yaml`, and its problems |
| `index/languages.py` | per language: its Snowball stemmer, its extra word forms, whether aliases match on its stems, its time words; English and Hungarian filled in |
| `index/text.py` | the tokenizer, the stemmers with a per-word cache, a word's forms per column, FTS5 string quoting |
| `index/schema.py` | the tables, the columns for the owner's languages, the version checks, the SQLite and FTS5 checks |
| `index/chunks.py` | a chunker per kind: transcripts, messages and thread windows, other records, processed docs |
| `index/matching.py` | alias forms and the judging of stem forms, the fuzzy walk over the vocabularies, mentions |
| `index/build.py` | `rebuild()` and `update()`, the lenient raw reader, the index lock, the file replace |
| `index/timewords.py` | time words to a range in the owner's time zone, from the tables in `languages.py` |
| `index/query.py` | `search()`: reading the query, candidates, fusion, collapse, groups; the Pydantic result models |
| `index/__init__.py` | `rebuild`, `update`, `status`, `search`, `locate`: what the service and the CLI call |

What it takes from #6, each public (no leading underscore):

- `segments()` and `Segment`, for the `segments` table and transcript windows;
- `format_anchor()` and the line-end anchor parser, to write locators and to cut a doc line's anchors out of its text;
- the paragraph counting in `spans.py`, so `#n-m` means what `read` resolves;
- the lenient doc parser and its line kinds (headings, fences), and the slug rule for entity ids;
- the control-character escape the `doc` commands print through, and `doc_put` for the fixture's docs.

### The entity file

The keyword layer, written by the user and later by curate. Users' vaults will hold hundreds of these, so the format
is a one-way door (Doors and data).

```yaml
# entities/customer/northwind.yaml
id: northwind
type: customer
name: {en: Northwind, hu: Northwind}
aliases:
  - {text: Northwind Traders}
  - {text: Nortwin, kind: asr}
  - {text: Norton, kind: asr, needs: [ben-sample, harbour-site]}
related: {site: [harbour-site], person: [ben-sample]}
ids: {email_domain: northwind.example}
status: active
```

| Field | Rule |
|---|---|
| `id` | required; the file name without `.yaml`; #6's slug rule (lowercase letters, digits, inner hyphens, at most 80 characters, no Windows device name); unique across all types |
| `type` | required; the folder's name; one of person, org, customer, project, site, device, product, topic, stream, meeting-series, document, repo, place, term |
| `name` | required; a map from a language code (two or three lowercase letters) to the name in that language; at least one |
| `aliases` | a list of `{text, kind?, needs?}`; `kind` is absent or `asr`; `needs` is a list of entity ids |
| `related` | a map from a type to a list of entity ids |
| `ids` | a map from a key (lowercase letters, digits, `.`, `_`, `-`, so a source's name such as `slack.work` can be one) to a string or a list of strings, kept as written and matched ignoring case |
| `status` | `active` (the default) or `archived`; both are matched |
| `role`, `note` | free text |
| `schema` | absent or `1`; any other value is a problem and the file is skipped, so a later format is never read by these rules |

- Read with YAML's base loader, as #6 reads frontmatter: every value is text, so `no` and `2026` stay names. UTF-8,
  a BOM dropped, CRLF read as LF.
- Lenient: an unknown key, an unknown type, a key given twice (the last is read), or an id in `needs` or `related`
  that no file defines is a problem, and the rest of the file loads. An alias whose `needs` can't be read is left out
  with a problem: without its condition it would match everywhere. A file that isn't YAML, lacks `id`, `type` or
  `name`, has a `schema` other than 1, or whose `id` or `type` disagrees with its path is a problem and is skipped.
  Two files with one id: the first in path order loads.
- Files and folders whose names start with `_` or `.` are not entities (`entities/_proposals-<machine>.jsonl`).
- The `ids` keys Docket matches today: a source's name (the record's `author` on that source), `email` (an author's
  address) and `email_domain` (that address's domain). Other keys are kept for the `entity` tool (#8).

### The database

One SQLite file per machine, `<vault>/index/docket.sqlite`, a cache: `index/` is git-ignored (DR-0019).

| Table | What |
|---|---|
| `meta` | the schema version, the tokenizer, the languages and their columns, the snowballstemmer version |
| `run_files` | each run file read: its path in the vault, its size and its modification time |
| `records`, `record_versions` | each record's latest version, its fields, run file and line; every `(rid, v)` with its file and line |
| `segments` | transcript utterances: rid, ordinal, engine, start and end ms, speaker, person |
| `chunks` | the searchable units: owner (a rid, a thread or a doc), ordinal, kind, group, source, time, start and end ms, doc lines, paragraphs, speakers, author, locator, text, text hash |
| `chunks_fts` | FTS5 over `folded`, `stem_en` and a `stem_<code>` per other owner language; contentless; `unicode61 remove_diacritics 2` |
| `docs`, `doc_files`, `doc_covers`, `doc_anchors` | each doc's frontmatter, title, file hash and successor; its covered rids; each content line's anchors as parsed |
| `entities`, `entity_files`, `aliases`, `alias_terms`, `entity_links`, `external_ids` | the keyword layer: each alias's forms, the vocabulary words it expands to and the stem forms dropped as too short or too common, `related`, `ids` |
| `mentions` | one row per chunk and entity: how (text, asr, needs, speaker, author, tagged) and the alias |
| `problems` | what didn't load, by path, path and line, or rid, in a fixed order |

- `PRAGMA user_version` is the schema's version. An index from another version, built with another snowballstemmer,
  or for other languages than `vault.yaml` names, is refused with "run docket index rebuild".
- Opening checks for SQLite 3.27 or later (`remove_diacritics 2`) and creates an FTS5 table in memory; either
  missing is a `DocketError` that says which.
- Contentless FTS5: the text lives once, in `chunks`. Deleting a chunk passes its columns again, recomputed from its
  text; snippets are cut in Python.
- Paths are vault-relative with forward slashes, so every system writes the same rows.
- Room left for later: `chunk_vec_<model>` keyed by chunk owner, ordinal and text hash, so a vector survives a
  rebuild; the ledger's tables; `extracts`, `crosswalk`, `derived_from`; a trigram column for languages without spaces.

FTS5 is compiled into every Python Docket runs on:

| Python | How we know |
|---|---|
| python.org, Windows | `PCbuild/sqlite3.vcxproj` defines `SQLITE_ENABLE_FTS5`; here, 3.12.10 with SQLite 3.49.1 lists `ENABLE_FTS5` in `pragma compile_options` |
| python.org, macOS | `Mac/BuildScript/build-installer.py` builds SQLite with `-DSQLITE_ENABLE_FTS5` |
| uv's managed Pythons | python-build-standalone's `cpython-unix/build-sqlite.sh` passes `-DSQLITE_ENABLE_FTS5`; its Windows build uses CPython's vcxproj |
| Linux distributions | CPython links the system SQLite; Debian's rules (so Ubuntu's) pass `--enable-fts5`, Fedora's spec enables FTS3 to 5 |
| CI | the opening check and a test that creates the table run on Windows, macOS and Linux |

Tried here on a contentless table with the standard library: `bm25()` with column weights, a column filter on a
phrase, `fts5vocab` with a term range, the `delete` command, `optimize`, and `iterdump()` with the shadow tables.

### Text and languages

Every chunk is indexed once as written and once per language, all precomputed in Python. The languages are
`vault.yaml`'s `owner.languages`, with English always among them.

| Column | What goes in | Example |
|---|---|---|
| `folded` | the text; the tokenizer folds case and accents | `hatarido` finds `határidő` |
| `stem_en` | each word lowercased, then its English Snowball stem | `consulting` finds `consultant` |
| `stem_<code>` | the same with each other owner language's stemmer, in code order (`stem_hu` for Hungarian) | `határidőről` finds `határidő` |

- Every stemmer runs on every chunk, whatever its language: calls mix languages.
- `languages.py` maps ISO 639-1 codes to Snowball's stemmers. `owner.languages` is free text, so it matches a code in
  any case, takes Snowball's own names too (`hungarian` is `hu`), and `nb` and `nn` as Norwegian. A language it can't
  place, or Snowball has no stemmer for, gets no column and is a problem: `index status` shows it, and `docket search`
  prints it after an `update` that rebuilt. Its words are still found through `folded`.
- Words are runs of Unicode letters and digits (`[^\W_]+`) in NFC text, close to how `unicode61` splits them.
- `snowballstemmer` 3.1.1: BSD-3-Clause, pure Python, 36 stemmers for 34 languages. Its `stemmer()` switches to
  PyStemmer when that is installed, which can stem differently, so Docket imports the pure-Python classes
  (`snowballstemmer.hungarian_stemmer.HungarianStemmer`) directly. A typed wrapper keeps pyright strict.
- Stems are cached per word: a year is tens of millions of words but a few hundred thousand distinct ones.

A word's forms in a stemmed column are its stem, the word as written (folded), and whatever that language's hook
adds. The forms are ORed. Hungarian's hook adds the stem of the word with a dative ending (`-nak` or `-nek`, after a
lengthened final vowel), because Snowball cuts a final `t`, `n` or `ra` from a bare word but only the case ending
from an inflected one:

| Word | Its stem | Its dative's stem | As a chunk inflects it |
|---|---|---|---|
| forint | forin | forint | forintot: forint |
| projekt | proj | projekt | projektben: projekt |
| consultant | consultan | consultant | consultantnek: consultant |
| Dóra | dó | dór | Dórának: dór |

`hatarido` typed without accents stems to `hatar`; its form as written meets `határidőről`, which stems to `határidő`.
English has no hook; another language gets one when someone measures that it needs one.

The other direction, an inflected query word and a bare word in a chunk, needs one more form. `robotot` stems to
`robot`, but a bare `robot` holds `rob`. So Hungarian stems a query word's stem again (`robotot`, `robot`, `rob`;
`projektről`, `projekt`, `proj`), and search keeps that form only when the index holds the first stem as a word: a
bare word's stem is no word, and its second cut (`forint`, `forin`, `for`) would meet every English `for`. The form is
judged by the common-form rule like the others.

A compound is one word to FTS5 (`tízmillió`), so `millió` never finds it. Amounts come with phase 1's typed extracts.

### Chunks

| Kind | Chunk | Locator |
|---|---|---|
| a record with segments (#6's `segments()`) | consecutive utterances: grow to 60 s, stop before 90 s or 350 words; the next window starts on the last utterance; an utterance over 350 words is split into pieces that keep its times | `r:<rid>@<start>-<end>` |
| `message` | the message alone; and thread windows, the parent and up to 10 replies, consecutive windows sharing one reply | `r:<rid>`; a window: its first message |
| any other record (mail, event, vendor summary) | the title on top, then the text; above 500 words, split between paragraphs as #6 counts them | `r:<rid>` or `r:<rid>#<n>-<m>` |
| processed doc | a section per heading, with the doc's title; anchors cut from the text and kept on the chunk; above 500 words, split between lines | the doc id, with the section's lines and anchors |

- Words are counted as the tokenizer counts them; phase 0 has no model tokens.
- Speakers go into the text once per turn (`Ben Sample: ...`) as the raw labels; times don't. Authors stay raw ids.
  No entity name enters chunk text, so editing an entity never re-chunks.
- A record with segments isn't chunked from its `text` as well.
- Only a record's latest version is chunked; `record_versions` keeps the others for `read` and `verify`.
- A chunk's time: the record's `ts`, plus the window's start. A doc section's: the earliest record its anchors point
  at, else the earliest in `covers`, else the date its slug starts with.
- A chunk's group: the record's `thread`, else its rid. A doc that covers one record or one thread joins that group;
  any other doc is its own. A recording, its second transcript and Plaud's summary land together once #10 sets the
  transcript's and the vendor summary's `thread` to the recording's rid.
- A doc chunk's source is the source of the records it covers, when they share one.
- Locators are written with #6's `format_anchor()`, so a rid holding `@`, `#`, `%` or `]` reads back.

### Matching

An entity is mentioned in a chunk when one of its names or aliases is in it, the speaker or author is the entity, or
the chunk's doc lists it. Every name, in every language, counts as an alias.

| How | Rule |
|---|---|
| text | the alias's folded words as a phrase in `folded`, or its stem forms as phrases in a stemmed column whose language matches aliases |
| asr | an `asr` alias also matches through vocabulary words within one edit of a word of 5 to 7 letters, two edits of 8 or more |
| needs | an alias with `needs` counts only when one of those entities has a mention of another kind in the same chunk |
| speaker | a segment's speaker equal, folded, to a person's name or plain alias; it also fills `segments.person` |
| author | a record's author matching the entity's `ids` (the source's key, `email`, `email_domain`) |
| tagged | the doc's frontmatter `entities` lists it, on each of the doc's chunks |

- A language's hook says whether aliases match on its stems. Hungarian does, for inflected names (`Katának`,
  `Northwind Tradersnél`). English doesn't, since `Mark` would match every `marking`; nor does any other language
  until someone tunes it.
- An alias's last word gets a query word's forms (`Marco`: its stem `marc`, its dative's stem `marcó`, `marco` as
  written), so an alias is at most three phrases per column; the words before it are stemmed alone.
- Each stem form is judged on its own. A form under three letters is dropped, and so is one found in over ten times
  as many chunks as the alias as written (counting that as at least five), or in over a fifth of all chunks and over
  100, the query's floor. So `Dóra` loses `dó`, which English `do` floods; `Mark` loses `mar`, which `már` floods; `Rob` loses `rob`, which
  every `robot` floods. A dropped form stays in `alias_terms`, so curate (phase 1) can show why.
- The fuzzy walk runs over the sorted vocabulary from `fts5vocab`: the `folded` column's with the alias's words as
  written, and each alias-matching stemmed column's seeded from the alias's dative stem and its form as written (not
  Snowball's cut stem, shorter than the word), at the same distances, so `Nortvinnál` (stem `nortvin`) is found for
  `Nortwin`. A bounded Levenshtein reuses the rows of a shared prefix and
  skips every word under a prefix already too far. Pure Python, tested against a brute-force distance. What it finds
  is kept in `alias_terms`, so curate can stoplist it. A multi-word `asr` alias expands to at most 20 phrases, closest
  first.
- Mentions are found with one FTS5 query per alias, not a pass over every word: seconds for thousands of aliases.

### One query

`search(vault, query, *, people=(), entities=(), sources=(), since=None, until=None, k=20, now=None)`:

1. Read the query. Double-quoted parts are phrases, the rest words; FTS5 syntax never passes through. Time words,
   from the tables of the owner's languages, become a range and leave the text. Names and aliases in the text, found
   the way matching finds them, become the query's entities. `people` and `entities` resolve by id, name or alias;
   one that resolves to nothing is reported, not an error.
2. Expand: each word becomes an OR of its forms across the columns. Each entity in the text becomes an OR of its
   names, its plain and `asr` aliases and their vocabulary words; aliases with `needs` reach the results through
   mentions instead.
3. Filters go inside every candidate query, before its top 200 and before the fewer-than-k checks: the time range,
   explicit `since` and `until` intersected with it, and `sources`.
4. FTS candidates, top 200 by `bm25()` with weight 1.0 for `folded` and 0.6 for each stemmed column: all words and
   entities required; if that finds fewer than k, any of them; if still fewer, prefixes of words of three letters or
   more in `folded`. A form found in more than a fifth of all chunks, and in more than 100, is left out, each form
   judged alone; a word whose every form is left out leaves the query, unless every word would.
5. Entity candidates, top 200: chunks mentioning the query's or the boosts' entities; the most entities first, text,
   speaker, author and tagged mentions before `asr` and `needs`, then by FTS rank, then newest.
6. Fuse by reciprocal rank (60 plus the rank) over the two lists: a boost lifts a chunk and never drops one.
7. Collapse within a group: of two transcripts' hits whose times (the record's plus the window's offset) overlap by
   more than half the shorter, the better stays and the other's locator goes under `also`; a message inside a window
   hit goes the same way. Two recordings in one thread, at other hours, stay apart.
8. Group, the group with the best hit first, its hits in time order with their rank. A group's summary is a current
   (not superseded) minutes, recording note or thread summary covering it, in that order.

A query with no words and no entities, only a time word, returns the newest chunks in the range.

| Result | Holds |
|---|---|
| `SearchResult` | the query as read, the groups, and facets (by source, entity and month, over the candidates) for the Search page |
| `QueryReading` | words, phrases, the entities found and the words that found them, boosts, what resolved to nothing, the range and the words that set it |
| `Group` | key, kind (recording, thread, record, doc), title, source, first and last time, the summary (id, type, rev, title) or none, hits |
| `Hit` | locator, kind, rid or doc id, time, start and end seconds or doc lines, speakers, author, snippet, rank, how it was found (all, any, prefix, entity), the query's entities it mentions, a doc section's anchors, `also` |

- A snippet is about 40 words around the first match, plain text.
- The parameter names follow the design's MCP tools table, so #8 maps them one to one; they become a door when #8
  lands the tool.

Time words come from one small table per language, used for the owner's languages, in the owner's time zone from
`vault.yaml`, weeks starting on Monday. English and Hungarian ship:

| English | Hungarian | Range |
|---|---|---|
| today, yesterday | ma, tegnap | that day, midnight to midnight |
| this week | ezen a héten, a héten, e héten | this Monday to the next |
| last week | múlt héten, múlt hét, előző héten | the Monday before to this Monday |
| this month, last month | ebben a hónapban, múlt hónapban, előző hónapban | calendar months |
| this year, last year | idén, tavaly | calendar years |
| last N days, past N days | az elmúlt N napban, elmúlt N nap | now minus N days to now |
| 2026-10-12, 2026-10 | the same | that day or month |

- Matched on folded words, longest first, so `mult heten` typed without accents works.
- A language without a table has no time words; `since` and `until` still work.
- Several time words give the span covering them. A range is never dropped when it empties the result;
  `QueryReading` names the words that set it.

### Build and update

- `rebuild(vault)` takes the index lock (`index/docket.lock`), builds a new file beside the old one
  (`journal_mode=OFF`, `synchronous=OFF`: a crash leaves only a temp file), runs FTS5 `optimize`, and replaces the old
  file. Under the lock it first deletes every `docket.sqlite.*.tmp` a killed rebuild left.
- Every insert is sorted: records by time and rid, chunks by owner and ordinal, docs, entities, aliases, terms and
  mentions by their keys. No dict or set order reaches the file, so two rebuilds of one vault on one machine give the
  same `iterdump()` in any two processes.
- Before the replace it opens the old index once, so SQLite rolls back a hot journal a crashed update left; an old
  index that won't open is deleted with its journal files. On Windows a replace refused because another process holds
  the index open is retried for up to five seconds, then a `DocketError` names the cause.
- It reads the working tree: `raw/` through `RawLog.run_files()` and a lenient line reader of its own,
  `processed/**/*.md` through #6's lenient parser, and `entities/`. Never `staging/`, never git objects.
- A raw line that isn't JSON or fails the record model is a problem at `raw/<...>.jsonl:<line>`, and the rest is
  indexed. A field this Docket doesn't know (a newer optional field, which DR-0020 allows), at the top or inside an
  attachment, is dropped, reported, and the record indexed.
- `update(vault)` runs under the same lock, in one transaction:
  - a run file not in `run_files` adds its records; a later run's version replaces a record's chunks and rebuilds its
    thread's windows (a parent's too, whose rid is its thread);
  - a doc whose hash changed is chunked again, a removed one dropped;
  - any changed entity file reloads the keyword layer;
  - any change re-judges the stem forms, walks the new words (and drops misspellings no chunk holds any longer), and
    recomputes every mention, so an alias whose kept forms or vocabulary words changed is matched again;
  - a run file gone or changed in size or modification time (history rewritten, even to the same length), no index,
    an index from another version, or `owner.languages` changed: a rebuild.
- After `update` the index holds the same rows as a rebuild, keyed by chunk owner and ordinal rather than row id.
- `search()` only reads, with a busy timeout; the service (#8) calls `update` after its own writes. Readers open the
  file by its path with `PRAGMA query_only`, not a read-only URI: SQLite then rolls back a hot journal a killed update
  left, and a vault on a `\\server\share` path, which has no file URI SQLite opens, works.

### The API and the commands

| Python, `docket.index` | Command |
|---|---|
| `rebuild(vault) -> BuildReport` | `docket index rebuild`: counts, problems, time taken |
| `update(vault) -> BuildReport` | `docket index update`: what changed, or that it rebuilt and why |
| `status(vault) -> IndexStatus` | `docket index status`: built or not, the languages and columns, counts, what is new since, problems; exit 1 when it needs a rebuild |
| `search(vault, query, ...) -> SearchResult` | `docket search <query> [--since] [--until] [--source ...] [--person ...] [--entity ...] [-k N] [--no-update]` |
| `locate(vault, rid) -> RecordLocation \| None` | none: for #6's `read`, once both have merged |

- `docket search` runs `update` first, which builds the index when there is none; `--no-update` skips it. Times print
  in the owner's time zone.
- The `index` group and `search` sit in `cli.py`, apart from #5's `staging` and #6's `doc`. Raw text is printed with
  control characters escaped, through #6's helper.
- Problems don't fail a rebuild: the index is still usable, and the command prints them.

## Doors and data

One new one-way door, the entity file format; the rest are medium or cheap decisions in
`packages/docket/index.yaml`, each `proposed` until the maintainer confirms it:

| Decision | Cost | Holds |
|---|---|---|
| The entity file format (entities, DR-0113) | one-way | the path, the fields and their rules, `schema`, the types, the alias kinds and `needs`, the `ids` shape, the base loader, lenient read |
| A stemmed column per owner language (columns, DR-0114) | medium | supersedes DR-0017: `folded` and a stemmed column per owner language, English always, in code order; the per-language hooks and time-word tables; languages without spaces later; vectors and a reranker where a model is available, as before |
| The index is a per-machine cache (index, DR-0115) | medium | the file, rebuild by replace, versions and languages that refuse, the working tree read leniently, sorted inserts, two rebuilds equal, update equal to a rebuild |
| Chunking and alias matching (matching, DR-0116) | medium | the chunk rules, a word's forms, which stems aliases use, the judging of stem forms, the `asr` distances and vocabularies, `needs`, speakers and authors |
| How search ranks and groups (search, DR-0117) | medium | filters before the cut; AND, OR, prefix; boosts by rank fusion; time words as filters; groups by `thread`; summaries; the result's shape |
| Snowball stemmers in pure Python (snowball, DR-0118) | cheap | snowballstemmer's own classes, never PyStemmer; the version recorded in the index |

- `AGENTS.md`'s one-way doors gain the entity format. The PR title names it, and the maintainer's agreement goes in
  #7 before the merge.
- Users' data: nothing is written into the vault except `index/`, which is git-ignored. `entities/` is only read; in
  existing vaults it holds its `.gitkeep`, so nothing migrates. Raw records and docs are untouched.
- A vault that adds a language: the user adds it to `owner.languages` in `vault.yaml`. The index's recorded
  languages no longer match, so the next `update` (and so the next `docket search`) rebuilds the whole index with
  the new column: minutes for a year. Nothing in the vault changes, and every other machine rebuilds its own index
  once it pulls the edited `vault.yaml`. Removing a language works the same way.
- A request to #10, recorded in the search decision: a transcript or vendor summary sets `thread` to its recording's
  rid.
- The MCP tool's names and parameters are #8's door; this plan names the Python API after the design's table.
