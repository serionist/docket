# Back to the design's trust model

Claude releases, changes settings, confirms decisions and confirms old cuts by running the owner's own commands after
the owner says yes in chat; Docket checks nothing for that yes. Only `docket forget --now` and turning
`redaction.credentials` off keep the console's yes (`console.confirm`, #178). The media host list goes too. One PR,
mostly deletions; the one new piece is an in-place editor for a `vault.yaml` laid out by hand.

## What "your OK in chat" is

- Claude asks in chat, the owner says yes, Claude runs the command. That is all: no flag, token, marker or prompt.
- Claude Code's own permission prompt still shows each acting command, since the skills keep pre-approving reads only.
  An owner who wants no second prompt adds an allow rule of their own.
- The commit says who, through one helper, `console.who()`: a body line `by Claude, with the owner's OK in chat` when
  `CLAUDECODE` is set, `via page` from a page as today, nothing more from the owner's terminal. A label, never a check.

## Editing a `vault.yaml` with its own layout

PyYAML is the only YAML dependency, with no round trip. The smallest way is PyYAML's own node marks:

- `compose()` gives every node its start and end in the text. Each change between the settings before and after is one
  splice: a scalar set; a key added after its mapping's last entry, at its indentation; an item appended after a block
  list's last item, or a flow list's span rewritten; an item's own lines deleted; a source's block added or replaced.
- New text comes from the paste helpers that exist (`key_line`, `item_line`, `source_block`), in the file's own line
  endings. Splices run from the end of the file back, so earlier marks hold.
- The result must parse to exactly the settings asked for. Otherwise nothing is written and the command prints the
  line, as today: the rare case of an anchor, an alias, a flow mapping or a scalar over several lines.
- A file in Docket's own form keeps today's whole rewrite.
- Not chosen: ruamel.yaml, a new dependency with a compiled part whose dump re-indents the file to its own settings.

## Media hosts

- `media_put` with a URL fetches from any https host. Kept: every resolved address global and no IPv6 form of an IPv4
  one, the connection pinned to a checked address, 3 redirects each checked again, no compression, the size cap and
  the timeouts, a URL never logged; the gate's media checks, and media stored only once its record is in raw.
- `media_folders` stays: a path put reads local files, and the list keeps it to the folders the owner chose. It is a
  separate check (`open_path`'s roots), not part of the host code.
- An existing `media_hosts` key reads and is ignored: a before-validator drops it, the dump never writes it. A file in
  Docket's form that lists `media_hosts: []` is then a file of its own layout, and the in-place editor keeps its line.
- With no host list to say a source has media, the run's media step and its media line go to every source that isn't
  a folder source; the step already says to put audio only where the skill says how to get it.
