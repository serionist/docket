# Rebuild the web app in React with shadcn/ui

The pages become one React app with shadcn/ui, built by Vite and committed in the Python package, so the service still
serves it all from 127.0.0.1 and an install needs no Node. Ten PRs, the day pages first; main works after each one.

## Goal

- Done: every page in the React app with a sidebar, the list and a Linear-style panel; the old tasks app's bar kept on
  the day pages (the keys, one selection, saves on change, the unsaved guard, bulk by dry run, undo and redo by batch,
  the 5 s poll that holds, materials and their path checks); sign-in, the Guard and the CSP as strict as now.
- Out: features no page has today or in #203's plan; the Outbox; a command palette; pixel baselines.

## Design

### The stack (DR-0703, decided)

| Part | Pick, pinned exact in `package-lock.json` (each a week old or more on 19 Oct) |
|---|---|
| runtime | Node 24.21.0 exact in `.nvmrc`, `engines.node` `>=24.21.0 <25`, npm 11.19.0 in `packageManager`; `.npmrc`: `save-exact`, `ignore-scripts`, `engine-strict` |
| app | React 19.3.0, TypeScript 6.0.3 (7.0 waits for typescript-eslint), Vite 8.3.4 with `@vitejs/plugin-react` 6.1.2 |
| look | Tailwind CSS 4.3.3 with `@tailwindcss/vite`; shadcn CLI 4.21.4 copying components into `src/components/ui/`; `radix-ui` 1.7.0; `lucide-react` 1.55.0; Atkinson Hyperlegible Next and Mono, `@fontsource-variable` 5.3.0, Latin Extended |
| router | TanStack Router 1.170.42 with its own `parseSearch` and `stringifySearch`: strings, repeated keys repeated, never JSON, encoded as the server's `urlencode` with one `URL_SAFE` (`:@/,` raw, space as `+`, `*!'()` encoded); the canonical string written back by `router.history.replace` |
| data | TanStack Query 5.104.2 in memory: no refetch on focus or reconnect, `staleTime: Infinity`, no retry on a 4xx; the poll is the only refetch |
| API types | `openapi-typescript` 7.13.0 and `openapi-fetch` 0.17.0 over `openapi.json`; `overrides` gives openapi-typescript our TypeScript (`"$typescript"`) |
| keys | our own module, one listener and a registry per page (DR-0711); no form, toast, virtual-list or hotkey library |
| checks | ESLint 10.12.0, typescript-eslint 8.71.1, Prettier 3.9.10; Vitest 5.0.3, Testing Library 16.3.3, jsdom 30.1.2; axe-core 4.14.0 |

### Where it lives and how it ships (DR-0705)

| Path | What |
|---|---|
| `packages/docket/web/` | the source: `src/`, `components.json`, `vite.config.ts`, the lockfile, `.nvmrc`, `build-inputs.txt`, `openapi.json`; `node_modules/` in `.gitignore`; out of the wheel and sdist |
| `packages/docket/src/docket/web/app/` | the build, committed and marked `linguist-generated`: `index.html`, scripts, CSS and fonts under fixed names, `licences.txt`, `routes.json`, `build.json` |

- **The service hosts the front end.** FastAPI serves the build's files under `/static/app/` and its `index.html` for
  every client route, on the same origin and port as `/api` and `/mcp` (127.0.0.1:8741). No other server, no Node at
  runtime. Vite's dev server, for development only, runs on `localhost` (never 127.0.0.1, whose `docket_session` is
  the owner's) and proxies to a throwaway service with Host and Origin set to the target's.
- A user without Node runs `uv tool install git+https://github.com/serionist/docket@<sha>#subdirectory=packages/docket`
  as today: uv_build packs `docket/web/app/` like the templates now, nothing fetched at runtime.
- Checked fresh: the web job builds again and fails on `git diff`. `build.json` hashes the tracked files
  `build-inputs.txt` names, LF-normalised, read by Node and the gate's Python; `openapi.json` is out, the typecheck
  catching drift. Tailwind scans only `src` (`source(none)`, `@source`). A conflict is rebuilt. No `-diff`, so gitleaks
  scans the build; review-code and finish-work skip it with `':!packages/docket/src/docket/web/app'`.
- Licences: bundled React, Radix, shadcn/ui, Tailwind, TanStack, clsx, tailwind-merge, get-nonce (MIT), cva
  (Apache-2.0), lucide (ISC), the fonts (OFL-1.1); build and test only, axe-core (MPL-2.0) never ships. All fit.

### The API (DR-0709)

| Page | Reads | Writes, JSON | Today |
|---|---|---|---|
| shell | `GET /api/web/shell`: counts, vault, machine, index line | none | parts in `/api/status`, `/api/day` |
| Ledger, Queue, Meetings, Today | `GET /api/web/<page>`, its panel, `ledger/changed`, `ledger/text` | `ledger/write`, `ledger/save`, `ledger/open` | `views.read` (LedgerRead), `store.write`; the routes are HTML |
| Search, Recording, Briefs | `GET /api/web/search`, its panel; `recording`, `recording/audio`; `briefs` | `briefs/decision` | `/api/search`, `/api/read`, `/api/verify` lack facets and labels |
| Staging, Curate, Sync, Settings | `GET /api/web/<page>` and panels | Staging's two, Curate's four, Settings' three | HTML only |

Each read answers what its `*_view.py` builder builds today, less markup, with values ready to show from the same
Python helpers (`at`, `clock`, `history`, `marked`'s rule): times as text in the owner's zone, snippets as text and mark
segments, never HTML. Each write calls what its form post calls, on the writer thread, answering JSON for a 303.
`uv run devkit web-schema` writes the routes' OpenAPI to `web/openapi.json`, which the quick gate checks.

### Auth and the guard

| Concern | With the app |
|---|---|
| sign-in | unchanged: `docket open`'s one-time code, `/session` sets the SameSite=Strict, HttpOnly cookie; a stranger gets the document with the command in a meta element, 401, naming no vault or machine (DR-0704) |
| a lapsed session | `/api/web` answers 401; a dialog says run `docket open`, then Retry; typed text stays in the page |
| the Guard | unchanged: Host, Origin and Sec-Fetch-Site on writes, OPTIONS refused, no CORS (DR-0152) |
| CSRF | the Guard's checks, plus `/api/web` takes the cookie only and writes only `application/json`; no token needed |
| CSP | `script-src 'self'`; styles `'self'` plus a per-response nonce, which one `useNonce()` gives Radix's three style elements: the scroll lock, Select and ScrollArea (DR-0706) |
| what replaces DR-0170 | a path is the document or JSON, never chosen by a header; the URL a plain query string, the server's canonical one written back as it comes (DR-0704, decided) |

### The day pages' bar (DR-0710, DR-0711)

| Behaviour | How |
|---|---|
| keys | 1 to 4, 0, e, Delete or Backspace, s, u or Ctrl+Z, x or Space, n, j and k, Enter or o, Esc, ?: one registry runs the command a button runs |
| selection | one; the panel follows j and k; a call moves to the row after |
| saves, guard | on change through `ledger/save`, answered with the row, title, history and version; a refused one stays unsaved, and leaving unsaved text asks (the router's blocker, `beforeunload`) |
| bulk, undo | a dry run; skipped rows named; the old verdict rule, so no write toggles; quick buttons per row, Select all per group; the notice bar's Undo and Redo by batch, which u presses |
| poll | every 5 s on DR-0663's hash (the op files' names, sizes and times, Today's with the cursor files), and once on mount, so a cached page is never stale; a change refetches in place; holds while typing, ticking, a dialog or a hidden tab |
| kept | the `page:<day>T<hh:mm>` source; Enter saving a field, dropping from the why, snoozing from the date; no writing keys on Staging and Curate; later pages keep their keys and ways: Search's v, [, ], c and o, the Recording page's play from a line, the results announcement |
| materials | open and the text viewer through `ledger/open` and `ledger/text`, DR-0664's checks as they are |

### The screenshot loop (DR-0712)

| Rule | What |
|---|---|
| design | each page and shared component is designed with `frontend-design:frontend-design`, invoked by the Skill tool |
| run | `uv run devkit ui <page>`: seeds an invented world (empty, a working week), starts a throwaway service on port 0 with its own config and state, a file token and `PYTHON_KEYRING_BACKEND=keyring.backends.fail.Keyring` (a test holds its environment), never 8741 or the owner's keychain; drives the build in Chrome |
| shots | each state (default, panel open, ticked, after a write, refused, empty) light and dark at 1440x900 and 390x844, clock, zone and motion fixed, to `.local/ui/<page>/r<n>/` |
| machine checks | axe, console and CSP errors, sideways scroll, targets of 24 px (44 coarse): block every round |
| critique | spec first (the page's table, the old app's bar), then hierarchy at a glance, density (20 rows at desktop), both themes, narrow, the words |
| rounds | 4 at most, fewer when a round finds only polish; what is left goes in the PR |

- A Windows build differing from Linux's fails CI's diff: PR 1 builds on both and compares; inputs are LF-normalised.
