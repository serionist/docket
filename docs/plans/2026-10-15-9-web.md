# Add the web app's foundation and the Search page

## Goal

The browser gets the same search Claude uses, on the service's own port: type a question, narrow by source and time,
favour people and entities, and open any hit as its summary next to the raw it came from. The page works offline on
127.0.0.1 under the service's CSP, in light and dark, by keyboard, with nothing loaded from the network. This is the
Search page of phase 0, and the shell every later page fills in.

- In scope: `docket/web/`, a router the service mounts; the shell (layout, navigation with a slot for every page of
  the design, light and dark, fonts served by the service); a small design system (tokens, components as Jinja
  macros); the Search page with facets, results grouped by container, and a panel that puts a hit's summary next to
  its raw (`read` with `around`) and verifies a summary line by line; keys; empty and error states; accessibility
  basics; tests over HTTP and one browser smoke test in CI.
- Out of scope: every other page (Staging, Curate, Sync and Settings in phase 1; Recording and Briefs in 2; Today,
  Queue, Ledger, Meetings and Outbox in 3), which get a navigation slot only; any write from the browser (phase 0
  has none); playing audio (phase 2); search as you type (an open question); the phone page (phase 4).

The code starts after PR #48 (#8, the service) merges: the branch is rebased on it before the first step.

## Design

One new package, `docket/web/`, mounted by `service/app.py`. One new runtime dependency, Jinja2 (with MarkupSafe),
and one new dev dependency, Playwright. htmx, two fonts and about a dozen icons are files vendored in the package.

| Module | What it does |
|---|---|

| `web/pages.py` | the navigation: every page of the design with its path, phase, one-line description and whether it is built; the keys as data |
| `web/templating.py` | the Jinja environment (autoescape, `StrictUndefined`), the filters (a time in the owner's zone, a locator, marks in a snippet), and `page()`: every response with the page CSP and `no-store` |

### Pages and fragments

Every state of the page is a URL that renders whole without JavaScript; htmx swaps parts of it.

- Pages and fragments live at different URLs: `/search` is always a whole page; `/search/results` and
  `/search/panel` are always fragments. No route reads `HX-Request` to choose, so a reload, a bookmark and the back
  button always get a page.
- A fragment's answer carries `HX-Push-Url` with the canonical `/search?...` URL, so the address bar holds the state
  in one form, whatever order the form sent its fields in.
- Routes read the query string themselves into `SearchState`; a bad value is the page's own error state with status
  400, never FastAPI's JSON 422.
- A web route catches its own exceptions: a `DocketError` renders its message as an error state; anything else is
  logged through the service's logging (the type and frames, never the message) and renders the error page with
  status 500. Unknown page paths get an HTML 404; `/api` keeps its JSON.
- `/` redirects to `/search` until Today exists (phase 3).

### Assets, CSP and what the browser keeps

Nothing loads from the network: every asset is a file in the package, served by the service.

| What | How |
|---|---|
| htmx | `vendor/htmx-<version>.min.js`, the newest 4.0.x release at least seven days old, as published; its version, URL, sha256 and licence (0BSD) pinned in `assets.py`; a test hashes the file, and the script tag's `integrity` comes from the same pin |
| fonts | Inter and JetBrains Mono, variable woff2, upright only, as released, each with its OFL-1.1 licence file; `font-display: swap`, the system stacks behind them |
| icons | about a dozen Lucide icons (ISC) as inline SVG, `aria-hidden` beside a text label |
| our own | four CSS files, one JS file, `icon.svg` |
| serving | `/static/<path>` answers only for the allow-list; content types come from a fixed table, never `mimetypes`, which on Windows can read `text/plain` for `.js` from the registry, and `nosniff` then blocks the script; `Cache-Control: no-cache` with a strong ETag, so an upgrade never leaves an old stylesheet in use, for a 304 per file on loopback |

Every page and fragment goes out through `page()` with `Cache-Control: no-store` and this policy; the Guard's floor
stays for everything else:

```
default-src 'none'; script-src 'self'; style-src 'self'; font-src 'self'; img-src 'self'; connect-src 'self';
base-uri 'none'; form-action 'self'; frame-ancestors 'none'
```

- No inline script, no `<style>`, no `style=` attribute, no `on*=` handler, no `javascript:` URL. The htmx features
  that need `new Function()` (filters in `hx-trigger`, `hx-on`, `js:` values) are never used, so the policy has no
  `unsafe-eval`. A test walks every rendered state and fails on any of these.
- htmx's config is a meta tag: `includeIndicatorCSS: false` (our CSS has the indicator), `history: true` (htmx 4
  fetches the page again on back and keeps no snapshot), `mode: "same-origin"`. Our JS sets styles through the CSSOM,
  which the policy allows.
- The user's words stay out of browser storage: pages are `no-store`, htmx keeps no snapshot, and the only state the
  browser keeps is two cookies of one word each, `docket_theme` and `docket_keys`, which the server reads to render
  `<html data-theme data-keys>`, so the first paint is right without a script in the head.
- An htmx request answered 401 (the session ended) reloads the page, which then shows the sign-in page.

### The design system

Hand-written CSS with no build: cascade layers, custom properties, native nesting, `light-dark()` and `:has()`, for
browsers from mid-2024 on, with no prefixes and no polyfills.

| Layer | Holds |
|---|---|
| tokens | colours as `light-dark(<light>, <dark>)` pairs: surfaces, ink, muted, line, accent, focus, mark, ok, warn, error, and one hue per kind (recording, thread, mail, event, doc); the type scale (13 px base, dense like a desktop tool), spacing in 4 px steps, radii, shadows, the two font stacks |
| base | the elements: body, links, headings, code, `kbd`, focus rings, `prefers-reduced-motion` |
| components | button, icon button, field, chip (facet, filter, removable), badge (kind, phase, found-by), locator (mono, with a copy button), card, panel, segment line, line pair (verify), notice, empty and error states, the loading indicator, dialog |
| pages | the Search layout: facets, results, panel |

- `color-scheme: light dark` follows the system; `data-theme="light"` or `"dark"` on `<html>` overrides it, and the
  switch cycles system, light, dark.
- One Jinja macro per component in `macros.html`, its CSS class named after it, so later pages reuse both.
- Times and locators in the mono face with tabular figures, summaries in the sans, raw text with its line breaks.
- Content is data: every value is autoescaped; nothing from a record or a doc goes through `|safe`; marks in a snippet
  are built from escaped pieces; content blocks get `dir="auto"`; URLs in content stay text, never links.

### The Search page: its URL

A search is bookmarkable, and its parameters are the `search` tool's, under the same names, so Claude can hand the
user a link to the hits it cites.

| Parameter | What | Default |
|---|---|---|
| `query` | the text | empty |
| `sources` | narrow to these sources; repeated | none |
| `people`, `entities` | favour these; repeated | none |
| `since`, `until` | a date or a time, read by `parse_when` as the tool reads them | none |
| `k` | how many hits; "Show more" adds 20, up to the tool's 100 | 20 |
| `hit` | the open hit's locator, as `read` takes it | none |
| `lines` | for a hit in a doc, its lines (`4-9`) | none |
| `around` | context either side of the raw, as `read` takes it; 0 to 30 | 1 |
| `verify` | `1`: the panel shows the summary verified, line by line | off |

Example: `/search?query=consultant+cost&people=ben-sample&since=2026-10-01&hit=r:calls:rec-0100@02:30-04:00`.

- One canonical form: the order above, defaults left out, repeated values sorted. `SearchState.url()` writes every
  link the page makes.
- Parameters only gain optional ones whose default keeps today's meaning, as the tool's do; unknown ones are ignored,
  so an old bookmark still opens.
- A query that is one locator (`r:...`, or a doc id with its type) opens that locator in the panel instead of
  searching its words, so a locator pasted from Claude's answer shows its raw.
- With no query and no filter, the page shows its start state and runs no search (the tool would refuse it).

### The Search page: facets

A facet click runs the search Claude would run, because the facets are the tool's own parameters.

| Facet | From | A click |
|---|---|---|
| Source | `facets.sources` | narrows (`sources`) |
| Person | the entities in `facets.entities` whose type is person, named through `labels()` | favours (`people`) |
| Entity | the other entities, grouped by type | favours (`entities`) |
| Time | `facets.months`, and two date fields | narrows to that month (`since` its first day, `until` its last) |

- Person and entity are boosts, as the design's recall section has them: a hard filter would drop a chunk whose
  speaker has no label, and that is often the chunk with the answer. The chip says "favour Ben Sample", never "only".
- Counts are over the candidates search ranked (at most 200), and the facets' heading says so.
- Chosen facets sit as removable chips under the box; each chip is a link to the same state without it.
- A line under the box says how search read the query, from `QueryReading`: the time words and the range they set,
  the names found and the entity each is, the names not found, the words left out as too common.

### The Search page: results

One card per group, in search's order.

- The head: the kind (recording, thread, record, doc) as an icon and a word, the title, the source, the first and
  last time in the owner's zone.
- The summary, when a current doc covers the group: its title, type and rev, as a link that opens it in the panel.
- Each hit: its locator (copyable); the stretch (`02:30-04:00`, `¶ 1-4`, `lines 4-9`); speakers or authors; the
  snippet with the query's words marked; the entities it mentions that the query named; why it was found when not by
  all the words ("some words", "a word's start", "by name"); "and 2 more on the same stretch" for `also`.
- Every hit is a link: its `href` is the whole page with `hit=`, its `hx-get` the panel fragment.

### The Search page: the panel

A hit opens beside the results, its summary on one side and its raw on the other.

| Hit | Summary side | Raw side |
|---|---|---|
| in a record (a recording, a message, a mail) | the doc `summary_for(rid)` names, read whole; the lines that point at this stretch (the `lines` of `read(hit, view="both", around)`) marked and scrolled to; without a summary, "no summary covers this yet", and any legacy note that covers the record | the `spans` of the same `read`: segments with times and speakers, or paragraphs, or messages; the hit's own stretch marked and the context around it plain; "3 versions; this is the latest" when it applies |
| in a doc | the doc, its hit lines marked | `verify(doc, lines)`: each of those lines next to the raw its anchors point at |

- `around` has a minus and a plus, named in the hit's unit (minutes, paragraphs, messages), and lives in the URL.
- Every anchor in the summary is a link that loads that raw span on the raw side: a line's `@12:08` opens the raw at
  12:08.
- Verify (`verify=1`): one row per summary line, the line on the left and its raw spans on the right, a problem in the
  error colour where an anchor doesn't resolve. A legacy note has no anchors; the panel says so and names the
  recording it covers.
- Each raw line's own locator (`r:<rid>@12:08`) copies on click.
- Opening the panel moves focus to its heading; closing it returns focus to the hit.

### Keys

Single keys work while focus isn't in a field, as in a desktop tool; the keys dialog has a switch that turns them off
(WCAG's character key shortcuts), kept in `docket_keys`.

| Key | Does |
|---|---|
| `/` | to the query box |
| `Enter` in the box | search |
| `j`, `k` | next, previous hit (moves focus) |
| `Enter`, `o` | open the focused hit in the panel |
| `v` | verify the open summary, and back |
| `[`, `]` | less, more around |
| `c` | copy the focused hit's or the panel's locator |
| `Esc` | close the panel, or leave the box |
| `?` | the keys dialog |

The keys are data in `pages.py`, so the dialog and the footer list the keys the JS handles.

### Empty and error states

| State | What the page shows |
|---|---|
| start, nothing asked | what a query can hold (names, quoted phrases, time words in the owner's languages, a date, a locator) and the index's counts |
| nothing found | what search read, and a link per filter or boost that drops it |
| a bad parameter | the message (`since is a date or a time, such as 2026-10-14 or 2026-10-14T09:30`), status 400, the box still filled |
| the index being built | "the index is being built", and the results fragment asks again every five seconds (`hx-trigger="load delay:5s"`) |
| no vault, or one the service can't read | the `DocketError`'s message, with the command it names |
| a hit that no longer resolves | the panel's own error; the results stay |
| a session that ended | the sign-in page, naming `docket open` |
| anything else | the error page: that something failed, and where the service log is |

### Accessibility basics

- Landmarks (`header`, `nav`, `main`, `aside` for the facets and the panel), a skip link, one `h1`, headings in order.
- Every field has a label and every icon button an accessible name; icons are `aria-hidden`.
- A polite live region says how many hits and groups came back.
- Colour never alone: a kind has its word, a match its `mark` element, a problem its text.
- Contrast at least 4.5:1 for text and 3:1 for borders, the focus ring and icons, in both themes.
- The focus is always visible; the keys dialog is a native `dialog`; at 200 % zoom every control stays reachable.

### How pages are tested

| Kind | What it covers | Where it runs |
|---|---|---|
| render tests | every route and state through Starlette's TestClient on #7's index fixture vault, the HTML parsed with the standard library's `html.parser` | every system, in `gate full` |
| the HTML check | over every rendered state: no inline script or style, no handler, no eval-only htmx attribute, every asset referenced in the allow-list, the structural accessibility rules above | the same |
| the token check | the contrast pairs computed from `tokens.css`, both themes | the same |
| a browser smoke test | one flow over the real service in Playwright, on the system's Chrome | a Linux CI job with `DOCKET_TEST_BROWSER=chrome` |

The smoke test catches what render tests can't see: a CSP violation, a swap that doesn't happen, a key that does
nothing, a font that doesn't load. It downloads no browser (GitHub's Linux image has Chrome, which Playwright drives
through `channel`), and runs on a desktop with `DOCKET_TEST_BROWSER=msedge` or `chrome`. With the variable set, a
missing browser fails it; without it, it skips and says so.
