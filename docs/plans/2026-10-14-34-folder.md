# Let the vault be a folder of the user's own repo

## Goal

A vault can be a folder of the repo the user already works in (the host repo), the default DR-0102 sets, and a vault
made as a repo of its own can become one with its history. In a host, Docket only makes local commits of the vault's
paths; the user's own git does everything else.

- In scope: finding and opening a folder vault; Docket's private files under the host's git dir; commits limited to
  the vault's paths; `docket sync` in both modes; `docket init` offering both modes with the host checks; `docket
  vault convert` from a repo of its own to a folder of the repo around it.
- Out of scope: forget in folder mode (phase 2, with forget); turning a folder back into a repo of its own;
  re-checking the host's remotes after setup (handed to #8, under Risks); `sources/`, which DR-0108 took out of the
  layout (the issue no longer lists it).

## Design

### Where a vault lives

`vault.yaml` gains `storage`, and Docket checks that the disk agrees before it writes:

| `storage` | The vault | Docket's private files |
|---|---|---|
| `repo`, or no key (every existing vault) | is the top of its own repo | `<vault>/.git/docket/` and `<vault>/.git/docket.lock`, as today |
| `folder` | is a folder strictly inside a host repo, with no `.git` of its own | `<host git dir>/docket/<vault path>/`: `docket.lock`, `machine`, `tmp/`, `convert.json`, `before-folder.git/` |

- A new `home.py` resolves this once, at open: the mode, the repo's top, the vault's path in it (`git rev-parse
  --show-prefix`), the git dir (`--absolute-git-dir`) and every private path. `lock.py`, `machine.py`, `rawlog.py`,
  `staging.py`, `docstore.py` and the sync marker take their paths from it instead of `root / ".git"`.
- `Vault.find` takes the nearest folder upward whose `vault.yaml` has its own `.git` beside it, or says `storage:
  folder`. Another tool's `vault.yaml` in some repo is never taken for a vault.
- `Vault.open` first asks git for the repo around the vault's folder and looks there for a `convert.json` for the
  vault's path. If there is one, a convert stopped part way (between the rename and the folder files the vault looks
  like a repo with no `.git`), and open refuses: `docket vault convert` finishes it, `docket vault convert --abort`
  undoes it.
- Then it refuses, and says what to do, for:
  - `storage: folder` with a `.git` of its own, at the host's top, or inside another vault;
  - `storage: repo` without its own `.git`;
  - a folder vault reached through a linked worktree of the host: it names the main checkout's copy, the one the
    service writes.
- In a repo of its own, git runs with `GIT_CEILING_DIRECTORIES` set to the vault's parent, so a vault whose `.git` went
  missing fails instead of committing into a repo above it.

### Committing in a host

Commits keep #20's shape (`git add`, then `git commit --only`, the paths on stdin), run from the vault's folder. Some
of git's output is relative to the host's top, and some of the host's state is the user's:

| Where | Change |
|---|---|
| `Git.commit`'s staged check | `git diff --cached --name-only -z -- .`, its host-relative names compared with the prefix added: without the prefix nothing ever matches and nothing is committed. Not `--relative`, which crashes git 2.47.0.windows.2 during a stash-pop conflict in the host |
| `changed_against_head` | `-- <under>`, the prefix taken off, so `vault check` names the vault's own paths |
| `DocStore._blob` | `<sha>:./<path>`: git reads `<rev>:<path>` from the repo's top |
| `last_commit` | `-- .`: the vault's last commit, not the host's |
| a failed commit after `add` | in folder mode, `git reset -q -- <paths>` unstages Docket's paths, as `DocStore._write_and_commit` does, so the user's index is as it was |
| run files a missed commit left | the orphan pickup also takes run files staged but not in HEAD, which a crash between `add` and `commit` leaves |
| the host's hooks | off for Docket's commits in folder mode (`-c core.hooksPath=<private>/no-hooks`, an empty folder) |
| the host's `index.lock` | a fresh one is retried for a few seconds (the user's editor may be running git), then the write fails naming it; a stale one is reported with its age; Docket never deletes it |

- `_recover` reads the host's git dir: a host mid-merge, mid-rebase, mid-cherry-pick or revert, or on a detached HEAD
  blocks Docket's writes, and Docket never aborts anything there.
- The unmerged check stays on the vault's own paths: a conflict in the user's files doesn't block Docket, and git's
  partial commit leaves it unresolved (tried on git 2.47).
- Docket commits on whichever branch the host has checked out. `docket vault status` shows the storage, the host and
  the branch, and warns when the host has an `origin/HEAD` and the branch isn't it.
- `vault check` in folder mode also runs the host's ignored check below; when the rule is the `/<vault>/` line the
  convert took out of the host's `.gitignore`, it says to commit that edit. It also reports a doc rev that two commits
  claim, naming both: the user's own merge can bring one from each side (see Doors and data).

### Sync

- Folder mode: `Vault.sync()` makes no git call and says "<vault> is a folder of <host>: your own git (commit, pull,
  push) moves it".
- A repo of its own: as today (DR-0022).
- `docket sync` is the new command for both; a conflict exits 1.

### Attributes and search

- The vault's own `.gitattributes` holds every attribute in both modes. It starts with `* !filter !diff !merge
  !working-tree-encoding`, so a host rule such as `*.jsonl filter=lfs` doesn't reach inside the vault, then sets its
  own: LF, `*.jsonl merge=union`, media in LFS, and the `merge=union` line #10 adds for the hold lists
  (`state/holds/<source>.txt`). Git reads a nested `.gitattributes` for the paths below it, a deeper file wins over
  the host's (tried: the host's `-filter` on the same path loses), and the file moves with the folder.
- Only the host's `.git/info/attributes` beats it. `vault.py` keeps a table of a sample path, an attribute and its
  value for each line, including `raw/` with `filter` unspecified (#10 adds its row); init, convert and `vault check`
  read each with `git check-attr` and report a mismatch.
- A folder vault has its own `.ignore` (`/*`, `!/processed/`): ripgrep, Claude Code and editors see its processed docs
  and nothing else in it (tried with ripgrep), as the parent's three `.ignore` lines do for a nested repo today.
- The host's `.gitattributes` gets nothing. DR-0102's bind puts the media lines there; a new decision refines it to
  the vault's own file, which git applies to the same paths and which moves with the folder, where a host line would go
  stale. DR-0102 itself isn't edited: the maintainer reviews the refinement.

### Host checks

A new `host.py`, run by init and convert:

| Check | Rule |
|---|---|
| remotes | every URL from `git remote get-url --all` and `--push --all`, which expand `insteadOf` and `pushInsteadOf`; an `ssh://` or `git@host:path` URL is probed as `https://host/path` with today's anonymous `ls-remote`, run from a temp folder outside any repo with `GIT_CONFIG_GLOBAL` an empty file and `GIT_CONFIG_NOSYSTEM=1`, so the user's own rewrites and credentials never reach the probe. Public refuses folder mode; can't tell asks the user to confirm it's private (`--remote-is-private` under `--yes`) |
| shared | author and committer emails in HEAD's last 1000 commits, minus the owner's, git's `user.email`, `noreply@github.com` and `[bot]` addresses. Any left: a warning that names them, `repo` becomes the default, and under `--yes` folder mode needs `--allow-shared` |
| ignored | `git check-ignore -v` on a sample path for each vault folder; a host rule that ignores one refuses, naming the rule |
| attributes | `git check-attr` on the table above |
| git-lfs | installed, its filter set, its pre-push hook in the host; after the yes Docket runs `git lfs install --local` in the host when they're missing, and when a hook of the user's is in the way it says to add `git lfs pre-push "$@"` to it. Without git-lfs, media waits, as today |
| state | on a branch, with at least one commit, nothing in progress |

### Setup

`docket init`:

- Inside a repo it asks `folder` or `repo`, default `folder`; outside one it takes `repo` without asking. `--storage
  folder|repo` answers.
- A public host remote refuses folder mode and offers `repo`; a shared-looking host warns and defaults to `repo`.
- Folder mode writes inside the vault's folder only: the folders and their `.gitkeep`, `.gitattributes`, `.gitignore`,
  `.ignore`, and `vault.yaml` with `storage: folder`. The machine name goes in the private folder. One commit, "Start
  the vault", holds exactly those paths. No `git init`, no lines in the host's `.gitignore`, `.ignore` or
  `.gitattributes`, and the host may have uncommitted changes, which stay as they were.
- A failed folder init removes the folder and unstages its paths.
- The summary shows the storage, the host and its branch, each check's result and what git-lfs needs, before anything
  is written.
- Repo mode is today's wizard, writing `storage: repo`.

### Convert

`docket vault convert` turns a repo of its own into a folder of the repo around it, history included. It is built for
the shape `docket init` makes when it nests a vault: a repo with no remote, inside a working repo whose `.gitignore`
has `/<vault>/` and whose `.ignore` has the three lines.

The dry run comes first, every time:

- the host, its branch, and the host checks' results;
- how many vault commits join the host's history, and how many LFS objects are copied;
- the folder commit on top of them, the one merge Docket makes in the host, and the host files it edits and leaves for
  the user to commit (`.gitignore`, `.ignore`);
- where the old `.git` goes, and what only it keeps: other branches, tags, stashes, commit signatures;
- that the user's next push sends all of it to the host's remotes.

`--dry-run` stops there; otherwise it asks, and `--yes` answers. It refuses when:

- the vault has any remote: another machine's clone of it would be overwritten by that machine's next pull of the
  host. The message says to retire the other clones first (bring their commits here, delete them), then remove the
  remote;
- the vault has uncommitted changes (its ignored `staging/` and `index/` aside), has an operation in progress, is
  detached, or its lock is held;
- the host fails a check, tracks anything under the vault's path, or holds it as a submodule.

Each step is written to `convert.json` before it runs, and a second run finishes what a crash stopped:

1. Fetch the vault's branch into the host as `refs/docket/convert/source`, and copy its LFS objects into the host's
   store (`<git dir>/lfs/objects`, or `lfs.storage` when set), listing in `convert.json` the ones that weren't there.
   Nothing the user sees changes.
2. Rewrite that history under the vault's path with one `git fast-import`: each commit's tree becomes the vault's path
   holding the original tree (`M 040000 <tree> <prefix>`), with the author, committer, dates and message kept. `git log
   -- <prefix>/processed/<doc>` then reaches every `Doc:` line, so revisions read as before (DR-0112). The stream ends
   with one ordinary commit, "Make the vault a folder of this repo", that writes the folder files under the prefix:
   `storage: folder` in `vault.yaml`, the `.ignore`, and the `.gitattributes` lines the vault lacks. The host merge
   then adds nothing of its own, so a `pull --rebase` that drops the merge keeps them.
3. Rename `<vault>/.git` to `<private>/before-folder.git`, then check that its HEAD is still the fetched commit; if a
   writer slipped in, rename it back and stop.
4. Write the same folder files in the working tree, byte for byte as the folder commit holds them.
5. Make the host merge the way `git commit` does: take the host's `index.lock` (retried a few seconds), build the
   merge's tree in a temporary index (the host's HEAD tree, the rewritten head's tree under the prefix), make the
   commit with the host's HEAD and the rewritten head as parents, write into the lock the current index plus the
   vault's entries, `git update-ref` from the old HEAD only, and rename the lock over the index. A second run that finds
   the rewritten head already in HEAD (`git merge-base --is-ancestor`) skips to putting the vault's entries in the
   index.
6. Drop `/<vault>/` from the host's `.gitignore` and Docket's three lines from its `.ignore`, in the working tree only,
   left uncommitted for the user; copy the machine name; delete the refs and `convert.json`.

`--abort` undoes a convert stopped before the host merge: it renames the backup back, restores the files the convert
wrote, deletes `refs/docket/convert/*` and the LFS objects it copied, and says what it removed.

Not chosen:

- the folder files in the merge itself: a `pull --rebase` drops the merge and them with it, and the next open refuses
  (the review's probe);
- a bundle of the old history: revisions and `Doc:` lines would end at the convert, against DR-0112, and a bundle
  carries no LFS objects;
- `git subtree`: a contrib script many installs lack, and its history keeps the old paths, so `git log --
  <prefix>/...` stops at the merge;
- `git filter-repo`: another install;
- the user's own `git merge`: it refuses while anything is staged.

## Doors and data

One-way doors this touches, so the PR title names them and the maintainer agrees in the issue (the issue already asks
for the first):

- `vault.yaml` (DR-0021) gains `storage`. No key means `repo`, so `schema_version` stays 1 and every existing vault
  reads as before. A Docket from before this change refuses the key, since unknown keys are refused; before the first
  release that is accepted.
- The layout (DR-0019) is superseded by a decision that restates it and adds where Docket's private and temp files
  live in each mode, and the folder vault's `.ignore`.
- DR-0102's bind on where the media lines go is refined by a new decision: the vault's own `.gitattributes`, not the
  host's. DR-0102 stays as the maintainer wrote it, and he reviews the refinement.
- DR-0024 (decided) binds every staging file to a temp file in `.git/docket/tmp/`. The layout decision restates that
  bind for both modes (`<private>/tmp/`) as a proposed refinement; DR-0024 isn't edited.

DR-0112 holds through a convert: every rev stays the commit that wrote it, under its new path. Its sync bind (sync
stops when this machine and the remote both wrote the same `Doc: <id> rev <n>`) has no folder-mode twin, since Docket
never runs the user's merges: a merge of two branches can bring two commits for one rev. `vault check` reports it,
naming both, and the next put goes on from the highest rev.

Existing vaults: nothing moves on its own. A vault without `storage` is a repo of its own, with its private files where
they are. A nested vault with no remote becomes a folder only through `docket vault convert` and the user's yes, and
its old `.git` stays in the private folder until the user deletes it.

Decisions, recorded at build time with `uv run docs add decisions`, `proposed`, by Claude (autonomy grant):

| Decision | Cost | Holds | Not chosen |
|---|---|---|---|
| `vault.yaml` says where git keeps the vault | one-way | `storage: folder` or `repo`, no key is `repo`; open refuses when the disk disagrees, and first points at a stopped convert; a folder vault is found only by its key; a repo of its own runs git under `GIT_CEILING_DIRECTORIES` | detecting it from the disk alone: a copied vault, or one whose `.git` went missing, would commit into whatever repo holds it |
| The vault's layout and where Docket's own files live (supersedes DR-0019, refines DR-0024's temp-file bind) | one-way | DR-0019's layout and run-file names; private and temp files in `.git/docket/` for a repo of its own, in `<host git dir>/docket/<vault path>/` for a folder; staging's temp files in that `tmp/` in both modes; a folder vault's `.ignore`; DR-0024 not edited | private files in an ignored folder of the vault: a host's `git clean -x` deletes them and editors list them |
| A folder vault's media LFS lines are in its own `.gitattributes`, refining DR-0102's bind | one-way | every attribute the vault needs in the vault's own file, in both modes, after `* !filter !diff !merge !working-tree-encoding`; nothing in the host's `.gitattributes`; `git check-attr` checks what applies; DR-0102 not edited | the host's root file: stale when the folder moves, and a host path Docket would have to commit |
| In a host, Docket's commits skip the host's hooks | medium | `-c core.hooksPath=<private>/no-hooks` on Docket's commits; a failed commit unstages Docket's paths; staged run files count as orphans; a fresh `index.lock` retried a few seconds, never deleted; an operation in progress blocks Docket's writes | running the host's hooks: a formatter would rewrite raw files written once, a commit-msg rule would refuse or rewrite `Doc:` lines |
| Docket commits on whichever branch the host has checked out | medium | no branch is pinned; `vault status` shows the branch and warns when it isn't the host's `origin/HEAD` | committing only on one branch: writes on any other branch would wait, uncommitted, for the user's own `git add -A` |
| In folder mode, two commits for one doc rev are reported, not prevented | cheap | `vault check` names both; the next put goes on from the highest rev; DR-0112's sync stop stays for a repo of its own | a merge driver or hook in the host: Docket doesn't run the user's merges |
| Setup checks the host before folder mode | medium | the host checks table: URLs from `git remote get-url`, SSH probed as https with the user's config shut out, public refused, unknown confirmed; shared warned, `repo` the default, and under `--yes` folder mode needs `--allow-shared`; ignore rules, attributes, git-lfs | trusting SSH remotes as private; warning only under `--yes`; probing with the user's config, which rewrites the URL |
| A vault becomes a folder by rewriting its history under its path, a folder commit on top, and one host merge that adds nothing of its own | medium | the convert's steps, the dry run, the yes, the refusal of a vault with a remote, the backup, the index written under the host's lock, resume and abort | the folder files in the merge; converting a vault with a remote; a bundle, `git subtree`, `git filter-repo`, the user's own merge |
| The convert leaves its `.gitignore` and `.ignore` edits for the user to commit | cheap | the host merge holds the vault's paths only; the dry run, the last message and `vault check` name the two files | putting them in the host merge: Docket would commit paths that aren't the vault's |
| A folder vault isn't opened from a linked worktree of its host | cheap | the refusal names the main checkout's copy | writing the worktree's copy, which puts vault commits on a feature branch; redirecting without saying so |

The maintainer took every recommendation the first draft asked him about (14 Oct); each is a row above.

## Tests

Every test builds its host and vault in a temp folder from invented people and messages, under the isolated git config
`conftest.py` already sets. None reads a real vault or the network: remote visibility is passed in, as the wizard's
tests do now.

`folder_vault`: a host repo with an invented `README.md`, one commit and a local bare `origin`; the vault at
`notes/vault`, two levels down so a path bug can't hide; the user's staged change to `README.md`, an unstaged one to
another file, and a staged hand edit inside the vault.

| Test | Proves |
|---|---|

| a stash-pop conflict outside the vault | Docket commits, the staged check doesn't crash git, and the conflict is still there |
| a commit that fails after `add`, and a crash between `add` and `commit` | nothing of Docket's stays staged after the failure; the staged run file the crash left goes in with the next commit |
| a host `index.lock` held by another process | a fresh one: the write retries, then fails naming it, with nothing staged; a stale one: reported, and still there |
| a run while the host is on a feature branch | the commit lands on that branch; `vault status` warns that it isn't `origin/HEAD` |

| a host `.gitattributes` with `*.jsonl filter=lfs` | `git check-attr` gives `filter` unspecified for the vault's raw files, and a run file is stored as text |
| init in folder mode | only the vault's paths in its commit; nothing written outside the vault folder but the private files; the host's `.gitattributes` byte-identical while `git check-attr` gives `filter: lfs` for `notes/vault/media/x.age`; the user's changes untouched; a failed init leaves no folder and nothing staged; with `rg` on PATH, `rg --files` from the host lists `processed/` and not `raw/` |
| convert | on a nested vault made by today's wizard, with raw runs, a doc at rev 2, a fake LFS object and a waiting staged record: the dry run changes nothing (the host's HEAD, index and working tree, and the vault's `.git`, identical); after the yes, `git log -- notes/vault/processed/<doc>` shows both revs, `read(rev=1)` works, the merge's tree equals its first parent's plus the rewritten head's, the LFS object is in the host's store, the staged record is still there and ignored, `.gitignore` lost `/notes/vault/` and `.ignore` its three lines, both left uncommitted and outside the merge, the user's changes are untouched, `vault.yaml` says `folder`, the machine name is kept; `vault check` names the `.gitignore` edit when it is undone |
| `pull --rebase` after the convert, with a new commit on `origin` | the merge is gone, the folder commit and every `Doc:` commit are there, and the vault opens as a folder |
| convert refusals | a vault with a remote (the message says to retire the other clones), a dirty vault, a public host remote, a host tracking the path, a submodule, a held lock |
| convert after a crash | a failure injected after each step, then a second run: one host merge, the same result; a crash after `update-ref` and before the index: no vault file shows as deleted once the second run is done, and it doesn't rebuild the merge; open in between points at `convert` and `--abort`; `--abort` before the merge restores the vault as it was and removes the refs and the copied LFS objects |

## Risks

| Risk | Status |
|---|---|
| A host's `git clean -x` deletes `staging/`, the only copy of records waiting for the gate | accepted for phase 0: a source's lookback pulls waiting records again, and the README says it; moving staging would change DR-0024's door |
| `git stash -u` in the host takes run files a crash left uncommitted | accepted: run files are committed in the call that writes them, so only a crash's leftovers are exposed |
| A host that turns public later keeps its URL, so no setup check sees it | handed to [#8](https://github.com/serionist/docket/issues/8): the service re-checks every remote and push URL daily and warns |
| Docket's commits follow the checked-out branch, and a branch the user drops takes them with it | decided: `vault status` warns, and the reflog keeps them |
| A user's `pull --rebase` flattens the convert's merge | resolved: the merge adds nothing of its own, so every commit, the folder commit and every `Doc:` line survive |
| Rewritten commits get new ids and lose their signatures | said in the dry run; the backup keeps the originals |
| On Windows, a program holding a file in the vault's `.git` stops the rename | the convert stops before anything the user sees has changed, and asks to close it and run again |
| An older Docket refuses `storage` | accepted before the first release |
