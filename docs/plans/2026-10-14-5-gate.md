# Add the staging gate: staging format, never-store, cuts, redaction

## Goal

A record reaches the raw log only through the gate. Anything on a never-store list or from a private source is gone
without a trace; a mixed source's records wait until classified; what reaches raw is cut and redacted, `native`
included. The service (#8), the connectors (#10) and the import (#11) all write through it.

- In scope: `staging/` and its file format; the gate's Python API (`stage`, `list`, `show`, `classify`,
  `promote`); never-store matching; the source rules; cuts on `text` plus a per-source cutter hook; redaction with
  built-in rules and the user's patterns; `docket staging list | show | classify | promote`.
- Out of scope: time cuts on a recording (the connector's cutter, over the segment contract #6 brings in
  `docket/vault/segments.py`; audio is phase 2); loading connectors through the `docket.connectors` entry point
  (#10); cursors and lookback (the sync issue); removing what is already in raw (`docket forget`, phase 2); the
  Staging page (phase 1); redacting derived text (#6 calls the same `Redactor`); card numbers, IBANs and other shapes
  (the user's patterns until someone asks).

## Design

Five modules under `packages/docket/src/docket/vault/`:

| Module | What it does |
|---|---|
| `redact.py` | `Redactor`, built from `vault.yaml`'s `redaction`: runs the rules over `text`, `title`, attachment names and refs, and every key and value in `native`, recursively; each match becomes `[redacted:<rule>]`; returns the record and a count per rule |
| `neverstore.py` | whether a record matches a never-store list, and which list (never which entry, so nothing can log it) |
| `cuts.py` | `Cut(start, end, unit)` with unit `char` or `ms`; `register_cutter(source, cutter)`, a registry like `records.register_projection`; `cut_text`, the default |
| `staging.py` | the folder and its files: read, write through a temp file and a rename, delete; the hand-decision memory |
| `gate.py` | `Gate(vault)`: the rules in order, and the API |

The gate runs the design's order (its Sync section), each step where it is safest:

| Step | When | What happens |
|---|---|---|
| source | intake, every call | an unknown or disabled source refuses the whole batch; `private` drops |
| never-store | intake, every call | a match is dropped in memory, before anything is written |
| redact | intake | staging, temp files and Claude's classification never see a credential |
| already kept | intake, after redaction | the key and `v` come from the redacted record; a version already in raw or staged, or whose key is in `_decided.jsonl`, is skipped; any other version of a record decided by hand waits as `pending`, whatever its source |
| classify | `classify()` | `work` makes it `ready` (cuts checked by a dry run of cut, then redact), `private` deletes it |
| cut, then redact | promotion | on a copy: the stored cuts on the staged text, then the current rules |
| write | promotion | one `Vault.write_run` per source, which commits |

"Decided by hand" means a key or rid in `_decided.jsonl` (this machine's classifications and cuts), a rid whose
version in raw holds a `[cut]` marker (a cut made on any machine, once fetched), or a rid with another staged version
holding cuts.

"Every call": each gate call first sweeps staging under the vault lock. It re-reads `vault.yaml` (a file that doesn't
load refuses the call, so a typo never leaves the gate on an older list), deletes what a never-store list or a
now-private source matches, deletes every staged key found in `_decided.jsonl` (never promoting it), sends a `ready`
record nobody classified back to `pending` when its source became `mixed` or its rid is decided by hand, and removes
temp files a crash left.

Staging, a one-way door (Doors and data):

```
staging/
  <source>/<key>.json   one staged version; key = the first 32 hex of sha256(rid + "\n" + v)
  _decided.jsonl        hashes of versions decided by hand (classified private, or promoted with cuts); never content
```

| Field | What |
|---|---|
| `schema_version` | 1 |
| `state` | `pending` (waits for a classification) or `ready` (goes to raw at the next promotion) |
| `staged_at` | when it was staged, UTC |
| `classified_by` | `user`, `claude`, or null when the source's rule made it ready |
| `cuts` | applied at promotion |
| `problem` | why the last promotion held it back, or null |
| `record` | the record, redacted at intake |

- A record leaves staging promoted (its file deleted after the commit) or dropped (deleted, only counted).
- `_decided.jsonl` lines are `{"rid": <hash of the rid>, "key": <key>}`, appended and fsynced before the staged file
  is deleted; an append first ends a torn last line with a newline. A never-store or private-source drop writes none.
- It is per machine, like staging. The `[cut]` markers in raw carry cuts to other machines without a new trace; a
  private decision can't travel without one (Risks).
- The gate keeps a set of rids whose raw text holds `[cut]`, read from run files it hasn't seen yet, the way the raw
  log keeps its seen-set.

Never-store matching fails closed: too broad drops a work record, too narrow stores a private one.

| List | Matches |
|---|---|
| people | equal, case-folded, to `author`, any `to`, or any string in `native`; `Name <addr>` on either side matches by its address too |
| containers | equal to `container` or `thread`, with or without the `<source>:` prefix |
| keywords | whole tokens in `title`, `text`, attachment names and every string in `native`: case and accents folded, curly apostrophes and typographic dashes plain, HTML entities decoded, any run of non-letters and non-digits a space (so `check-up` also matches "check up"), and a keyword of two or more words also matched split at a lower-to-upper case change and run together (`dora example` matches `dora-example`, `dora_example`, `DoraExample`, `doraexample`); a one-word keyword never splits a word (`art` never matches inside `start`, `Max` never inside `maxRetries`); `matches_text` holds a plain string (a path, a slug, an id) to the same rule |

Redaction's built-in rules (`redaction.builtin`, on by default):

| Rule | Catches | Leaves |
|---|---|---|
| `password` | the value after a label (password, passwd, pwd, passcode, secret, and the word for password in a few languages) and `:` or `=`; the password in `scheme://user:pass@host` | the label |
| `api-key` | token shapes (`sk-`, `ghp_`, `github_pat_`, `xox?-`, `AKIA`, `AIza`, JWTs, `Bearer <token>`) and the value after an api key, token, client secret, secret access key or access key label | the label |
| `private-key` | a `BEGIN ... PRIVATE KEY` block to its END line, or to the end of the text when the END is missing | |
| `phone` | a `+` and 8 to 15 digits with spaces, dots, dashes or brackets, unless a currency or a percent follows; any number after a phone label (phone, tel, mobile, cell) | amounts (`+12 500 000 Ft`), dates, ids, timestamps |

A label counts in the forms secrets really come in:

| Form | Example |
|---|---|
| quoted | `"password": "x"`, `'client_secret' = 'x'` |
| inside an identifier in any case style | `DB_PASSWORD=x`, `AWS_SECRET_ACCESS_KEY=<40 chars>`, `client-secret: x`, `clientSecret: x`, `apiKey = x`, `refresh_token: x` |
| tags (even long or wrapped over lines), line breaks, emphasis or table marks, `&nbsp;` or entities around the label and before the value | `<b>Password:</b>&nbsp;x`, `<td>Password:</td>` then `<td>x` on the next line, `*Password:* x`, `**API key:** x` |
| a `native` key that is a label | `{"password": "x"}`: the key's string value is redacted whole |

- A user's pattern replaces its whole match, or only its `secret` group when it has one; its marker carries the
  pattern's name made into `[a-z0-9-]`.
- Text inside a marker is never matched again, so redacting twice changes nothing.
- Ids are not redacted (`rid`, `container`, `thread`, `author`, `to`): they are how a record is found, matched and
  deduplicated.

Cuts:

- `char` cuts are offsets in the staged text, the text `show` prints, and are applied before promotion's redaction,
  so a rule added after the classification can't shift them. `cut_text` replaces each stretch with `[cut]` and clears
  `native`, because a copy of the stretch there may be HTML or escaped, which a plain replace misses.
- Every cutter leaves `[cut]` in `text` where it cut: that marker is how another machine knows the record was cut.
- `ms` cuts need the source's cutter. Without one, `classify` refuses them; a record already holding them stays
  `ready` with its `problem`.
- A cutter is a pure function `(RawRecord, list[Cut]) -> RawRecord`; the Plaud connector (#10) registers one over the
  segment contract.

The API, which the CLI and the service (#8) call:

| Call | Returns |
|---|---|
| `Gate(vault).stage(records)` | counts: ready, pending, skipped, dropped per reason (never-store, private), redactions per rule |
| `list(source=None, state=None)` | the staged records, oldest first, and any unreadable file as a problem |
| `show(ref)` | one staged record, and the raw version's text with its `[cut]` markers when one was cut; `ref` is a key prefix of at least 6 characters, or a rid when one version of it waits |
| `classify(ref, "work" or "private", cuts=(), by="user")` | the new state |
| `promote(source=None)` | per source: the run file, written, skipped, held, dropped, redactions per rule, the commit |

- Every gate call runs under the vault lock. filelock is reentrant, so `Vault.write_run` inside `promote` takes it
  again.
- A staging file is written to a temp file in `.git/docket/tmp/`, then `os.replace`d. On Windows a replace or delete
  refused because another process has the file open is retried for up to a second.
- The gate logs counts only, never a dropped record's rid, title or text; its errors name a staged record only by
  key or rid.
- After a crash: raw holds only what `promote` built in memory after cut and redact; a staged file is deleted only
  after its run is committed; a rerun dedupes by `(rid, v)` and calls `Vault.commit()` even when `write_run` wrote
  nothing, so an orphan run is committed (DR-0022) before the staged files it holds are deleted.

`cli.py` gains `docket staging`:

| Command | Does |
|---|---|
| `docket staging list [--source] [--state]` | key, state, source, time, kind, who classified, problem, the title or first words; then the counts |
| `docket staging show <ref>` | the staged record and its cuts |
| `docket staging classify <ref> work\|private [--cut 120-340] [--cut 12:30-14:05] [--by user\|claude]` | plain numbers are characters, `mm:ss` or `hh:mm:ss` are times |
| `docket staging promote [--source]` | what each source wrote, held and dropped |

Alternatives: stage everything and drop later (a crash in between leaves the file); redact only at promotion
(staging, temp files and Claude would hold credentials); a folder per state (a classification becomes a write and a
delete, and a crash leaves two copies); a `redactions` field on the raw record (changes the model DR-0020 fixes).

## Doors and data

It adds one one-way door and leaves the others alone.

- New: staging's format, its layout, the staged file's fields, the two states and `_decided.jsonl`. Staging holds the
  only copy of a waiting record (the connector has moved past it), so a later Docket reads every earlier
  `schema_version` or migrates it. It lands as a `cost: one-way` decision, `AGENTS.md`'s doors line gains it, the PR
  title names it, and the maintainer's agreement goes in #5 before the merge.
- Raw text now carries `[redacted:<rule>]` and `[cut]` markers. A medium decision: later passes over derived text
  (#6) know them.
- Unchanged: `vault.yaml` (no new keys or validators, DR-0021), the raw record and its version (DR-0020), the run
  files (DR-0019); the vault's `.gitignore` already ignores `staging/`.
- Existing vaults: none (the vault's PR #16 isn't merged), so nothing migrates.

Entries to add, each `proposed`:

| Decision | Cost |
|---|---|
| staging's layout, the staged file's fields, its two states, `_decided.jsonl` | one-way |
| the gate's order: drops in memory at intake, redaction at intake, cut then redact at promotion, a new version of a hand-decided record waits (a `[cut]` in raw counts), `vault.yaml` re-read on every call | medium |
| never-store matching: what each list matches, failing closed | medium |
| redaction: what it covers, the built-in rules, markers in place, counts and never the secret | medium |
| cuts: `Cut`, the per-source cutter registry, the default text cutter | medium |

## Steps

1. `redact.py`, with `test_redact.py`: each built-in rule on invented hits and on numbers it must keep (`10 millió
   forint`, `1 500 000 Ft`, a date, a chat timestamp, an order number, a version); each label form (quoted JSON, a
   `DB_PASSWORD=` and an `AWS_SECRET_ACCESS_KEY=` line, kebab, `clientSecret`, `apiKey`, `refresh_token`, HTML with
   `&nbsp;`, a `native` key holding the value);
   a private key block with and without its END; `native` keys and values at depth, two keys redacting alike kept
   apart; a user pattern with and without `secret`; `builtin: false`; twice equals once; no output holds the secret.
2. `neverstore.py`, with `test_neverstore.py`: each list's hits and near misses: `art` misses `start`; a phrase
   across a line break; `Kovacs` hits `Kovács`; a bare container id; an address inside `Name <addr>`; a keyword only
   in a `native` transcript segment.
3. `cuts.py`, with `test_cuts.py`: overlapping cuts merged; out of range refused; `[cut]` in place; `native` cleared;
   `ms` refused without a cutter; a registered cutter used for its source only.
4. `staging.py`, with `test_staging.py`: write, read, replace, delete; a failure inside the replace leaves the old
   file whole and no temp file; the Windows retry; an unreadable file reported and never promoted; a torn last line
   in `_decided.jsonl` ignored on read and ended before the next append, which keeps both lines whole.
5. `gate.py`, with `test_gate.py` on a temp vault:
   - a work record staged `ready`, promoted into one run per source, committed; private dropped; mixed waits; an
     unknown or disabled source refuses the batch with nothing written;
   - classify `work` with cuts, `private`; an unknown or ambiguous ref;
   - a re-pull of a promoted, cut or private-classified version skipped, and of a promoted record whose phone number
     was redacted; a new version of a hand-decided record from a work source waits as `pending`;
   - a second machine: an empty `_decided.jsonl` and a cut version in raw, then a re-pull, gives `pending`, and
     `show` prints the raw version's cuts;
   - two versions of a work-source message staged, one classified with a cut: promote leaves the other `pending` and
     out of raw;
   - the rules changed between classify and promote: the cut still removes the stretch the user chose;
   - `vault.yaml` edited while records wait: a new never-store entry deletes, a source made private drops, a source
     made mixed sends unclassified records back to `pending`; a `vault.yaml` that doesn't load refuses every call and
     writes nothing until it loads;
   - `ms` cuts with no cutter: that record held with its problem, the rest promoted;
   - no trace: after a never-store drop, its rid, author and a marker word appear nowhere in the vault's files
     (`.git/docket/` included), `git log -p --all`, the logs (caplog at DEBUG) or the CLI's output;
   - a crash injected after each promotion step (cut and redact, write, commit, `_decided.jsonl`, delete) leaves raw
     without a pending record or an unredacted secret; after a rerun every work record is in raw exactly once and no
     raw file is untracked;
   - a crash in `classify(private)` between the `_decided.jsonl` line and the delete: the next call deletes the
     staged file and raw never holds it;
   - an AST scan: under `src/`, only `gate.py` calls `write_run`.
6. `cli.py`, with `test_cli.py`: the four commands through Typer's runner; `--cut` parsing for characters and times;
   an unknown ref exits 2; `promote` prints counts and no dropped record.
7. The entries, the glossary, `AGENTS.md`, the package README and index, `CHANGELOG.md` (Docs).
8. `gate full`, then `review-code` until it is clean.

## Risks

| Risk | Status |
|---|---|
| A credential with no label and no known shape reaches raw | accepted: the user's patterns; derived text is redacted again (#6) |
| A phone number with no `+` and no label stays (`06 30 ...`) | accepted: the user adds a pattern; the other way loses amounts |
| A user's pattern backtracks badly and stalls the gate on a long transcript | accepted: it is the user's own; `vault.yaml` checks that it compiles |
| A deleted staging file stays in the disk's free blocks | accepted: staging is never committed; disk encryption is the user's |
| A never-store entry added after a record reached raw doesn't remove it | accepted until `docket forget` (phase 2) |
| One keyword drops a whole recording | accepted: never-store means never; a cut is the narrower tool |
| A connector package calls `write_run` itself | partly: the scan covers this package; a connector gets `stage()` only (#10) |
| A record's text asks Claude to classify it as work | partly: `classify` is a call the content can't make; the plugin treats content as data (#12) |
| Phone numbers used as ids (an SMS source's `author`) reach raw | accepted: no phase 0 source has them |
| Hand decisions are per machine: a record classified private on one machine is re-asked on another (mixed) or stored (work) when that machine re-pulls it | accepted: sharing it means a trace in git; a cut does travel, through the `[cut]` marker in raw, once the other machine fetches |
| gitleaks flags the tests' secret-shaped fixtures | resolved: built at runtime, no allowlist |
| PR #16 changes in review | resolved by a rebase; of its files, this touches only `cli.py` and `vault/__init__.py` |

## Decided

Taken under the autonomy grant; each one's alternative is the option not taken.

| Decided | Not taken |
|---|---|
| never-store and private-source drops in memory at intake | stage everything, drop later: a crash in between leaves the file |
| redact at intake and again at promotion | only at promotion: staging, temp files and Claude would hold credentials |
| one file per staged version, named by a hash, the state inside | a folder per state: two steps per classification; rid-based names: `:` and `/` fail on Windows |
| two states; private and promoted records leave staging | a `dropped` state: a trace |
| `_decided.jsonl` of hashes, never pruned (a few lines a day) | no memory: each lookback re-asks every recording, and a cut work record comes back uncut and goes straight to raw |
| a new version of a hand-decided record waits as `pending` | follow the source's rule: an edited message the user cut or dropped reaches raw whole |
| an unknown or disabled source refuses the batch | drop it quietly: a typo loses a source; treat it as work: stores what nobody vetted |
| `vault.yaml` re-read on every call; one that doesn't load refuses the call | re-read on a changed modification time: misses fast edits; keep the last good config: a typo leaves the gate on an older list |
| a `[cut]` in a rid's raw version counts as decided by hand | `_decided.jsonl` alone: a second machine would store a cut record whole |
| cut, then redact, at promotion | redact, then cut: a rule added since the classification shifts the cut's offsets |
| keywords also match `native` strings and attachment names | text and title only: a recording's transcript lives in `native` |
| keywords as whole words, case- and accent-folded | substrings: `art` drops every `start` |
| containers match with or without the `<source>:` prefix | prefixed only: a bare id the user wrote would store what they listed |
| ids are never redacted | redact them: breaks matching and deduplication |
| markers in place; counts returned, never stored apart | a `redactions` field on the raw record: changes the model DR-0020 fixes |
| `phone` needs a `+` or a label | any long digit run: redacts amounts, tickets and timestamps, the numbers Docket exists to keep |
| a user pattern's marker name is its name made into `[a-z0-9-]` | a validator on the name: changes `vault.yaml`'s schema |
| a text cut becomes `[cut]` and clears `native` | cut silently: joins two sentences nobody said together; replace in `native`: misses HTML or escaped copies |
| cuts stored with the record, applied at promotion, checked at classify | cut at classify: no way to correct a cut before it is final |
| who classified is kept in staging only | a raw record field (DR-0020) |
| a record that can't be promoted is held; the rest goes on | fail the whole promotion: one missing cutter blocks every source |
| an AST scan that only `gate.py` calls `write_run` | a wrapper type only the gate makes: stronger, but changes the vault API under review in #16 |
| `staging list` prints the counts; `vault status` unchanged | a staging line in `vault status`: a second place for one number |
| one ref per `classify` | a batch: the service can loop |
